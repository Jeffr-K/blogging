뉴비 분들이 러스트를 공부하다 보면 가장 많이 헷갈려 하시는 오타 중 하나가 바로 MPSC입니다. 결론부터 말씀드리면, mpcs가 아니라 mpsc이며, 러스트 표준 라이브러리(std::sync::mpsc)에 포함되어 있습니다.

이게 무엇인지, 그리고 왜 중요한지 아주 쉽게 설명해 드릴게요.

1. MPSC의 정체
MPSC는 Multi-Producer, Single-Consumer의 약자입니다.

Multi-Producer (여러 생산자): 데이터를 보내는 쪽은 여러 명일 수 있습니다.

Single-Consumer (한 명의 소비자): 데이터를 받는 쪽은 딱 한 명이어야 합니다.

한마디로 **"여러 갈래의 길(Thread)에서 보내온 소식들이 하나의 우체통(Receiver)으로 모이는 구조"**를 말합니다. 러스트에서는 이를 **채널(Channel)**이라고 부릅니다.

2. 왜 쓰는 걸까? (도대체 왜?)
러스트의 철학 중 하나는 **"메모리를 공유해서 스레드 간에 소통하지 말고, 메시지를 보내서 소통하라"**는 것입니다.

데이터를 직접 공유하면 Mutex 같은 복잡한 잠금 장치가 필요하고 사고(Deadlock)가 날 위험이 큽니다.

대신 채널(MPSC)을 쓰면 데이터를 던져주고 잊어버리면 되기 때문에 훨씬 안전하고 깔끔합니다.

3. 어떻게 생겼나? (코드 맛보기)
표준 라이브러리에 있기 때문에 별도의 설치 없이 바로 쓸 수 있습니다.

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    // tx: 데이터를 보내는 송신구 (Transmitter)
    // rx: 데이터를 받는 수신구 (Receiver)
    let (tx, rx) = mpsc::channel();

    let tx1 = tx.clone(); // 송신기는 여러 개가 될 수 있어서 clone 가능!

    thread::spawn(move || {
        tx1.send("1번 스레드에서 보냄").unwrap();
    });

    thread::spawn(move || {
        tx.send("2번 스레드에서 보냄").unwrap();
    });

    // 수신기는 하나이므로 여기서 모아서 받음
    for received in rx {
        println!("받은 메시지: {}", received);
    }
}
```

4. MPSC와 우리가 배운 것들의 연결고리
여기서 오늘 배운 개념들이 다시 등장합니다!

Send: 채널을 통해 데이터를 보내려면, 그 데이터는 당연히 Send 트레이트를 구현하고 있어야 합니다. (배달 가능해야 하니까요!)

'static: 스레드로 데이터를 보낼 때, 그 데이터가 금방 사라질 참조자라면 컴파일러가 mpsc 사용을 막아버립니다. (소유권이 있는 'static 데이터여야 안전합니다.)

5. 실무에서의 MPSC
러스트 표준의 mpsc는 아주 기본적인 기능만 제공합니다. 그래서 실제 비동기 서버(Axum 등)를 만들 때는 표준 std::sync::mpsc 대신, 더 빠르고 강력한 **tokio::sync::mpsc**나 crossbeam-channel 같은 외부 라이브러리를 더 많이 쓰기도 합니다. (구조는 똑같습니다!)

💡 요약

- MPSC는 우체통 시스템이다.

- 표준 라이브러리(std) 맞다.

- 멀티스레드 환경에서 데이터를 안전하게 주고받을 때 쓴다.

이제 러스트 표준 라이브러리의 핵심 도구들을 거의 다 훑어보셨네요! mpsc까지 알게 되셨으니, 나중에 Aspect나 Transactional 로직에서 "백그라운드로 로그를 던지거나" 하는 기능을 구현할 때 아주 유용하게 쓰일 거예요.
