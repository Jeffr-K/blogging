## 왜 Jest인가? 델라이트풀(Delightful) 테스팅의 정수

테스팅은 흔히 '귀찮고 힘든 일'로 여겨졌습니다. 복잡한 설정, 느린 실행 속도, 그리고 조잡한 Mocking 도구들 때문이었죠. 페이스북은 이 문제를 해결하기 위해 **'인간 중심의 테스팅 프레임워크'**인 **Jest**를 세상에 내놓았습니다. Jest가 추구하는 가장 큰 가치는 바로 **'델라이트풀(Delightful)'**한 경험입니다.

---

### 1. Zero Configuration의 마법

과거의 테스팅 도구들은 테스트 러너, 단언 라이브러리(Assert), 모킹 라이브러리를 제각각 설치하고 연동해야 했습니다. Jest는 이 모든 것을 하나로 묶었습니다.

- **올인원 패키지**: `expect`, `mock`, `coverage`가 별도 설정 없이 즉시 작동합니다.
- **스마트한 기본값**: 대부분의 JavaScript 프로젝트에서 설정 파일 없이도 테스트 파일을 찾아내고 실행합니다.

### 2. 고속 환경: "필요한 것만 빠르게"

Jest는 단순히 모든 테스트를 돌리는 것이 아니라, 똑똑하게 실행합니다.

- **병렬 실행**: 멀티코어를 활용하여 여러 테스트 파일을 동시에 실행합니다.
- **Watch Mode**: 수정된 파일과 연관된 테스트만 골라서 즉시 재실행합니다. 이 '즉각적인 피드백'이 개발자의 리듬을 깨지 않게 도와줍니다.
- **Fail First**: 지난번에 실패했던 테스트를 가장 먼저 실행하여, 버그 수정 여부를 빠르게 확인할 수 있게 합니다.

### 3. 신뢰의 도구: Snapshot 테스팅과 스냅샷 모킹

비교하기 힘든 거대한 데이터 구조나 UI 구성을 텍스트 파일로 저장하고 비교하는 **Snapshot 테스팅**은 Jest가 대중화시킨 가장 혁신적인 기능 중 하나입니다. 이는 테스트 지루함을 제거하고 "어? 예전이랑 달라졌네"라는 사실을 아주 싸고 빠르게 알려줍니다.
