## 텍스트 이상의 의미: AST(Abstract Syntax Tree)

스키마틱스가 단순히 파일을 새로 만드는 것뿐만 아니라, **기존의 `app.module.ts` 파일을 읽어서 `imports` 배열에 새로 만든 모듈을 자동으로 주입**하는 원리는 무엇일까?

정규표현식(Regex)을 사용하여 특정 문자열 뒤에 코드를 붙이는 원시적인 방식이 아니다. 그 이면에는 소스 코드를 객체 지향적인 트리 구조로 분석하는 **AST(추상 구문 트리)** 조작 기술이 있다. 이번 아티클에서는 스키마틱스가 어떻게 TypeScript 코드를 정밀하게 파괴하지 않고 수정(Transformation)하는지 딥다이브해 본다.

---

## 1. AST란 무엇인가?

소스 코드는 컴퓨터에게는 그저 긴 문자열일 뿐이다. 하지만 컴파일러는 이 문자열을 의미 있는 단위인 **'토큰(Token)'**으로 쪼개고, 이를 **'나무(Tree)'** 구조로 재구성한다.

- **Node**: 함수 선언, 변수 할당, 배열의 요소 하나하나가 이 트리의 노드가 된다.
- **TypeScript AST**: `ts.createSourceFile()`과 같은 API를 통해, 우리는 `app.module.ts`의 전체 구조를 자바스크립트 객체처럼 탐색할 수 있는 상태가 된다.

---

## 2. 딥다이브: 주입의 경로 찾기 (Path-finding)

스키마틱스가 모듈을 등록할 때 하는 일은 다음과 같다.

1. **File Read**: 기존 소스 코드를 읽어와 AST 소스 파일 객체로 변환한다.
2. **Node Traversal**: 모든 노드를 돌면서 `@Module` 데코레이터를 찾는다.
3. **Property Find**: 데코레이터 내부의 객체에서 `imports`라는 속성(Property)을 찾는다.
4. **Insert Position**: `imports` 배열의 마지막 요소 뒤, 혹은 닫는 대괄호(`]`) 직전의 정확한 **문자 위치(Position)**를 계산한다.

---

## 3. 코드 변환과 변경 내역(Change) 적용

위치(Position)를 찾았다면, 이제 코드를 주입할 차례다.

- **`InsertChange`**: 특정 위치에 문자열을 삽입하겠다는 선언적 객체다.
- **내부 동작**: 스키마틱스는 이 변경 내역을 즉시 파일에 쓰지 않고, `Tree.beginUpdate()`를 통해 기록해 둔다. 여러 변경사항(Import 문 추가 + 배열 요소 추가)이 모두 준비되면, 한꺼번에 `Tree.commitUpdate()`를 실행하여 파일을 우아하게 업데이트한다.

---

## 4. 실전 활용: 우리 팀만의 자동 코드 주입기 제작

이 기술을 응용하면, 새로운 서비스를 만들 때마다 자동으로 특정 인터셉터를 주입하거나, 전역 설정 파일을 자동으로 업데이트하는 고도의 자동화 도구를 구축할 수 있다.

- **`ts.createSourceFile`**: TypeScript 컴파일러 API의 정수.
- **`findNode`**: NestJS가 제공하는 AST 유틸리티 함수들을 사용하여 특정 노드를 쉽고 정확하게 포착.

---

## 요약

AST 조작은 **"코드를 이해하는 코드"**를 작성하는 고급 엔지니어링의 정점이다.

- 단순 문자열 치환이 아닌, 논리적 구조 분석을 통한 안전한 코드 주입 보장
- `ts.SourceFile`을 통한 소스 코드의 객체화와 정밀 조작
- 트랜잭션 방식의 변경 내역(`Change`) 적용으로 코드 파손 방지

이 지식을 마스터했다면, 이제 우리는 단순한 개발자를 넘어 **팀의 생산성 자체를 설계하는 아키텍트**로 거듭나게 된 것이다.

다음 아티클에서는 이러한 모든 스키마틱스 지식을 총동원하여, 실전에서 바로 사용할 수 있는 **우리 팀만의 맞춤형 프로젝트 템플릿 개발 가이드**를 제시하며 이번 테마를 마무리한다.
