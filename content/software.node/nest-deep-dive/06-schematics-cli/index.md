# Schematics & CLI (스키마틱스: 자동화와 엔지니어링 효율화)

NestJS는 단순히 코드를 실행하는 런타임뿐만 아니라 코드를 생성하는 코드도 강력하게 제공합니다. 이 섹션은 `nest-cli`가 어떻게 코드를 생성하고, 우리가 이 시스템을 어떻게 확장할 수 있는지 파헤칩니다.

## ✨ 왜(Why) 들여다봐야 하나요?

- 우리 팀만의 코딩 표준과 구조를 따르는 커스텀 스키마틱스(Schematics)를 만들기 위해.
- 반복적인 보일러플레이트 코드를 줄여 팀의 생산성을 극적으로 높이기 위해.
- 코드 생성기가 어떻게 동작하는지 이해하여 NestJS 프로젝트 관리를 시스템화하기 위해.

## 🔍 무엇을(What) 핵심적으로 보나요?

- **@angular-devkit/schematics**: NestJS가 이 강력한 엔진을 어떻게 활용하는지.
- **Rule & Tree**: 가상 파일 시스템 개념을 통해 실제 파일을 어떻게 조작하는지.
- **AST (Abstract Syntax Tree)**: 코드를 단순한 문자열이 아니라 구조화된 트리로 다루어 정확한 코드를 주입하는 기법.
- **CLI Plugin**: `nest-cli`에 기능을 추가하거나 수정하는 플러그인 시스템.

## 🛠 어떻게(How) 탐구하나요?

- `@nestjs/schematics` 패키지의 내부 스키마 템플릿(`.ts.template`)들을 직접 수정해보고 관찰.
- 런타임에 소스 코드를 생성하는 미니 스키마틱스 프로젝트 개발 및 테스트.
- 스키마틱스 내부의 파일 생성 순서와 트랜잭션 처리 원리를 추론.
