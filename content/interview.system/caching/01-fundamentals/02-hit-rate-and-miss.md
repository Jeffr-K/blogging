## 히트율 (Hit Rate)

```
히트율 = 캐시 HIT 횟수 / 전체 요청 횟수 × 100%
미스율 = 1 - 히트율
```

예를 들어 100번 요청 중 95번이 캐시에서 처리되면 히트율은 **95%**입니다.

### 히트율이 왜 중요한가

캐시의 효과는 히트율에 따라 극적으로 달라집니다.

```
DB 응답시간: 10ms
캐시 응답시간: 0.1ms

히트율 50%: 평균 응답 = 0.5 × 0.1 + 0.5 × 10 = 5.05ms
히트율 90%: 평균 응답 = 0.9 × 0.1 + 0.1 × 10 = 1.09ms
히트율 99%: 평균 응답 = 0.99 × 0.1 + 0.01 × 10 = 0.199ms
```

히트율 90%와 99%는 10%p 차이지만, 응답 속도는 **5배** 차이납니다. **히트율이 높아질수록 효과가 지수적으로 커집니다.**

### 서비스별 목표 히트율

```
일반 웹 서비스:       > 90%
읽기 집약 서비스:     > 95%
CDN:                 > 98%
L1 CPU 캐시:         > 99%
```

## 미스(Miss)의 3가지 종류

### 1. Cold Miss (강제 미스, Compulsory Miss)

**캐시가 처음 시작할 때 발생하는 불가피한 미스.**

```
서버 재시작 → 캐시 비어있음 → 모든 요청이 미스
배포 직후 → 새 서버는 캐시가 없음 → 히트율 0%에서 시작
```

해결: **캐시 워밍업(Pre-warming)** — 서비스 오픈 전에 미리 캐시를 채움

### 2. Capacity Miss (용량 미스)

**캐시 용량이 부족해서 필요한 데이터가 이미 밀려난 경우.**

```
캐시 크기: 1,000개
실제 활성 데이터: 5,000개
→ 자주 쓰는 데이터도 밀려남 → 미스 증가
```

해결: **캐시 크기 늘리기** 또는 **더 나은 Eviction 정책** 선택

### 3. Conflict Miss (충돌 미스)

**동일한 캐시 슬롯에 매핑되는 데이터들이 서로 자리를 뺏는 경우.**

Direct-Mapped 캐시에서 발생. Fully Associative(완전 연관) 구조에서는 발생하지 않습니다.

실무에서는 캐시 키 충돌로 나타납니다:
```
잘못된 설계: user:1, product:1이 같은 Redis 슬롯에 매핑
올바른 설계: 네임스페이스 분리로 충돌 방지
```

## 미스 발생 시 비용: Cache Miss Penalty

```
평균 응답 시간 = 히트율 × 캐시 레이턴시
              + 미스율 × (캐시 레이턴시 + DB 레이턴시)
```

미스가 발생하면 캐시 조회 + DB 조회 **두 번** 합니다. 히트보다 더 느린 것이죠.

```
캐시 레이턴시: 1ms
DB 레이턴시: 20ms

HIT: 1ms
MISS: 1ms + 20ms = 21ms  ← 캐시 없을 때(20ms)보다 오히려 1ms 더 느림!
```

히트율이 너무 낮으면, 캐시가 없는 것보다 오히려 더 느릴 수 있습니다. **캐시를 도입하기 전에 히트율 예측을 먼저 해야 합니다.**

## 히트율 올리는 방법

### 1. TTL 조정
너무 짧은 TTL → 데이터가 자주 만료 → 미스 증가

```python
# 변경이 거의 없는 데이터는 TTL을 길게
redis.set("config:feature_flags", value, ex=3600)   # 1시간

# 자주 바뀌는 데이터는 짧게
redis.set("user:cart:123", value, ex=300)            # 5분
```

### 2. 캐시 크기 확보
활성 working set이 캐시에 다 들어가야 합니다.

### 3. 키 설계 개선
같은 데이터를 다른 키로 여러 번 캐싱하는 낭비 제거

### 4. 캐시 워밍업
Cold Miss를 최소화하기 위해 배포 전에 핵심 데이터 미리 채우기

## 핵심 요약

- 히트율이 높아질수록 효과가 지수적으로 커짐 (90% → 99%는 5배 차이)
- 미스 종류: Cold(시작 시), Capacity(용량 부족), Conflict(충돌)
- 히트율이 너무 낮으면 캐시가 오히려 레이턴시를 늘릴 수 있음
- TTL 설계와 캐시 크기가 히트율의 핵심 변수
