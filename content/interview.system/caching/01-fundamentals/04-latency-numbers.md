## 개발자가 외워야 할 레이턴시 수치

Jeff Dean (Google)이 정리한 수치를 기반으로, 현재 기준으로 업데이트한 버전입니다.

```
L1 캐시 참조              ~1 ns
L2 캐시 참조              ~4 ns
L3 캐시 참조              ~10 ns
뮤텍스 잠금/해제           ~25 ns
메인 메모리 참조 (DRAM)    ~100 ns

SSD 랜덤 읽기             ~100 μs  (100,000 ns)
HDD 탐색 시간             ~10 ms   (10,000,000 ns)

Redis 명령어 (로컬)        ~0.1 ms  (네트워크 없음)
Redis 명령어 (원격)        ~1 ms
DB 단순 쿼리               ~1~5 ms
DB 복잡한 쿼리             ~10~100 ms

같은 데이터센터 내 패킷     ~0.5 ms
서울 → 도쿄 왕복 (RTT)    ~30~50 ms
서울 → 미국 서부 왕복      ~180 ms
```

---

## 단위 감각 잡기

이 숫자들을 외우기 전에 단위 감각부터 잡겠습니다.

```
1 ns  = 0.000000001초 (10억분의 1초)
1 μs  = 0.000001초    (100만분의 1초) = 1,000 ns
1 ms  = 0.001초        (1000분의 1초) = 1,000,000 ns

1 ms = μs의 1,000배
1 μs = ns의 1,000배
```

인간이 인식할 수 있는 최소 시간 지연: **~100ms** (100ms 이상 걸리면 "느리다"고 느낌)

## 캐시의 가치를 수치로 계산하기

### 예시: 상품 상세 API

```
DB 쿼리 (JOIN 포함): 30ms
Redis 조회:          1ms

초당 1,000 요청 기준:
  캐시 없음: 1,000 × 30ms = 30,000ms 처리 부하
  캐시 히트율 95%: 50 × 30ms + 950 × 1ms = 1,500 + 950 = 2,450ms
  → DB 부하 약 20분의 1로 감소
```

### 예시: 로컬 캐시 vs Redis

```
로컬 캐시 (Caffeine): ~1μs = 0.001ms
Redis (같은 IDC):     ~1ms

차이: 1,000배

초당 100,000 요청 × 1ms 절약 = 100초 절약/초 → DB 여유 확보
```

## 레이턴시로 보는 캐시 계층 선택

```
요청 유형                    적합한 캐시        예상 레이턴시
───────────────────────────────────────────────────────────
동일 JVM 내 데이터           로컬 메모리 캐시    ~1μs
여러 서버 공유 데이터         Redis              ~1ms
전 세계 정적 자산             CDN                ~10~50ms
대용량 파일                  CDN + S3           ~50~200ms
```

## "빠르다"는 게 얼마나 빠른 건지

빛의 속도로 계산해보면:

```
빛이 1ns 동안 이동하는 거리: ~30cm

즉, L1 캐시 참조 1ns 동안 빛은 30cm밖에 못 움직입니다.
서울 → 부산 거리(400km)를 빛이 이동하는 시간: ~1.3ms

Redis 원격 조회 ~1ms = 빛이 서울 → 부산만큼 이동하는 시간
```

같은 데이터센터 안에서 패킷이 ~0.5ms 걸리는 이유가 물리 법칙의 한계입니다.

---

## 실무에서 쓰는 방식

면접이나 설계 미팅에서 빠르게 계산할 때:

```
캐시 (Redis):  1ms
DB:            10ms  (단순) ~ 100ms (복잡)
네트워크:       0.5ms (같은 IDC)

"Redis 캐싱하면 DB 부하 10배 줄어들고 레이턴시 10ms → 1ms"
→ 이 정도 수준으로 빠르게 추정
```

정확한 수치보다 **"몇 배 차이나는가"** 의 오더(Order of Magnitude)를 아는 게 중요합니다.

---

## 핵심 요약

- L1 캐시 ~1ns, DRAM ~100ns, Redis ~1ms, DB ~10ms → 각각 100배씩 차이
- 히트율 95%에서 Redis 캐싱은 DB 부하를 약 20배 줄임
- 로컬 캐시(~1μs)는 Redis(~1ms)보다 1,000배 빠름
- "몇 배 차이인가" 오더를 외워두면 설계 논의에서 빠르게 판단 가능
