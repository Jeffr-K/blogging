## 예외 제어 흐름 (Exceptional Control Flow, ECF)

일반적인 프로그램은 순차적으로 실행되지만, **예외 제어 흐름**은 특별한 이벤트에 반응하여 제어를 운영체제로 넘기는 메커니즘입니다.

---

## 1. 예외 (Exception)의 개념

```
예외 = 어떤 이벤트에 반응하여
      현재 프로세스의 상태를 저장하고
      OS의 예외 핸들러로 제어를 넘기는 것

이벤트 종류:
  하드웨어: 타이머, I/O 완료, 잘못된 메모리 접근
  소프트웨어: 시스템 콜, 나누기 0, 페이지 폴트

예외 벡터 테이블:
  예외 번호 → 핸들러 함수 주소 (OS가 부팅 시 설정)
```

---

## 2. 4가지 예외 유형

### 2.1 인터럽트 (Interrupt)

**비동기적**, 외부 하드웨어 장치에서 발생합니다.

```
발생 원인:
  - 타이머 인터럽트: OS의 시분할 스케줄링
  - I/O 완료: 디스크 읽기 완료, 네트워크 패킷 도착
  - 키보드/마우스 입력

동작:
현재 명령어 완료 후 → 인터럽트 핸들러 실행 → 원래 프로그램 복귀

특징:
  ✓ 비동기: 프로그램과 무관하게 발생
  ✓ 항상 다음 명령어로 복귀 (투명하게 처리)
  ✓ 마스킹 가능: cli/sti 명령어로 일시적 비활성화

예시:
  타이머 인터럽트 → 프로세스 전환 (컨텍스트 스위칭)
  DMA 완료 → I/O 작업 완료 처리
```

### 2.2 트랩 (Trap)

**의도적인 예외**, 시스템 콜(System Call)이 대표적입니다.

```
발생 원인:
  - syscall 명령어 실행 (시스템 콜)
  - 디버거의 브레이크포인트 (int3 명령어)

동작:
syscall 실행 → 커널 모드로 전환 → 시스템 콜 처리 → 복귀

특징:
  ✓ 동기적: 명령어 실행의 결과
  ✓ 의도적: 프로그래머가 요청
  ✓ 다음 명령어로 복귀

예시 (x86-64):
  syscall  → 시스템 콜 번호에 따라 처리
  int 0x80 → 구 Linux 시스템 콜 방식 (32비트)
  int3     → 소프트웨어 브레이크포인트 (gdb)
```

### 2.3 폴트 (Fault)

**수정 가능한 오류 조건**, 처리 후 재시도할 수 있습니다.

```
발생 원인:
  - 페이지 폴트: 가상 메모리 페이지가 DRAM에 없음
  - 보호 폴트: 읽기 전용 메모리 쓰기 시도
  - 정수 나누기 0

동작:
오류 발생 → 폴트 핸들러 실행 → 수정 후 재실행 (또는 종료)

특징:
  ✓ 동기적
  ✓ 수정 가능 시 재시도, 불가 시 프로세스 종료
  ★ 같은 명령어를 다시 실행! (트랩과의 차이)

예시:
  페이지 폴트:
    1. 해당 페이지 접근
    2. 폴트 핸들러 실행
    3. 디스크에서 페이지 로드
    4. 같은 메모리 접근 명령어를 다시 실행 → 이번엔 성공!
```

### 2.4 어보트 (Abort)

**복구 불가능한 심각한 오류**입니다.

```
발생 원인:
  - 하드웨어 오류 (패리티 오류, 기계 오류)
  - 이중 폴트 (Double Fault)
  - 스택 오버플로우

동작:
오류 발생 → 어보트 핸들러 → 프로세스 종료 (또는 시스템 리셋)

특징:
  ✓ 복귀 없음
  ✓ 프로세스 강제 종료
```

## 3. 예외 유형 비교

```
유형        | 원인           | 동기성  | 복귀 위치          | 의도
──────────────────────────────────────────────────────────────
인터럽트    | 외부 I/O       | 비동기  | 다음 명령어        | 비의도적
트랩        | syscall, int3  | 동기    | 다음 명령어        | 의도적
폴트        | 페이지 폴트 등 | 동기    | 같은 명령어 재실행  | 비의도적
어보트      | 하드웨어 오류   | 동기   | 복귀 없음          | 비의도적
```

---

## 4. Linux 예외 번호 (x86-64)

```
0:  #DE - Divide Error (나누기 0) → 폴트
1:  #DB - Debug → 폴트/트랩
3:  #BP - Breakpoint (int3) → 트랩
4:  #OF - Overflow → 트랩
5:  #BR - Bound Range → 폴트
6:  #UD - Invalid Opcode → 폴트
8:  #DF - Double Fault → 어보트
13: #GP - General Protection → 폴트
14: #PF - Page Fault → 폴트 (가장 흔함!)
32~255: 외부 인터럽트 (I/O 장치)

Linux 시스템 콜: 인터럽트 0x80 (구) 또는 syscall 명령어 (신)
```

---

## 5. 예외 처리 과정

```
1. 이벤트 발생
2. 현재 CPU 상태 저장 (레지스터, PC, EFLAGS → 커널 스택)
3. 커널 모드로 전환 (특권 레벨 변경)
4. 예외 벡터 테이블에서 핸들러 주소 조회
5. 핸들러 실행
6. (인터럽트/트랩) 저장된 상태 복원 + 복귀
   (폴트) 문제 수정 → 같은 명령어 재실행
   (어보트) 프로세스 종료
```

---

## 핵심 요약

- **인터럽트**: 외부 하드웨어 비동기 이벤트. 타이머, I/O. 다음 명령어로 복귀.
- **트랩**: 의도적 예외. syscall, 브레이크포인트. 다음 명령어로 복귀.
- **폴트**: 수정 가능 오류. 페이지 폴트가 대표적. **같은 명령어** 재실행.
- **어보트**: 복구 불가 오류. 프로세스 강제 종료.
- **페이지 폴트**: 가장 중요한 폴트. 가상 메모리 시스템의 핵심 메커니즘.
