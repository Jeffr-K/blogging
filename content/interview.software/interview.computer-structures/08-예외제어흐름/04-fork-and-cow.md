## fork와 Copy-on-Write

`fork()`는 부모 프로세스의 완전한 복사본을 생성하지만, **실제로 메모리를 즉시 복사하지 않습니다**. 이를 **Copy-on-Write(CoW)**라고 합니다.

---

## 1. fork 없이는 어떻게 될까?

```
순진한 fork 구현:
1. 자식 프로세스를 위한 새 주소 공간 생성
2. 부모의 모든 메모리 페이지를 복사
   - 예: 부모가 1GB 메모리 사용 → 1GB 복사!
3. 복사 완료 후 자식 실행

문제:
  - 1GB 복사: 수백 ms 소요
  - 대부분의 fork는 즉시 execve로 다른 프로그램을 실행
  - → 복사한 메모리를 쓰지도 않고 버림! 엄청난 낭비
```

---

## 2. Copy-on-Write 메커니즘

```
CoW fork 구현:
1. 자식 프로세스의 페이지 테이블 생성
2. 부모의 모든 페이지 → "읽기 전용"으로 표시
   (부모와 자식이 같은 물리 페이지를 공유)
3. 즉시 완료! (복사 없음)

페이지 쓰기 시:
  - 보호 폴트(Protection Fault) 발생
  - OS가 해당 페이지를 복사 (이때만 실제 복사)
  - 쓰기 프로세스에게 새 복사본 제공
  - 원본 페이지의 보호를 해제 (남은 공유자가 1개뿐이라면)
```

---

## 3. CoW 동작 시뮬레이션

```
fork() 직후:
부모 페이지 테이블:              자식 페이지 테이블:
[Page A] → 물리 프레임 0 (RO)   [Page A] → 물리 프레임 0 (RO)
[Page B] → 물리 프레임 1 (RO)   [Page B] → 물리 프레임 1 (RO)
[Page C] → 물리 프레임 2 (RO)   [Page C] → 물리 프레임 2 (RO)

자식이 Page A에 쓰기 시도:
→ 보호 폴트 발생!
→ OS: 물리 프레임 0을 프레임 3으로 복사
→ 자식 페이지 테이블 업데이트:

부모 페이지 테이블:              자식 페이지 테이블:
[Page A] → 물리 프레임 0 (RW)   [Page A] → 물리 프레임 3 (RW) ← 새 복사본
[Page B] → 물리 프레임 1 (RO)   [Page B] → 물리 프레임 1 (RO)
[Page C] → 물리 프레임 2 (RO)   [Page C] → 물리 프레임 2 (RO)
```

## 4. fork + execve의 최적화

```c
// 쉘의 명령어 실행
pid_t pid = fork();
if (pid == 0) {
    execve("/bin/ls", argv, envp);  // 즉시 execve 호출
}

// execve 시:
// - 이전 주소 공간을 버리고 새 프로그램 로드
// - CoW로 복사된 페이지는 아예 사용 안 함 → 폴트 발생하지 않음!
// - 결과: fork는 페이지 테이블 복사만, 실제 메모리 복사 없음
```

`vfork()`: 더 극단적인 최적화

```c
// vfork: 부모의 주소 공간을 공유 (CoW도 없음)
// 자식이 execve 또는 _exit를 호출할 때까지 부모는 중단됨
// 위험: 자식이 공유 스택을 수정하면 부모에게 영향!
// 현대 fork+CoW는 충분히 빠르므로 vfork는 거의 사용 안 함

pid_t pid = vfork();
if (pid == 0) {
    execve("/bin/ls", argv, envp);  // 즉시 execve 해야 함!
    _exit(1);  // execve 실패 시 _exit (exit이 아닌 _exit!)
}
```

## 5. 참조 카운팅

```
CoW를 구현하기 위해 각 물리 페이지에 참조 카운터 유지:

물리 프레임 0: refcount = 2 (부모 + 자식이 공유)
물리 프레임 1: refcount = 2
물리 프레임 2: refcount = 2

자식이 프레임 0에 쓰기:
→ 새 프레임 3으로 복사
→ 프레임 0: refcount = 1 (부모만 사용)
→ 프레임 3: refcount = 1 (자식만 사용)
→ 프레임 0의 보호 해제 (RO → RW)

프레임 0: refcount = 0이 되면 메모리 반환
```

## 6. CoW의 다른 활용

### 6.1 Redis BGSAVE

```
Redis는 fork로 자식 프로세스를 만들어 스냅샷 저장:
1. fork() → 자식이 메모리 상태 스냅샷
2. 부모는 계속 요청 처리 (메모리 변경 시 CoW로 복사)
3. 자식은 변경 안 된 메모리를 디스크에 저장
→ 부모의 서비스를 중단하지 않고 스냅샷 가능!
```

### 6.2 파일 시스템 스냅샷

```
ZFS, Btrfs의 스냅샷도 CoW 원리:
→ 스냅샷 시 데이터 복사 없음
→ 원본 수정 시에만 스냅샷 전용 복사본 생성
→ 빠른 스냅샷, 공간 효율적
```

---

## 핵심 요약

- **CoW**: fork 시 메모리 즉시 복사 안 함. 부모/자식이 페이지를 읽기 전용으로 공유.
- **쓰기 시 복사**: 어느 쪽이든 페이지를 수정할 때만 보호 폴트 → OS가 그 페이지만 복사.
- **fork+execve 최적화**: exec가 주소 공간을 새로 교체하므로 CoW 복사 발생 안 함.
- **참조 카운팅**: 물리 프레임마다 참조 수 추적. 0이 되면 메모리 해제.
- **활용**: Redis BGSAVE, ZFS/Btrfs 스냅샷도 CoW 원리 사용.
