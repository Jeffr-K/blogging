## 클라이언트-서버 모델

현대 네트워크 애플리케이션의 기본 구조입니다.

---

## 1. 기본 구조

```
클라이언트 (Client):
  서비스를 요청하는 주체
  먼저 연결을 시작 (능동적)
  예: 웹 브라우저, curl, ssh 클라이언트

서버 (Server):
  서비스를 제공하는 주체
  연결을 기다림 (수동적)
  예: 웹 서버(Nginx), DB 서버, SSH 서버

동작:
  클라이언트 ──── 요청(Request) ───→ 서버
  클라이언트 ←─── 응답(Response) ─── 서버
```

---

## 2. 서버의 역할

```
반복 서버 (Iterative Server):
  한 번에 하나의 클라이언트만 처리
  이전 요청 완료 후 다음 클라이언트 수락
  간단하지만 동시 처리 불가

  while (1) {
      accept()    // 클라이언트 연결 수락
      handle()    // 처리
      close()
  }

동시 서버 (Concurrent Server):
  여러 클라이언트 동시 처리
  방법 1: 프로세스 기반 (fork)
  방법 2: 스레드 기반 (pthread)
  방법 3: 이벤트 기반 (epoll + 이벤트 루프)
```

---

## 3. 포트 (Port)

```
IP 주소: 어떤 컴퓨터인가 (호스트 식별)
포트:    그 컴퓨터의 어떤 서비스인가 (프로세스 식별)

잘 알려진 포트 (Well-Known Ports, 0~1023):
  22   = SSH
  25   = SMTP (이메일)
  53   = DNS
  80   = HTTP
  443  = HTTPS
  3306 = MySQL
  5432 = PostgreSQL
  6379 = Redis
  
  루트 권한 필요 (0~1023 바인딩)

임시 포트 (Ephemeral Ports, 1024~65535):
  클라이언트가 연결 시 OS가 임시로 할당
  예: 브라우저 → 임시 포트 54321에서 서버 80으로 연결

소켓 주소쌍 (Socket Pair):
  (클라이언트 IP:포트, 서버 IP:포트)
  TCP 연결을 고유하게 식별
```

---

## 4. 트랜잭션 모델

```
HTTP/1.0 (비연결):
  클라이언트 연결 → 요청 → 응답 → 연결 종료
  매 요청마다 TCP 연결 수립/해제

HTTP/1.1 (지속 연결, Keep-Alive):
  여러 요청을 하나의 연결에서 처리
  파이프라이닝: 응답 기다리지 않고 요청 연속 전송

HTTP/2:
  다중화(Multiplexing): 하나의 TCP 연결로 병렬 요청
  헤더 압축, 서버 푸시

HTTP/3:
  QUIC 프로토콜 (UDP 기반) 사용
  연결 수립 지연 감소 (0-RTT)
```

---

## 5. P2P vs 클라이언트-서버

```
클라이언트-서버:
  서버가 중앙 집중화
  서버 장애 → 전체 서비스 중단
  서버 스케일링 필요
  예: 웹 서비스, DB

P2P (Peer-to-Peer):
  모든 노드가 클라이언트이자 서버
  분산 구조, 단일 실패점 없음
  복잡한 분산 알고리즘 필요
  예: BitTorrent, 블록체인

하이브리드:
  인덱스 서버 + P2P 파일 공유
  예: 초기 Napster (인덱스는 중앙, 전송은 P2P)
```

---

## 핵심 요약

- **클라이언트**: 연결 시작, 요청 전송. **서버**: 대기, 요청 처리.
- **포트**: 같은 호스트의 여러 서비스 구분. 잘 알려진 포트 0~1023.
- **소켓 주소쌍**: (클라이언트 IP:포트, 서버 IP:포트)로 연결 식별.
- **반복 서버**: 단순하지만 동시성 없음. **동시 서버**: fork/thread/epoll.
