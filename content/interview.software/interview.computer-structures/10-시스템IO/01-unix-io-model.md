## 유닉스 I/O 모델

유닉스의 핵심 철학: **"Everything is a File"**. 파일, 소켓, 파이프, 디바이스 — 모두 파일 디스크립터로 접근합니다.

---

## 1. 파일 디스크립터 (File Descriptor, FD)

```
파일 디스크립터:
  프로세스가 열린 파일을 참조하는 작은 정수(0, 1, 2, ...)
  프로세스마다 독립적인 FD 테이블 유지

기본 FD:
  0 = stdin  (표준 입력)
  1 = stdout (표준 출력)
  2 = stderr (표준 오류)

open() 반환값은 가장 작은 미사용 FD:
  fd = open("file.txt", O_RDONLY);
  → 보통 3 반환 (0,1,2 이미 사용 중)
```

---

## 2. 커널 내부 데이터 구조

```
세 가지 테이블의 관계:

프로세스 A FD 테이블       열린 파일 테이블        아이노드 테이블
┌───┬────────────┐        ┌──────────────────┐   ┌───────────────┐
│ 0 │ → stdout  │        │ 파일 오프셋        │   │ 파일 크기     │
│ 1 │ → file1   │──────→ │ 접근 플래그       │──→│ 수정 시간     │
│ 2 │ → stderr  │        │ 참조 카운트: 1    │   │ 데이터 블록   │
│ 3 │ → file1   │──╮     └──────────────────┘   └───────────────┘
└───┴────────────┘  │     ┌──────────────────┐
                    ╰───→ │ 파일 오프셋 (별도) │──→ 같은 아이노드!
프로세스 B FD 테이블       │ 접근 플래그       │
┌───┬────────────┐        │ 참조 카운트: 1    │
│ 3 │ → file1   │──────→ └──────────────────┘
└───┴────────────┘

관계:
  - 같은 파일을 open() 두 번: 독립적 오프셋 (다른 열린 파일 테이블 항목)
  - dup(): 같은 열린 파일 테이블 공유 → 오프셋 공유
  - fork(): 자식이 부모 FD 테이블 복사 → 열린 파일 테이블 공유
```

## 3. 파일의 종류

```
유닉스에서 "파일"의 의미:

일반 파일 (Regular File):
  텍스트, 바이너리 데이터
  선형 바이트 시퀀스

디렉터리 (Directory):
  파일 이름 → 아이노드 번호 매핑 목록
  read()로 읽을 수 없음 (readdir() 사용)

소켓 (Socket):
  네트워크 연결을 파일로 추상화
  read()/write()로 데이터 송수신

파이프 (Pipe):
  프로세스 간 단방향 통신
  fd[0] = 읽기 끝, fd[1] = 쓰기 끝

블록 디바이스 (Block Device):
  디스크, SSD 등
  /dev/sda, /dev/nvme0n1

문자 디바이스 (Character Device):
  터미널, 마우스, 키보드
  /dev/tty, /dev/null, /dev/random

심볼릭 링크 (Symbolic Link):
  다른 파일 경로를 가리키는 포인터
```

## 4. 통일된 인터페이스의 장점

```
동일한 시스템 콜로 모든 종류 처리:
  read(fd, buf, n)  → 파일, 소켓, 파이프, 터미널 모두
  write(fd, buf, n) → 동일
  close(fd)         → 동일

프로그래밍 편의:
  cat 명령어:
    while (read(0, buf, n) > 0)  // stdin에서 읽기
        write(1, buf, n);         // stdout에 쓰기
  → stdin이 파일이든 파이프든 소켓이든 동일하게 동작!

리다이렉션:
  cat < input.txt > output.txt
  → 셸이 FD 0, 1을 적절히 교체
  cat 코드 변경 없음
```

## 5. 특수 파일들

```
/dev/null: 블랙홀
  읽기: 즉시 EOF
  쓰기: 무시
  사용: ./noisy_program 2>/dev/null (오류 출력 버리기)

/dev/zero: 무한 0 바이트 스트림
  읽기: 0으로 채워진 바이트 무한 공급
  사용: 메모리 초기화, 파일 생성

/dev/random, /dev/urandom: 난수 생성기
  커널 엔트로피 풀에서 랜덤 바이트 생성

/proc/[pid]/: 프로세스 정보
  /proc/self/maps: 현재 프로세스 메모리 매핑
  /proc/self/fd/: 열린 파일 디스크립터 목록

/sys/: 커널 시스템 정보
```

## 핵심 요약

- **Everything is a File**: 파일, 소켓, 파이프, 디바이스 모두 FD로 접근.
- **FD**: 프로세스 내 열린 파일의 정수 인덱스. 기본 0/1/2.
- **3계층**: FD 테이블 → 열린 파일 테이블(오프셋) → 아이노드.
- **fork()**: 자식이 부모 FD 복사 → 열린 파일 테이블 공유 → 오프셋 공유.
- **통일성**: 동일한 read/write API로 모든 파일 종류 처리.
