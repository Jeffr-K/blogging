## 캐시 교체 정책 (Cache Replacement Policy)

캐시가 가득 찼을 때 **어떤 캐시라인을 버릴지** 결정하는 알고리즘입니다.

---

## 1. 교체 정책이 필요한 이유

```
집합 연관(Set-Associative) 캐시에서:
세트에 E개의 라인(Way)이 있고 모두 채워진 경우,
새로운 캐시라인을 로드하려면 기존 라인 하나를 제거해야 함

직접 사상(Direct-Mapped): 교체 대상이 정해져 있음 (교체 정책 불필요)
집합/완전 연관: 여러 후보 중 선택 필요 → 교체 정책 필요
```

---

## 2. LRU (Least Recently Used)

> **가장 오랫동안 사용되지 않은** 캐시라인을 교체.

```
동작 예시 (4-Way 세트):
시간 →  0    1    2    3    4    5    6
접근:    A    B    C    D    A    E    A

t=0: [A][ ][ ][ ]           캐시: {A}
t=1: [A][B][ ][ ]           캐시: {A,B}
t=2: [A][B][C][ ]           캐시: {A,B,C}
t=3: [A][B][C][D]           캐시: {A,B,C,D} (가득참)
t=4:  A 히트 → A를 최근으로   LRU 순서: B,C,D,A
t=5:  E 미스 → LRU(B) 교체   캐시: {E,C,D,A}, LRU 순서: C,D,A,E
t=6:  A 히트 → A를 최근으로   LRU 순서: C,D,E,A
```

**구현**:
```c
// 하드웨어: 각 라인에 접근 카운터(타임스탬프) 저장
// 4-way: 2비트로 LRU 순위 추적 가능
// 8-way 이상: 근사 LRU(Pseudo-LRU) 사용 (정확한 LRU는 비용 높음)

// 소프트웨어 구현 (OS 페이지 교체에서):
// Doubly Linked List + Hash Map
// 접근 시: 해당 노드를 리스트 앞으로 이동 O(1)
// 교체 시: 리스트 뒤 노드 제거 O(1)
```

**특징**:
- 시간 지역성을 잘 활용
- 현대 CPU L1/L2/L3 캐시의 표준
- 순차 스캔(Sequential Scan)에서 성능 저하 (LRU Thrashing)

## 3. LFU (Least Frequently Used)

> **가장 적게 사용된** 캐시라인을 교체.

```
동작 예시 (접근 횟수 추적):
접근 순서: A, B, A, C, A, B, D

접근 후 카운트:
A: 3회
B: 2회
C: 1회 ← LFU 교체 대상
D: 1회

새 E 접근 시: C(또는 D, 1회) 교체
```

**특징**:
```
장점: 자주 쓰는 데이터(핫 데이터)를 보호
단점:
  - 과거에 많이 쓴 데이터가 지금은 안 쓰여도 남음 (캐시 오염)
  - 카운터 오버플로우, 주기적 감쇠 필요
  - 구현 복잡 (O(1) LFU는 복잡한 자료구조 필요)
  - 캐시 하드웨어에서는 거의 미사용
```

## 4. FIFO (First In, First Out)

> **가장 먼저 캐시에 들어온** 라인을 교체.

```
동작 예시 (3-Way 세트):
접근: A, B, C, D, A

t=0: [A]           큐: A
t=1: [A][B]        큐: A,B
t=2: [A][B][C]     큐: A,B,C (가득참)
t=3: D 미스 → A(가장 먼저) 교체  큐: B,C,D
t=4: A 미스 → B 교체             큐: C,D,A
     (방금 쫓아낸 A에 다시 접근해야 해서 비효율!)
```

**특징**:
```
장점: 구현 단순
단점:
  - 시간/공간 지역성을 고려하지 않음
  - Belady's Anomaly: 캐시 크기 늘려도 미스율이 증가할 수 있음!
  - 성능이 LRU보다 일반적으로 나쁨
```

## 5. 기타 교체 정책

### 5.1 CLOCK (Second-Chance) — OS 페이지 교체에 자주 사용

```
FIFO를 개선한 근사 LRU:
각 페이지에 Reference 비트(R) 유지
  R=1: 최근에 접근됨
  R=0: 오랫동안 접근 안 됨

교체 시:
  시계 바늘이 순서대로 순회
  R=1이면: R=0으로 리셋 후 다음으로
  R=0이면: 이 페이지 교체
```

### 5.2 Random Replacement

```
무작위로 교체할 라인 선택
장점: 구현 초간단, 특정 패턴에서의 최악 케이스 없음
단점: 예측 불가능한 성능
사용: ARM Cortex-A 계열 CPU 일부
```

### 5.3 Optimal (Belady) — 이론적 최적

```
미래에 가장 늦게 사용될 라인을 교체
→ 최소 미스율 보장
→ 미래를 알아야 하므로 실제 구현 불가
→ 교체 정책 성능 비교의 상한선(Upper Bound)으로 사용
```

---

## 6. 정책 비교 실험

```
접근 패턴: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
캐시 크기: 3-Way

FIFO:    12번 중 9번 미스 (75%)
LRU:     12번 중 8번 미스 (67%)
Optimal: 12번 중 6번 미스 (50%)

실제 워크로드(SPEC 벤치마크):
LRU ≈ Optimal (차이 5% 미만)
→ LRU가 실용적으로 최선
```

## 핵심 요약

- **LRU**: 가장 오래 미사용된 라인 교체. 시간 지역성 반영. 현대 CPU 표준.
- **LFU**: 가장 적게 사용된 라인 교체. 핫 데이터 보호. 캐시 오염 문제.
- **FIFO**: 가장 먼저 들어온 라인 교체. 단순하나 Belady's Anomaly 발생.
- **CLOCK**: FIFO + Reference 비트. OS 페이지 교체의 실용적 선택.
- **Optimal**: 미래 기반 최적. 구현 불가, 비교 기준으로만 사용.
- 실제 CPU: 하드웨어 비용 절감을 위해 Pseudo-LRU 사용 (8-way 이상).
