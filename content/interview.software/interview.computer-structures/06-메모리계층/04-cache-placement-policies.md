## 캐시 배치 정책 (Cache Placement Policy)

메모리 블록이 캐시의 어느 위치에 저장될 수 있는지를 결정하는 정책입니다. 이 정책은 충돌 미스와 하드웨어 복잡도 사이의 트레이드오프입니다.

---

## 1. 직접 매핑 (Direct Mapped, 1-way)

각 메모리 블록이 **정확히 하나의 캐시 세트**에만 배치될 수 있습니다.

```
캐시 세트 = 메모리 블록 주소 mod 캐시 세트 수

예: 캐시 4세트, 블록 크기 4바이트
메모리 주소 0  → 세트 0
메모리 주소 4  → 세트 1
메모리 주소 8  → 세트 2
메모리 주소 12 → 세트 3
메모리 주소 16 → 세트 0 (다시 시작)
메모리 주소 20 → 세트 1
...
```

### 1.1 직접 매핑 시뮬레이션

```
캐시: 4세트, 직접 매핑, 블록 4B
접근 순서: 0, 8, 0, 8, 0, 8 (스래싱!)

주소 0  → 세트0 → MISS  [세트0: 블록@0]
주소 8  → 세트0 → MISS  [세트0: 블록@8]  (충돌! 0 교체)
주소 0  → 세트0 → MISS  [세트0: 블록@0]  (충돌! 8 교체)
주소 8  → 세트0 → MISS  [세트0: 블록@8]  (충돌! 0 교체)
...

→ 히트율 0%! (Thrashing: 스래싱)
이유: 주소 0과 8이 같은 세트(0)에 충돌
```

### 1.2 장단점

```
장점:
✓ 하드웨어 단순 (세트당 1개 라인만 비교)
✓ 저전력, 저면적
✓ 결정론적 동작 (어떤 라인에 있는지 항상 알 수 있음)

단점:
✗ 충돌 미스(Conflict Miss) 취약
✗ 스래싱 발생 가능
→ 현대 L1에서는 사용 안 함
```

## 2. 집합 연관 (Set Associative, N-way)

각 세트에 N개의 라인이 있어 **N가지 위치 중 하나**에 배치 가능합니다.

```
2-way 집합 연관:
세트0: [라인0A | 라인0B]  ← 2개 라인 중 하나 선택
세트1: [라인1A | 라인1B]
세트2: [라인2A | 라인2B]
세트3: [라인3A | 라인3B]
```

### 2.1 2-way로 스래싱 해결

```
캐시: 4세트, 2-way, 블록 4B
접근 순서: 0, 8, 0, 8, 0, 8

주소 0  → 세트0 → MISS  [세트0: 라인A=@0, 라인B=비어있음]
주소 8  → 세트0 → MISS  [세트0: 라인A=@0, 라인B=@8]  (다른 웨이에 배치!)
주소 0  → 세트0 → HIT!  (라인A에 있음)
주소 8  → 세트0 → HIT!  (라인B에 있음)
주소 0  → 세트0 → HIT!
주소 8  → 세트0 → HIT!

→ 히트율 67%로 향상!
```

### 2.2 현대 CPU 캐시 연관도

```
Intel Core i7 (Skylake):
- L1-D: 32KB, 8-way, 64B 라인, 64세트
- L1-I: 32KB, 8-way
- L2:  256KB, 4-way
- L3:   8MB, 16-way (공유)

AMD Ryzen 5000 (Zen 3):
- L1-D: 32KB, 8-way
- L1-I: 32KB, 8-way
- L2:  512KB, 8-way
- L3:   32MB, 16-way (shared per CCD)
```

## 3. 완전 연관 (Fully Associative)

메모리 블록이 **캐시의 어느 위치에나** 배치 가능합니다.

```
완전 연관 캐시 (4라인):
[라인0 | 라인1 | 라인2 | 라인3]
어떤 메모리 블록이든 4개 중 하나에 배치

장점: 충돌 미스 불가능
단점: 모든 라인의 태그를 병렬 비교해야 함
     → N개 비교기 필요 → N이 크면 하드웨어 비용↑, 속도↓
```

### 3.1 완전 연관의 사용처

```
사용: TLB (Translation Lookaside Buffer)
  - 일반적으로 64~1024 엔트리
  - 완전 연관으로 모든 가상 페이지에서 충돌 없음
  - 엔트리 수가 작아 비교기 수 제한적

사용: 작은 특수 목적 캐시 (BTB 일부, 피해자 캐시)

미사용: L1/L2/L3 캐시 (수천~수백만 라인 → 병렬 비교 불가)
```

## 4. 연관도에 따른 성능 비교

```
충돌 미스 발생률 (실제 측정, SPEC 벤치마크):
연관도:  1-way   2-way   4-way   8-way   완전연관
미스율:  10.3%   6.7%    5.9%    5.5%    5.3%

→ 2-way: 1-way 대비 큰 향상
→ 4-way 이후: 수확 체감 (향상 폭 감소)
→ 8-way ≈ 완전연관 (실용적으로 동등)
```

## 5. 캐시 충돌을 줄이는 프로그래밍 기법

### 5.1 배열 패딩

```c
// 문제: 두 배열이 같은 세트에 충돌
double A[N], B[N];  // 같은 크기 → 같은 세트 인덱스 패턴

// 해결: 한 배열에 패딩 추가
double A[N + 8];    // 8 double = 64바이트 오프셋
double B[N];
// 이제 A[i]와 B[i]는 다른 세트에 매핑
```

### 5.2 2의 거듭제곱 배열 크기 주의

```c
// 위험: 정확히 2의 거듭제곱 크기 → 세트 충돌 위험
double matrix[512][512];  // 512 × 512 × 8 = 2MB (캐시 크기에 따라 충돌!)

// 안전: 소수 패딩으로 충돌 분산
double matrix[512][513];  // 513번째 열은 사용 안 함 (패딩)
```

## 핵심 요약

- **직접 매핑 (E=1)**: 각 메모리 블록이 정확히 1개 위치에만 저장 가능. 하드웨어 단순하지만 스래싱 취약.
- **N-way 집합 연관 (E=N)**: N개 위치 중 선택. 충돌 미스 감소. 현대 L1=8-way, L3=16-way.
- **완전 연관 (E=캐시크기/블록크기)**: 어디든 가능. 충돌 없지만 하드웨어 비용↑. TLB에 사용.
- **수확 체감**: E=8 이상은 완전 연관과 성능 차이 미미. 실용적으로 E=8~16 선택.
- **충돌 회피**: 2의 거듭제곱 배열 크기 주의, 배열 패딩으로 세트 충돌 분산.
