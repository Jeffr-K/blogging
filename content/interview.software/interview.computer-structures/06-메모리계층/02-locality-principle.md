## 지역성 원칙 (Principle of Locality)

캐시 메모리가 효과적인 근본 이유는 **지역성 원칙**입니다. 프로그램은 어느 순간에도 주소 공간의 일부분에만 집중적으로 접근하는 경향이 있습니다.

---

## 1. 시간 지역성 (Temporal Locality)

**최근에 참조된 메모리 위치는 가까운 미래에 다시 참조될 가능성이 높다.**

```c
// 시간 지역성의 대표 예: 루프
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += arr[i];
}
// sum: 매 반복마다 접근 → 강한 시간 지역성
// i:   매 반복마다 접근 → 강한 시간 지역성
// arr[i]: 각 원소는 1번만 접근 → 공간 지역성

// 루프 변수, 누산기, 자주 호출되는 함수 코드
// → L1 캐시에서 계속 히트
```

---

## 2. 공간 지역성 (Spatial Locality)

**최근에 참조된 메모리 위치 근처의 메모리 위치도 곧 참조될 가능성이 높다.**

```c
// 공간 지역성의 대표 예: 배열 순차 접근
for (int i = 0; i < n; i++) {
    sum += arr[i];  // arr[0], arr[1], arr[2]... 연속 접근
}
// 캐시라인 64바이트 = int 16개
// arr[0] 로드 시 arr[1]~arr[15]도 함께 캐시에 올라옴
// → 이후 15번의 접근이 캐시 히트!

// 구조체 멤버 접근도 공간 지역성
struct Point { float x, y, z; };
Point p;
p.x += dx;  // p.x 접근
p.y += dy;  // p.y: p.x 근처 → 같은 캐시라인에 있을 가능성 높음
p.z += dz;
```

## 3. 지역성이 좋은 코드 vs 나쁜 코드

### 3.1 벡터 합산

```c
// 좋음: 순차 접근 (공간 지역성)
int sum = 0;
for (int i = 0; i < N; i++) {
    sum += v[i];
}

// 나쁨: 보폭(stride)이 큰 접근
int sum = 0;
for (int i = 0; i < N; i += 32) {  // 32개씩 건너뜀
    sum += v[i];  // 매번 다른 캐시라인 → 캐시 미스!
}
```

### 3.2 2D 배열 접근

```c
// 좋음: 행 우선 접근 (C 언어 행 우선 저장)
for (int i = 0; i < N; i++)
    for (int j = 0; j < M; j++)
        sum += matrix[i][j];  // 연속 메모리 접근

// 나쁨: 열 우선 접근
for (int j = 0; j < M; j++)
    for (int i = 0; i < N; i++)
        sum += matrix[i][j];  // 스트라이드 M×4바이트 → 캐시 미스!
```

### 3.3 함수 호출 패턴

```c
// 좋음: 루프 안에서 인라인 함수 (시간 지역성)
for (int i = 0; i < N; i++) {
    result[i] = compute(data[i]);  // compute가 짧으면 L1-I 히트
}

// 나쁨: 다양한 대형 함수를 산발적으로 호출
// → I-Cache(명령어 캐시)에서 계속 미스
```

## 4. 지역성 측정

### 4.1 스트라이드 패턴 분석

```c
// 스트라이드-k 참조 패턴
// k=1: 순차 접근 (최상의 공간 지역성)
// k=2: 하나씩 건너뜀
// k=N: 완전 무작위에 가까움

// 측정 실험:
void stride_test(int stride) {
    for (long i = 0; i < ARRAY_SIZE; i += stride) {
        sum += arr[i];
    }
}

// 결과 (ARRAY_SIZE = 64MB):
// stride=1:  0.5 ns/접근  (순차, 프리패처 작동)
// stride=2:  0.5 ns/접근  (프리패처 여전히 감지)
// stride=8:  0.7 ns/접근  (프리패처 한계)
// stride=16: 3.0 ns/접근  (캐시라인 1개/접근)
// stride=64: 60 ns/접근   (DRAM 접근, 캐시라인 1워드만 사용)
```

### 4.2 작업 집합 크기 (Working Set)

```
작업 집합 < L1 캐시 (32KB): 거의 모든 접근이 L1 히트
작업 집합 < L2 캐시 (256KB): L2 히트 주도
작업 집합 < L3 캐시 (8MB): L3 히트 주도
작업 집합 > L3 캐시: DRAM 접근 (캐시가 의미 없음)
```

## 5. 지역성을 활용한 코드 최적화

### 5.1 루프 융합 (Loop Fusion)

```c
// 분리된 루프: arr를 두 번 순회
for (int i = 0; i < N; i++) b[i] = a[i] * 2;
for (int i = 0; i < N; i++) c[i] = b[i] + 1;
// a, b를 각각 두 번 캐시에서 사용

// 융합: 한 번 순회
for (int i = 0; i < N; i++) {
    b[i] = a[i] * 2;
    c[i] = b[i] + 1;  // b[i]가 레지스터에 있을 때 즉시 사용!
}
// a[i]를 한 번 로드하고 b[i], c[i] 모두 처리 → 캐시 히트
```

### 5.2 루프 교환 (Loop Interchange)

```c
// 나쁨: 행렬 B를 열 방향으로 접근
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        C[i][j] = A[i][j] + B[i][j];  // B[0][j], B[1][j]... 비연속

// 좋음: 루프 순서 교환
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        C[i][j] = A[i][j] + B[i][j];  // 모두 연속 접근
```

### 5.3 데이터 구조 재배치

```c
// 나쁨: 크고 드물게 사용하는 필드가 섞임
struct Object {
    int id;           // 자주 사용
    char name[256];   // 드물게 사용 → 같은 캐시라인 낭비!
    float score;      // 자주 사용
};

// 좋음: 자주 사용하는 필드를 앞에 모음 (Hot/Cold 분리)
struct ObjectHot {
    int id;
    float score;
};

struct ObjectCold {
    char name[256];
};
// id와 score가 같은 캐시라인 → 루프에서 히트율 증가
```

## 핵심 요약

- **시간 지역성**: 최근 접근한 데이터를 곧 다시 접근. 루프 변수, 반복 접근 데이터.
- **공간 지역성**: 접근한 데이터 근처도 곧 접근. 배열 순차 접근, 구조체 멤버.
- **캐시라인 64B**: 한 번에 64바이트 로드 → 순차 접근은 16개 int를 1번 미스로 처리.
- **스트라이드가 클수록 나쁨**: 스트라이드 ≥ 캐시라인 크기이면 모든 접근이 캐시 미스.
- **최적화 기법**: 루프 융합, 루프 교환, 핫/콜드 데이터 분리, 블록화(Tiling).
