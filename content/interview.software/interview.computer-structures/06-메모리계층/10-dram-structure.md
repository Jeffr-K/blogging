## DRAM 구조

DRAM(Dynamic RAM)은 주기억장치(메인 메모리)의 기반 기술입니다. 내부 구조를 이해하면 메모리 접근 패턴 최적화에 도움이 됩니다.

---

## 1. DRAM의 기본 원리

```
DRAM 셀 구조 (1트랜지스터 + 1커패시터):
    ┌─────────┐
    │  Word   │  ← 행 선택 신호 (Row Address)
    │  Line   │
    └────┬────┘
         │ 트랜지스터
    ┌────┴────┐
    │커패시터│  ← 1비트 저장 (충전=1, 방전=0)
    └─────────┘
         │
    Bit Line  ← 열 선택 신호 (Column Address)

장점: SRAM(6트랜지스터)에 비해 면적 1/6
단점: 커패시터 방전 → 주기적 리프레시(64ms마다) 필요
```

## 2. DRAM 내부 구조

```
DRAM 칩 구조:
┌──────────────────────────────────────┐
│                DRAM Chip             │
│  ┌─────────┐  ┌─────────┐           │
│  │ Bank 0  │  │ Bank 1  │  ...      │
│  │         │  │         │           │
│  │ Row 0   │  │ Row 0   │           │
│  │ Row 1   │  │ Row 1   │           │
│  │ ...     │  │ ...     │           │
│  │ Row 16K │  │ Row 16K │           │
│  └─────────┘  └─────────┘           │
│                                      │
│  Row Address → 행 선택 (RAS)         │
│  Col Address → 열 선택 (CAS)         │
└──────────────────────────────────────┘

일반적 파라미터 (DDR4 16GB):
  뱅크 수: 16개 (4개 뱅크 그룹 × 4뱅크)
  행 수: 65,536개 (16비트 행 주소)
  열 수: 1,024개 (10비트 열 주소)
  행 크기: 8KB (한 행 = 1024열 × 64비트)
```

## 3. DRAM 접근 과정

```
메모리 읽기 과정:

1. RAS (Row Address Strobe): 행 선택
   → 해당 행 전체(8KB)를 행 버퍼(Row Buffer)에 로드
   → 지연 시간: tRCD ≈ 14ns

2. CAS (Column Address Strobe): 열 선택
   → 행 버퍼에서 원하는 열 읽기
   → 지연 시간: CL (CAS Latency) ≈ 14ns

3. Precharge: 행 버퍼 초기화 (다음 행 접근 준비)
   → 지연 시간: tRP ≈ 14ns

전체 지연: tRCD + CL + tRP ≈ 42ns (+ 버스 전송)

DDR4 타이밍 표기: 14-14-14-34 (CL-tRCD-tRP-tRAS)
```

## 4. 행 버퍼 (Row Buffer) 최적화

```
행 버퍼 히트 (Row Buffer Hit):
  → 요청한 행이 이미 행 버퍼에 있음
  → CAS만 수행 → ~14ns (매우 빠름!)
  → 같은 행에 연속 접근 시 발생

행 버퍼 미스 (Row Buffer Miss):
  → 다른 행이 버퍼에 있음
  → Precharge → RAS → CAS → ~42ns

행 버퍼 빈(Empty Row Buffer):
  → 버퍼가 비어 있음
  → RAS → CAS → ~28ns (Precharge 불필요)
```

**행 버퍼 히트율 극대화**:
```c
// 같은 DRAM 행 내에서 연속 접근 → 행 버퍼 히트
// DRAM 행 크기: 8KB → 2048 int

// 좋은 패턴: 행 순서대로 접근
for (int i = 0; i < N; i++)
    process(arr[i]);  // 연속 주소 → 같은 행 버퍼 반복 활용

// 나쁜 패턴: 랜덤 접근 → 행 버퍼 미스 연발
for (int i = 0; i < N; i++)
    process(arr[rand() % N]);
```

## 5. 뱅크(Bank) 병렬성

```
뱅크 독립 동작:
  각 뱅크는 독립적으로 RAS/CAS 수행 가능
  → 여러 뱅크에 분산된 접근은 병렬 처리

뱅크 충돌 (Bank Conflict):
  → 같은 뱅크의 다른 행 접근 시 Precharge 대기 필요
  → 성능 저하

뱅크 주소 매핑 (일반적):
  물리 주소 비트 [6:0]:  캐시라인 오프셋 (64B)
  물리 주소 비트 [9:7]:  뱅크 선택 (3비트 = 8뱅크)
  물리 주소 비트 [25:10]: 행 주소
  
인터리빙: 연속 캐시라인이 서로 다른 뱅크에 분산
→ 순차 접근 시 자동으로 뱅크 병렬성 활용
```

## 6. DDR (Double Data Rate) 진화

```
규격     | 전송속도  | 대역폭(단일) | 전압 | 출시
────────────────────────────────────────────────
DDR1     | 200~400MT/s | 3.2 GB/s  | 2.5V | 2000
DDR2     | 400~1066MT/s| 8.5 GB/s  | 1.8V | 2003
DDR3     | 800~2133MT/s| 17 GB/s   | 1.5V | 2007
DDR4     | 1600~3200MT/s| 25.6 GB/s | 1.2V | 2014
DDR5     | 3200~6400MT/s| 51.2 GB/s | 1.1V | 2020

DDR: 클럭의 상승/하강 엣지 모두 사용 → SDR 대비 2배 속도
```

## 7. DRAM 리프레시 오버헤드

```
DRAM 리프레시 문제:
  커패시터 방전 → 64ms 내에 모든 행 리프레시 필요
  리프레시 동안: 메모리 접근 불가 (스톨)

DDR4 16GB 예시:
  행 수: 64K행 × 16뱅크 = 1M행
  리프레시 간격: 64ms / 1M행 = 64ns마다 한 행
  리프레시 시간: ~70ns
  → 오버헤드: 약 1~2%

Rowhammer 취약점:
  같은 행을 매우 빠르게 반복 접근(해머링)
  → 인접 행의 커패시터 비트 플립 유발
  → 메모리 보안 취약점
```

## 핵심 요약

- **DRAM 셀**: 1트랜지스터 + 1커패시터. 저렴하지만 주기적 리프레시 필요.
- **행/열 접근**: RAS(행 선택) → 행 버퍼 로드(8KB) → CAS(열 선택) → 데이터 반환.
- **행 버퍼 히트**: 같은 행 재접근 시 ~14ns. 미스 시 ~42ns. 순차 접근이 유리.
- **뱅크 병렬성**: 서로 다른 뱅크의 요청은 동시 처리 가능. 인터리빙으로 자동 활용.
- **DDR 진화**: DDR1→DDR5, 대역폭 2배씩 증가, 전압 감소 추세.
- **리프레시 오버헤드**: 64ms 주기, ~1~2% 성능 손실. Rowhammer 보안 취약점의 원인.
