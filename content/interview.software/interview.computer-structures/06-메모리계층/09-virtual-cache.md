## 가상 메모리와 캐시

현대 시스템에서 CPU는 **가상 주소(Virtual Address)**를 사용하고, 캐시와 메모리는 **물리 주소(Physical Address)**로 동작합니다. 이 불일치를 어떻게 처리하느냐에 따라 캐시 설계가 달라집니다.

---

## 1. 주소 변환 개요

```
가상 주소(VA) → [TLB/MMU] → 물리 주소(PA) → [캐시] → 데이터

문제: 캐시 접근에 주소 변환이 필요한데,
      변환 자체도 시간이 걸린다 (TLB 접근 ~5사이클)

설계 선택:
  언제 변환하느냐? → 캐시 접근 전 vs 후 vs 동시
```

---

## 2. PIPT (Physically Indexed, Physically Tagged)

> 물리 주소로 캐시 인덱싱 및 태그 비교.

```
동작:
VA → TLB → PA → 캐시 인덱스 계산 → 태그 비교 → 데이터 반환

장점:
  ✅ 구현 단순, 별칭(Aliasing) 문제 없음
  ✅ 서로 다른 프로세스의 같은 VA가 다른 PA면 → 자동으로 다른 캐시 엔트리

단점:
  ❌ TLB 변환 후 캐시 접근 → 직렬화 (느림)
  ❌ L1 캐시에 부적합 (지연 증가)

사용: L2, L3 캐시 (속도보다 정확성 우선)
```

---

## 3. VIVT (Virtually Indexed, Virtually Tagged)

> 가상 주소로 캐시 인덱싱 및 태그 비교.

```
동작:
VA → 캐시 인덱스 계산 → 태그 비교(VA 태그) → 데이터 반환
(TLB 변환 없이 즉시 캐시 접근!)

장점:
  ✅ TLB와 캐시 접근 완전 병렬화 → 가장 빠름

단점:
  ❌ 동의어(Synonym) 문제: 다른 VA → 같은 PA → 캐시에 중복 저장
     예: 프로세스A VA=0x1000, 프로세스B VA=0x2000 → 둘 다 PA=0x5000을 가리킴
     → 캐시에 두 개의 다른 엔트리로 저장됨 → 일관성 깨짐
  ❌ 컨텍스트 스위치 시 캐시 플러시 필요 (다른 프로세스의 VA 재사용)
  ❌ 동명(Homonym) 문제: 같은 VA → 다른 PA (프로세스마다 다른 매핑)

사용: 거의 사용 안 됨 (문제가 너무 많음)
```

---

## 4. VIPT (Virtually Indexed, Physically Tagged) — 현대 표준

> 가상 주소로 인덱싱, 물리 주소로 태그 비교.

```
동작:
VA → [캐시 인덱스 계산] ─────────────────────→ 세트 선택
VA → [TLB 변환] → PA → [태그 추출] → 태그 비교 ↗
(두 경로를 병렬로 수행!)

핵심 아이디어:
  캐시 인덱스 비트가 페이지 오프셋 비트에 포함되면
  → VA의 인덱스 비트 = PA의 인덱스 비트 (페이지 내 오프셋은 VA=PA)
  → TLB 변환 없이도 올바른 세트 선택 가능!
```

### VIPT의 조건: 인덱스 비트 ≤ 페이지 오프셋 비트

```
페이지 크기 4KB = 2^12 → 오프셋 12비트
캐시라인 64B = 2^6 → 블록 오프셋 6비트
캐시 세트 수 S = 2^s → 인덱스 s비트

조건: s + 6 ≤ 12 → s ≤ 6 → 세트 수 ≤ 64

예: L1 캐시 32KB, 8-Way, 64B 캐시라인
    세트 수 = 32KB / (8 × 64B) = 64세트 = 2^6
    인덱스 비트 = 6, 블록 오프셋 = 6
    → 총 12비트 = 페이지 오프셋 크기 → 조건 만족! ✅
    → VIPT이지만 PIPT와 동일하게 동작

만약 L1이 64KB, 8-Way라면:
    세트 수 = 128 = 2^7 → 인덱스 7비트
    7 + 6 = 13 > 12 → 조건 불만족! ❌
    → 동의어 문제 발생 → 소프트웨어 처리 필요
```

## 5. 캐시 설계와 TLB의 관계

```
현대 CPU (Intel Skylake 예시):
  L1-D: 32KB, 8-Way, 64B라인 → VIPT (사실상 PIPT)
  L2:   256KB, 4-Way          → PIPT
  L3:   8MB, 16-Way           → PIPT

TLB:
  L1-DTLB: 64엔트리, 완전 연관
  L2-TLB:  1536엔트리, 12-Way

최적 파이프라인:
  사이클 1: VA를 TLB와 L1 캐시 인덱스에 동시에 전달
  사이클 2: TLB→PA 완료 + L1에서 후보 라인 읽기 완료
  사이클 3: PA 태그와 캐시 태그 비교
  사이클 4: 히트면 데이터 반환 (총 4사이클!)
```

---

## 6. 컨텍스트 스위치와 캐시

```
프로세스 A → 프로세스 B 전환 시 문제:

VIVT: VA가 겹칠 수 있음 → 캐시 플러시 필수 (성능 손실)

VIPT/PIPT 태그가 PA이므로:
  → 다른 프로세스의 PA는 다름 → 자동 구분
  → 캐시 플러시 불필요!

단, TLB는 플러시 필요:
  → ASID(Address Space ID)로 해결 가능
  → ASID를 태그에 포함하면 TLB 플러시 없이 공존 가능
```

## 핵심 요약

- **PIPT**: 물리 주소로 인덱싱+태그. 정확하지만 TLB 직렬 접근으로 느림. L2/L3에 사용.
- **VIVT**: 가상 주소로만 처리. 빠르지만 동의어/동명어 문제. 실용적으로 미사용.
- **VIPT**: 가상 주소로 인덱싱, 물리 주소로 태그. TLB와 병렬 처리. **현대 L1 표준**.
- **VIPT 조건**: 캐시 인덱스 비트 + 블록 오프셋 비트 ≤ 페이지 오프셋 비트 (4KB=12비트).
- **동의어 문제**: 다른 VA → 같은 PA가 캐시에 중복 저장되는 문제. VIPT가 PA 태그로 해결.
