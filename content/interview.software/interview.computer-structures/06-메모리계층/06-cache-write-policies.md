## 캐시 쓰기 정책

CPU가 메모리에 **쓸(Write) 때** 캐시와 메인 메모리를 어떻게 동기화할 것인지 결정하는 정책입니다.

---

## 1. 쓰기 통과 (Write-Through)

> 캐시에 쓸 때 **메인 메모리에도 즉시 동시에 씀**.

```
Write-Through 동작:
CPU가 주소 X에 값 42 씀
  → 캐시의 해당 라인 업데이트 (42)
  → 동시에 메인 메모리도 업데이트 (42)
  → 항상 캐시 ≡ 메모리 (일관성 보장)

장점:
  ✅ 캐시와 메모리가 항상 일치 (구현 단순)
  ✅ 캐시 교체 시 추가 작업 없음 (이미 메모리에 있음)
  ✅ 충돌(Cache Coherence) 문제 단순화

단점:
  ❌ 매 쓰기마다 느린 메모리 접근 필요
  ❌ 쓰기 집중 워크로드에서 성능 저하
  ❌ 메모리 버스 대역폭 낭비
```

### Write-Through + Write-Around (No-Allocate)

```
쓰기 미스 발생 시 (Write-Through의 일반적 선택):
  → 메모리에만 씀, 캐시에 로드하지 않음 (No-Allocate)

이유: 어차피 메모리에 쓰므로, 캐시 공간 낭비 방지
     (쓴 데이터를 곧 읽지 않는 경우 효율적)
```

---

## 2. 쓰기 후 기록 (Write-Back)

> 캐시에만 쓰고, 해당 라인이 **교체될 때 메모리에 씀**.

```
Write-Back 동작:
CPU가 주소 X에 값 42 씀
  → 캐시의 해당 라인 업데이트 (42)
  → Dirty 비트 = 1 (메모리와 다름을 표시)
  → 메모리는 아직 업데이트 안 됨!

나중에 해당 라인 교체 시:
  → Dirty 비트 == 1이면 메모리에 씀 (Write-Back)
  → Dirty 비트 == 0이면 그냥 버림

장점:
  ✅ 대부분의 쓰기가 캐시에서만 처리 (빠름)
  ✅ 같은 라인에 여러 번 쓰면 한 번만 메모리 접근
  ✅ 메모리 버스 사용 최소화

단점:
  ❌ Dirty 비트 관리 복잡
  ❌ 캐시 교체 시 추가 메모리 쓰기 필요
  ❌ 시스템 충돌 시 캐시의 더티 데이터 손실 가능
```

### Dirty 비트 구조

```
캐시 엔트리 구조 (Write-Back):
┌───────┬───────────┬──────────────────────────┐
│ Valid │   Tag     │        Data (64B)         │
│  (1b) │           │                           │
├───────┼───────────┼──────────────────────────┤
│   1   │  0xA3F2   │  [수정된 데이터]          │ ← Dirty=1
│   1   │  0xB1C0   │  [원본 그대로]            │ ← Dirty=0
└───────┴───────────┴──────────────────────────┘
        ↑ Dirty 비트 추가
```

## 3. 쓰기 미스 처리 정책

쓰려는 주소가 캐시에 없을 때(쓰기 미스):

### 3.1 Write-Allocate (Fetch on Write)

```
쓰기 미스 발생
  → 메모리에서 해당 캐시라인 로드 (64바이트)
  → 캐시에서 원하는 위치 업데이트
  → Write-Back과 함께 주로 사용

장점: 이후 같은 캐시라인 읽기 시 히트
단점: 미스 시 캐시라인 전체 로드하는 오버헤드
```

### 3.2 No-Write-Allocate (Write-Around)

```
쓰기 미스 발생
  → 메모리에 직접 씀 (캐시 미로드)
  → Write-Through와 함께 주로 사용

장점: 캐시 오염(Pollution) 방지
단점: 이후 같은 데이터 읽으면 캐시 미스
```

---

## 4. 일반적인 조합

| 쓰기 정책 | 미스 정책 | 특징 | 사용 사례 |
|-----------|-----------|------|-----------|
| Write-Through | No-Write-Allocate | 단순, 느림 | L1 (일부), 임베디드 |
| Write-Back | Write-Allocate | 복잡, 빠름 | **현대 CPU L1/L2/L3** |

```
현대 x86-64 CPU (Intel, AMD):
  L1, L2, L3: Write-Back + Write-Allocate
  이유: 성능 극대화, 버스 대역폭 절약
```

## 5. 멀티코어에서의 쓰기 정책 문제

```
Write-Back의 캐시 일관성 문제:
Core 0: x = 1 씀 → Core 0의 L1에만 반영 (Dirty)
Core 1: x 읽음  → Core 1의 L1에는 x = 0 (구버전!)

해결: MESI 프로토콜 (캐시 일관성 프로토콜)
  M (Modified):  이 코어만 가짐, 수정됨 (Dirty)
  E (Exclusive): 이 코어만 가짐, 수정 안 됨
  S (Shared):    여러 코어가 공유, 읽기 전용
  I (Invalid):   유효하지 않음

Core 0가 x를 수정(M 상태)하면:
  → 다른 코어의 x 캐시라인을 Invalid 처리
  → Core 1이 x 읽으면 Core 0에서 직접 가져옴
```

## 핵심 요약

- **Write-Through**: 캐시와 메모리 동시 업데이트. 단순하지만 느림.
- **Write-Back**: 캐시에만 쓰고 나중에 메모리 반영. 빠르지만 Dirty 비트 필요.
- **현대 CPU**: Write-Back + Write-Allocate 조합 사용.
- **Dirty 비트**: Write-Back에서 캐시라인이 수정됐는지 추적하는 1비트 플래그.
- **멀티코어**: Write-Back에서 MESI 프로토콜로 캐시 일관성 보장.
