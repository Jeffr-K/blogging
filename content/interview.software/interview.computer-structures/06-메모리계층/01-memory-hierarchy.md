## 메모리 계층 구조

컴퓨터 시스템의 메모리는 **속도, 크기, 비용** 사이의 근본적인 트레이드오프 때문에 여러 계층으로 구성됩니다.

---

## 1. 메모리 계층 구조표

```
계층          | 기술       | 용량       | 레이턴시    | 대역폭      | 비용/GB
─────────────────────────────────────────────────────────────────────────
레지스터      | SRAM       | 수백 바이트 | 0사이클     | -           | 극고
L1 캐시       | SRAM       | 32~64KB    | 4~5사이클   | ~1TB/s      | 매우 고
L2 캐시       | SRAM       | 256KB~1MB  | 12~15사이클 | ~400GB/s    | 고
L3 캐시       | SRAM       | 8~64MB     | 30~50사이클 | ~200GB/s    | 중
DRAM (주기억) | DRAM       | 8~64GB     | 60~100ns    | ~50GB/s     | 저
SSD           | NAND Flash | 512GB~4TB  | 50~100μs    | ~3GB/s      | 매우 저
HDD           | 자기 디스크 | 1~20TB    | 5~10ms      | ~200MB/s    | 극저
```

시간 비교 (1ns = CPU 3사이클 @ 3GHz):
```
L1 캐시 히트:    4사이클   ≈  1.3ns
L2 캐시 히트:   12사이클   ≈  4ns
L3 캐시 히트:   40사이클   ≈ 13ns
DRAM 접근:     200사이클   ≈ 67ns   (L1의 50×!)
SSD 읽기:    150,000사이클 ≈ 50μs   (L1의 37,500×)
HDD 읽기: 30,000,000사이클 ≈ 10ms   (L1의 7,500,000×)
```

## 2. 메모리 계층이 존재하는 이유

### 2.1 속도-용량 트레이드오프

```
왜 전부 SRAM(캐시)으로 만들지 않는가?
→ SRAM은 비쌈: 1GB SRAM ≈ $1,000~$10,000
→ SRAM은 큼: 6개 트랜지스터/비트 vs DRAM 1개

왜 전부 DRAM으로 만들지 않는가?
→ DRAM은 느림: L1 대비 50× 느림
→ CPU가 DRAM 속도로 실행하면 성능 1/50로 감소
```

### 2.2 지역성 원칙 (Locality Principle)

메모리 계층이 효과적인 이유는 프로그램이 **지역성**을 가지기 때문입니다:

**시간 지역성 (Temporal Locality)**:
- 최근에 접근한 메모리는 곧 다시 접근될 가능성이 높다
- 예: 루프 변수, 자주 호출되는 함수

**공간 지역성 (Spatial Locality)**:
- 접근한 메모리 근처에 곧 접근할 가능성이 높다
- 예: 배열 순회, 구조체 멤버 접근

```c
// 두 가지 지역성을 모두 가진 코드
int sum = 0;                    // sum: 시간 지역성
for (int i = 0; i < N; i++) {  // i: 시간 지역성
    sum += arr[i];              // arr[i]: 공간 지역성 (순차 접근)
}
```

## 3. 캐시의 동작 원리

### 3.1 포함 관계 (Inclusion)

```
더 낮은 계층은 더 높은 계층의 내용을 포함함:

L1에 있으면 → L2에도 있음 (보통)
L2에 있으면 → L3에도 있음
L3에 있으면 → DRAM에도 있음

(Exclusive Cache: 다른 계층에 없는 경우도 있지만 드묾)
```

### 3.2 전송 단위: 블록/캐시라인

```
L1 ↔ L2: 64바이트 캐시라인 단위
L2 ↔ L3: 64바이트 (보통)
L3 ↔ DRAM: 64바이트 (또는 더 큰 버스트)
DRAM ↔ SSD: 4KB 페이지 단위
SSD ↔ HDD: 통상적으로 없음 (SSD가 주 저장소)

이유: 공간 지역성 때문에 근처 데이터도 함께 가져옴 (Prefetch 효과)
```

## 4. 현대 CPU 캐시 구조

```
┌─────────────────────────────────────────────┐
│  Core 0             Core 1                  │
│  ┌──────────┐      ┌──────────┐            │
│  │L1-I (32K)│      │L1-I (32K)│  (명령어)  │
│  │L1-D (32K)│      │L1-D (32K)│  (데이터)  │
│  └────┬─────┘      └─────┬────┘            │
│       │                   │                  │
│  ┌────┴─────┐      ┌─────┴────┐            │
│  │L2 (512K) │      │L2 (512K) │            │
│  └────┬─────┘      └─────┬────┘            │
│       └──────────┬────────┘                 │
│            ┌─────┴──────┐                   │
│            │  L3 (16MB) │   ← 코어 공유    │
│            └─────┬──────┘                   │
│                  │                           │
│            ┌─────┴──────┐                   │
│            │  DRAM      │   64GB             │
└────────────────────────────────────────────┘

인텔 Core i9-13900K:
- L1-D: 48KB per core (x24코어)
- L2: 2MB per core
- L3 (LLC): 36MB 공유
```

## 5. 캐시가 프로그램 성능에 미치는 영향

```c
// 실험: 배열 크기에 따른 읽기 속도
void benchmark(int n) {
    int *arr = malloc(n * sizeof(int));
    // 랜덤 접근 (지역성 없음)
    for (long i = 0; i < 100000000; i++) {
        sum += arr[rand() % n];
    }
}

// 결과:
// n=1K   (4KB):  0.5 ns/접근  ← L1 캐시
// n=8K   (32KB): 0.5 ns/접근  ← L1 캐시
// n=32K  (128KB):1.5 ns/접근  ← L2 캐시
// n=256K (1MB):  4.0 ns/접근  ← L3 캐시
// n=4M   (16MB): 10 ns/접근   ← L3 미스, DRAM
// n=64M  (256MB):50 ns/접근   ← 완전 DRAM
```

## 핵심 요약

- **메모리 계층**: 빠름→느림, 작음→큼: 레지스터→L1→L2→L3→DRAM→SSD→HDD.
- **속도 차이**: L1(4ns) vs DRAM(67ns) = 16×, DRAM vs SSD = 750×, SSD vs HDD = 200×.
- **지역성 원칙**: 시간 지역성(최근 접근 재접근)과 공간 지역성(근처 데이터 접근)으로 계층 구조가 효과적.
- **캐시라인**: 64바이트 단위로 계층 간 데이터 이동. 근처 데이터도 함께 로드.
- **캐시 히트율이 핵심**: 히트율 99% vs 95%는 성능 수십 배 차이.
