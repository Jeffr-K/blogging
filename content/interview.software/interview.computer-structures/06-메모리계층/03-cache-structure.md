## 캐시 내부 구조

캐시는 메모리 주소를 **세트(Set)**, **라인(Line)**, **태그(Tag)**로 분해하여 빠르게 데이터를 찾습니다.

---

## 1. 캐시 파라미터

캐시는 다음 파라미터로 특성화됩니다:

```
(S, E, B) 트리플렛:
- S = 세트 수 (S = 2^s)
- E = 각 세트의 라인(웨이) 수
- B = 블록(캐시라인) 크기 in 바이트 (B = 2^b)

캐시 총 크기 = S × E × B 바이트
```

예시: 32KB L1 캐시, 8-way, 64B 라인:
```
B = 64 → b = 6
S × E × B = 32,768
S × 8 × 64 = 32,768
S = 64 → s = 6
```

---

## 2. 주소 분해

64비트 주소가 다음과 같이 분해됩니다:

```
[  태그 (t비트)  |  세트 인덱스 (s비트)  |  블록 오프셋 (b비트)  ]
 63            ...   s+b          ...    b          ...         0

예: 주소 = 0x00007FFF_AABB1234
b = 6비트 (64B 블록): 블록 오프셋 = 0x34 & 0x3F = 52번째 바이트
s = 6비트 (64세트):   세트 인덱스 = (0x1234 >> 6) & 0x3F = 세트 8
태그 = 나머지 비트
```

캐시 조회 과정:
```
1. 주소에서 세트 인덱스(s비트) 추출 → 해당 세트로 이동
2. 세트 내 모든 라인의 태그와 비교 (병렬)
3. 태그 일치 + Valid bit = 1 → 캐시 히트!
4. 블록 오프셋(b비트)으로 해당 바이트 추출
```

## 3. 캐시 조직 구조

### 3.1 물리적 구조

```
세트 0: [V|태그|데이터 64B] [V|태그|데이터 64B]  ← E=2인 경우 (2-way)
세트 1: [V|태그|데이터 64B] [V|태그|데이터 64B]
세트 2: [V|태그|데이터 64B] [V|태그|데이터 64B]
...
세트 S-1: [V|태그|데이터 64B] [V|태그|데이터 64B]

V = Valid bit (이 라인의 데이터가 유효한지)
태그 = 메모리 주소의 상위 비트 (이 라인이 어떤 주소의 데이터인지)
데이터 = 실제 캐시된 메모리 블록 (64바이트)
```

### 3.2 구체적인 히트/미스 시뮬레이션

가정: 4세트, 1-way(직접 매핑), 4B 블록
```
주소 형식: [태그 | 세트 인덱스 2비트 | 블록 오프셋 2비트]

초기 상태: 모든 Valid bit = 0

접근 순서: 0, 1, 7, 8, 0

주소 0 (0b0000): 세트0, 태그=0 → MISS (cold miss)
  세트0: [V=1|태그=0|data@0x0]

주소 1 (0b0001): 세트0, 블록0 오프셋1 → HIT!

주소 7 (0b0111): 세트1, 태그=0 → MISS
  세트1: [V=1|태그=0|data@0x4]  (4~7 로드)

주소 8 (0b1000): 세트0, 태그=1 → MISS (conflict: 세트0 덮어씀!)
  세트0: [V=1|태그=2|data@0x8]

주소 0 (0b0000): 세트0, 태그=0 → MISS (conflict miss! 0x8로 덮어씌워짐)
```

## 4. 세트 연관도 (Set Associativity)

### 4.1 직접 매핑 (Direct Mapped, E=1)

```
장점: 하드웨어 단순, 빠른 조회
단점: 충돌 미스(Conflict Miss) 많음

예: 주소 A와 주소 B가 같은 세트에 매핑
→ A, B를 번갈아 접근하면 계속 미스!
```

### 4.2 완전 연관 (Fully Associative, E=S)

```
장점: 충돌 미스 없음
단점: 모든 라인과 태그 비교 필요 → 하드웨어 복잡, 느림
→ 실제로 작은 캐시(TLB, L1 i-cache 일부)에만 사용
```

### 4.3 N-way 집합 연관 (Set Associative, E=N)

```
현대 CPU 캐시:
- L1: 8-way (속도 우선)
- L2: 8~16-way
- L3: 16~32-way

N이 클수록 충돌 미스 감소, 하드웨어 비용 증가
실용적으로 8-way 이상은 이득이 급격히 줄어듦
```

## 5. 캐시 라인 내부 구조

```
캐시 라인 1개 (예: 64바이트):
┌───┬──────────────────────────────────────────────────────┐
│ V │  태그 (예: 46비트)  │     데이터 (64바이트)          │
│ 1 │  0x7FFF_AABB_0012  │ [00][01][02]...[3F]            │
└───┴──────────────────────────────────────────────────────┘

V (Valid): 이 라인이 유효한 데이터인지 (리셋 시 0)
Dirty bit (쓰기 정책에 따라): 수정된 데이터인지
```

---

## 6. 캐시 읽기/쓰기 흐름

```
읽기:
1. 주소 → 세트 인덱스 추출
2. 해당 세트의 모든 라인 태그와 비교
3. 히트: 블록 오프셋으로 데이터 반환 (~4사이클)
4. 미스: 하위 계층에서 블록 로드, 라인 교체

쓰기:
1. 캐시 히트 시:
   - Write-through: 즉시 DRAM에도 씀 (일관성↑, 대역폭↓)
   - Write-back: 캐시만 업데이트, Dirty bit 설정 (추후 DRAM 반영)
2. 캐시 미스 시:
   - Write-allocate: 먼저 블록 로드 후 수정 (일반적)
   - No-write-allocate: 캐시 건너뛰고 직접 씀 (대용량 스트리밍)
```

## 핵심 요약

- **캐시 파라미터 (S, E, B)**: S=세트 수, E=웨이(라인/세트), B=블록 크기.
- **주소 분해**: [태그 | 세트 인덱스 | 블록 오프셋] → 세트→태그비교→오프셋 순으로 접근.
- **Valid bit**: 캐시 라인이 유효한 데이터를 담고 있는지 표시.
- **E=1 (직접 매핑)**: 빠르지만 충돌 미스 多. **E=∞ (완전 연관)**: 충돌 없지만 복잡. 현실은 E=8~16.
- **Dirty bit**: Write-back 캐시에서 수정된 라인 표시 → 교체 시 DRAM에 반영.
