## 동시성 vs 병렬성

자주 혼동되는 두 개념을 명확히 구분합니다.

---

## 1. 핵심 정의

```
동시성 (Concurrency):
  여러 작업이 논리적으로 동시에 진행되는 것
  실제로 같은 순간에 실행될 필요 없음
  "여러 일을 다루는 능력" (dealing with multiple things at once)
  
  단일 코어에서도 가능:
  시간 분할(Time-slicing)로 번갈아 실행

병렬성 (Parallelism):
  여러 작업이 물리적으로 동시에 실행되는 것
  다수의 CPU/코어가 반드시 필요
  "여러 일을 동시에 하는 능력" (doing multiple things at once)

관계:
  병렬성 → 동시성 (병렬이면 항상 동시)
  동시성 → 병렬성 아닐 수 있음 (단일 코어 동시성)
```

---

## 2. 시각화

```
단일 코어 동시성 (시분할):
  코어: [작업A][작업B][작업A][작업B][작업A]
  시간: ───────────────────────────────────→
  → A와 B가 번갈아 실행 (빠르면 동시처럼 보임)

멀티코어 병렬성:
  코어1: [작업A][작업A][작업A]
  코어2: [작업B][작업B][작업B]
  시간:  ───────────────────────→
  → A와 B가 진짜 동시에 실행

멀티코어 동시+병렬:
  코어1: [작업A][작업C][작업A]
  코어2: [작업B][작업B][작업D]
  → 코어 내 동시성 + 코어 간 병렬성
```

---

## 3. 동시성 구현 방법 (CSAPP)

```
방법 1: 프로세스 기반 동시성
  fork()로 새 프로세스 생성
  각 프로세스가 독립적 메모리 공간
  오버헤드 큼, IPC 필요

방법 2: I/O 다중화 기반 동시성
  이벤트 루프 (Event Loop)
  epoll + 논블로킹 I/O
  단일 스레드에서 다수 연결 처리
  Node.js, Nginx 방식

방법 3: 스레드 기반 동시성
  같은 프로세스 내 여러 실행 흐름
  메모리 공유 (장점이자 위험)
  경량, 빠른 통신
```

---

## 4. CPU 관점: 명령어 수준 병렬성

```
파이프라이닝:
  여러 명령어가 파이프라인 단계에서 중첩 실행
  단일 코어에서 ILP (Instruction Level Parallelism)

슈퍼스칼라:
  같은 사이클에 여러 명령어 동시 실행
  여러 실행 유닛 (ALU, FPU 등)

SIMD:
  하나의 명령어로 여러 데이터 동시 처리
  벡터 연산 (AVX, SSE)

멀티코어:
  물리적으로 독립된 CPU 코어
  진정한 병렬 실행
```

---

## 5. 동시성이 필요한 이유

```
I/O 바운드 작업:
  파일 읽기/쓰기: CPU 대기 시간 동안 다른 작업
  네트워크 요청: 응답 기다리는 동안 다른 처리
  → 단일 코어에서도 동시성으로 처리량 향상

CPU 바운드 작업:
  계산 집약적 작업
  멀티코어 병렬성 필요
  → 코어 수만큼 속도 향상 가능

응답성 (Responsiveness):
  UI 스레드가 블로킹되지 않도록
  백그라운드 작업과 분리
```

---

## 6. 동시성의 복잡성

```
동시성이 어려운 이유:

경쟁 상태 (Race Condition):
  실행 순서에 따라 결과가 달라짐
  디버깅 어려움 (간헐적 버그)

데드락 (Deadlock):
  서로 상대방 락을 기다려 영원히 대기

라이브락 (Livelock):
  계속 실행 중이지만 진전 없음

기아 (Starvation):
  특정 스레드가 영원히 자원 획득 못 함

비결정론적 동작:
  같은 입력에도 매번 다른 실행 순서 가능
```

---

## 핵심 요약

- **동시성**: 논리적 동시. 단일 코어 가능. I/O 바운드에 효과적.
- **병렬성**: 물리적 동시. 다수 코어 필요. CPU 바운드에 효과적.
- **3가지 동시성**: 프로세스 기반, I/O 다중화, 스레드 기반.
- **동시성의 도전**: 경쟁 상태, 데드락, 비결정론.
