## 파이프라인 해저드 (Pipeline Hazard)

파이프라인이 이상적으로 동작하지 못하게 만드는 상황을 **해저드(Hazard)**라 합니다. 해저드는 파이프라인을 멈추게(Stall) 하거나, 잘못된 결과를 만들 수 있습니다. 세 종류가 있습니다.

---

## 1. 구조적 해저드 (Structural Hazard)

**두 명령어가 동시에 같은 하드웨어 자원을 사용하려 할 때** 발생합니다.

### 예시: 메모리 1개인 경우

```
I-Cache와 D-Cache를 분리하지 않고 메모리 1개만 있다면:

사이클: 1    2    3    4    5
I1:    [F]  [D]  [E→메모리 읽기]   ← 메모리 사용
I2:         [F]  [D]  [E]  [W]
I3:              [F → 메모리 필요]  ← 충돌!

→ 명령어 인출(F)과 데이터 읽기(E)가 동시에 메모리 필요
```

### 해결책

- **자원을 복제**: I-Cache와 D-Cache를 분리 (L1 캐시에서 항상 적용됨)
- **스톨(Stall)**: 한 명령어를 기다리게 하는 NOP(No Operation) 삽입

현대 CPU는 I-Cache/D-Cache 분리로 대부분 구조적 해저드를 제거합니다.

## 2. 데이터 해저드 (Data Hazard)

**이전 명령어의 결과를 아직 쓰기 전에 다음 명령어가 그 값을 읽으려 할 때** 발생합니다.

### RAW (Read After Write) — 가장 일반적

```c
// 데이터 의존성
a = b + c;    // I1: rax = rbx + rcx
d = a * e;    // I2: rdi = rax * rsi (a가 아직 준비 안 됨!)
```

```
사이클:  1    2    3    4    5    6
I1:     [F]  [D]  [E]  [W]       ← rax에 결과 기록: 사이클 4
I2:          [F]  [D]  [E] ...   ← E 단계에서 rax 읽어야 함: 사이클 4
                                    충돌! I2는 사이클 3에 Decode해서 E에 들어가는데
                                    I1은 사이클 4에야 rax를 기록
```

파이프라인이 이를 감지하지 못하면 I2가 **이전 rax 값**(잘못된 값)을 읽습니다.

### WAR (Write After Read) — 메모리 해저드, 비순차 실행에서 발생

```
I1: 읽기 연산 (rax 사용)
I2: 쓰기 연산 (rax에 쓰기)
비순차 실행으로 I2가 먼저 실행되면 I1이 잘못된 값을 읽음
```

### WAW (Write After Write) — 비순차 실행에서 발생

```
I1: rax에 쓰기
I2: rax에 쓰기 (나중에 써야 하는데 먼저 쓰면 문제)
```

## 3. 제어 해저드 (Control Hazard)

**분기(Branch) 명령어의 결과를 알기 전에 다음 명령어를 미리 인출할 때** 발생합니다.

```c
if (x > 0) {
    y = x * 2;   // 분기 성공 시
} else {
    y = -x;      // 분기 실패 시
}
```

```
사이클:  1    2    3    4    5
I1:     [F]  [D]  [E]  [W]        ← cmp 실행
I2:          [F]  [D]  [E]  [W]   ← jg 실행, 사이클 3에서 결과 알아
I3???:            [F]  ...        ← 어떤 명령어를 인출해야 하나?
                                    jg 결과가 사이클 3에 나오는데
                                    I3를 사이클 3에 이미 인출함
```

분기 방향을 모르는 상태에서 잘못된 명령어를 미리 인출하면, 이를 버려야(flush) 합니다. 이를 **분기 패널티(Branch Penalty)**라 합니다.

```
분기 패널티 = 파이프라인 단계 수 - 분기 결과를 아는 단계

예: 5단계 파이프라인, 분기 결과가 E(3단계)에서 결정
패널티 = 3 - 1 = 2 사이클 낭비
```

## 4. 스톨 (Stall, Pipeline Bubble)

해저드가 감지되면 CPU는 파이프라인에 **버블(Bubble, NOP)**을 삽입하여 기다립니다.

```
데이터 해저드 스톨 예시:

사이클:  1    2    3    4    5    6    7
I1:     [F]  [D]  [E]  [W]
I2:          [F]  [D] [NOP][NOP] [E]  [W]
                        ^이 두 사이클이 낭비됨 (스톨)
```

스톨은 성능 저하를 유발합니다. 이를 최소화하기 위해 **데이터 포워딩(Forwarding)**이 사용됩니다.

---

## 5. 해저드 종류 요약

| 해저드 종류 | 원인 | 해결책 |
|------------|------|--------|
| 구조적 해저드 | 하드웨어 자원 충돌 | 자원 복제 (I/D-Cache 분리) |
| 데이터 해저드 (RAW) | 이전 결과 미완성 | 포워딩, 스톨, 코드 재배치 |
| 제어 해저드 | 분기 방향 미결정 | 분기 예측, 지연 슬롯 |

---

## 6. 실제 CPU의 성능 영향

```
CPI (Cycles Per Instruction):
이상적: 1.0
실제 (고성능 CPU): 0.3~0.5 (슈퍼스칼라)
해저드로 인한 손실:

Intel Core i7 (코드 믹스 기준):
- 데이터 해저드 + 포워딩: ~5% 손실
- 분기 예측 실패: ~15% 손실  ← 가장 큰 비중
- 캐시 미스: ~30~50% 손실   ← 메모리 병목
```

---

## 핵심 요약

- **구조적 해저드**: 하드웨어 충돌. 자원 복제로 해결.
- **데이터 해저드(RAW)**: 이전 명령어 결과를 다음이 필요로 함. 포워딩 또는 스톨.
- **제어 해저드**: 분기 방향 불명확. 분기 예측으로 완화.
- **스톨**: 파이프라인에 NOP 삽입 = CPI 증가 = 성능 저하.
- 현대 CPU는 포워딩 + 분기 예측 + 비순차 실행으로 대부분의 해저드를 숨깁니다.
