## 데이터 포워딩

데이터 포워딩(Data Forwarding, 또는 Bypassing)은 **명령어의 결과가 레지스터 파일에 기록되기 전에, 직접 다음 명령어의 입력으로 전달**하는 기법입니다. 스톨 없이 대부분의 RAW 해저드를 해결합니다.

---

## 1. 포워딩 없이 스톨만 사용하는 경우

```c
int a = b + c;  // I1: rax = rbx + rcx
int d = a * 2;  // I2: rdi = rax * 2 (a를 바로 사용)
```

```
스톨만 사용:
사이클:  1    2    3    4    5    6    7
I1:     [F]  [D]  [E]  [W]              rax 기록: 사이클 4
I2:          [F]  [D] [NOP][NOP] [E]  [W]
                        ↑↑ 스톨 2사이클 낭비
```

I1이 Write-back(W)에서 rax를 기록한 후에야 I2의 Execute(E)가 rax를 읽을 수 있습니다.

---

## 2. 포워딩 적용

Execute 단계 직후 결과를 **파이프라인 레지스터**를 통해 다음 명령어의 Execute로 바로 전달합니다.

```
포워딩 사용:
사이클:  1    2    3    4    5
I1:     [F]  [D]  [E]  [W]      ← E 단계에서 rax 계산 완료
I2:          [F]  [D]  [E] [W]  ← E 단계에서 I1의 E 결과를 바로 받음
                        ↑ 포워딩! (스톨 없음)
```

포워딩은 **배선(wire)과 멀티플렉서(MUX)**로 구현됩니다. 실행 결과가 특정 파이프라인 레지스터에서 다음 단계의 ALU 입력으로 연결됩니다.

---

## 3. 포워딩 경로의 종류

```
포워딩 경로:
EX → EX: 바로 다음 명령어에 포워딩 (1-사이클 간격)
MEM → EX: 2개 이전 명령어에서 포워딩 (2-사이클 간격)
WB → EX: 3개 이전 명령어에서 포워딩 (3-사이클 간격, 보통 불필요)
```

```
예시:
I1: add rax, rbx, rcx   # rax = rbx + rcx
I2: add rdi, rax, rdx   # EX→EX 포워딩: I1의 E 결과를 I2의 E로
I3: add rsi, rax, r8    # MEM→EX 포워딩: I1의 M 결과를 I3의 E로
```

---

## 4. 포워딩으로도 해결 안 되는 경우: Load-Use Hazard

메모리 로드 명령어 직후 그 값을 바로 사용하는 경우, **1 사이클 스톨이 불가피**합니다.

```c
long *p = ...;
long a = *p;   // I1: load rax, (p)
long b = a + 1; // I2: add rbx, rax, 1 (a를 바로 사용)
```

```
사이클:  1    2    3    4    5    6
I1(load): [F]  [D]  [E]  [M]  [W]   ← 메모리에서 읽기: M 단계에 완료
I2(add):       [F]  [D] [스톨] [E]  [W]
                           ↑ 1 사이클 스톨 불가피
                     (I1의 M이 완료되어야 포워딩 가능)
```

M(Memory) → E(Execute) 포워딩으로 1사이클은 절약하지만, Load의 M 단계는 E 다음에 오므로 최소 1 사이클 스톨이 필요합니다.

### 컴파일러 최적화: 스케줄링으로 스톨 숨기기

```c
// 스톨이 발생하는 코드
long a = *p;
long b = a + 1;  // a를 바로 사용 → 스톨

// 컴파일러가 다른 독립적 명령어를 사이에 삽입
long a = *p;
long c = x + y;  // 독립적인 연산 삽입 (스톨 동안 유용한 작업)
long b = a + 1;  // 이제 a가 준비됨 → 스톨 없음!
```

---

## 5. 스톨 (Stall)

포워딩으로 해결하지 못하는 경우, 파이프라인에 버블(NOP)을 삽입합니다.

### 하드웨어 스톨 구현

```
스톨 발생 시:
1. Decode 단계에서 해저드 감지
2. Execute 단계에 NOP 삽입
3. Fetch와 Decode 단계를 일시 정지 (PC와 IF/ID 레지스터 유지)
4. 해저드 해소 후 정상 진행
```

```
스톨 삽입 시 파이프라인:

정상:  I1[F] → I1[D] → I1[E] → I1[W]
           I2[F] → I2[D] → I2[E] → I2[W]

스톨:  I1[F] → I1[D] → I1[E] → I1[W]
           I2[F] → I2[D] → [NOP] → I2[E] → I2[W]
                    ↑ 정지         ↑ 재개
```

---

## 6. 포워딩 vs 스톨 비교

| 해결책 | 비용 | 적용 가능 경우 |
|--------|------|--------------|
| 포워딩 | 하드웨어 배선 추가 | 대부분의 RAW 해저드 |
| 스톨 | CPI 증가 (성능 손실) | Load-Use 해저드 |
| 코드 재배치 | 컴파일러 복잡도 | 독립적 명령어가 있는 경우 |

---

## 7. 실제 영향

```
포워딩 없이 스톨만 사용 시:
  일반 코드: CPI ≈ 1.5~2.0 (RAW 해저드 빈번)

포워딩 적용 후:
  일반 코드: CPI ≈ 1.0~1.1 (Load-Use 스톨만 남음)

→ 포워딩으로 ~50% 성능 향상!
```

---

## 핵심 요약

- **포워딩**: 실행 결과를 레지스터 기록 전에 다음 명령어로 직접 전달. 대부분의 RAW 해저드 해결.
- **Load-Use 해저드**: 로드 직후 사용 → 1사이클 스톨 불가피. 포워딩으로도 완전 해결 불가.
- **컴파일러 스케줄링**: 스톨 구간에 독립적인 명령어 배치 → 실질적 스톨 제거.
- **스톨**: NOP 삽입 → CPI 증가 → 성능 손실. 마지막 수단.
