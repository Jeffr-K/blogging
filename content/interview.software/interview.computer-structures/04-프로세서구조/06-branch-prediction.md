## 분기 예측 (Branch Prediction)

현대 CPU는 분기 명령어(`if`, `loop`, `switch`)의 결과를 미리 **예측**하고 예측된 경로의 명령어를 미리 실행합니다. 예측이 맞으면 성능 이득, 틀리면 취소(flush)하고 재시작합니다.

---

## 1. 왜 분기 예측이 중요한가?

현대 CPU의 파이프라인은 20단계 이상입니다. 분기 명령어의 결과(어느 방향으로 갈지)는 파이프라인 중간(약 15단계)에서 결정됩니다.

```
분기 결과 확인 전까지: 15개 명령어가 파이프라인에 채워짐
예측 실패 시: 15개 명령어를 모두 버려야 함 (15 사이클 낭비)

분기 명령어 빈도: 전체 명령어의 약 20%
예측 실패율: 1%라도 성능에 큰 영향!
```

## 2. 예측 전략의 종류

### 2.1 정적 예측 (Static Prediction)

실행 시간과 무관하게 항상 같은 방향을 예측.

**전방 분기(Forward Branch)**: 분기 안 함 예측 (조건 거짓 → 루프 진행)
**후방 분기(Backward Branch)**: 분기 함 예측 (루프 반복)

```asm
# 루프의 후방 분기 (반복이 더 많으므로 "분기 함" 예측)
.loop:
    # 루프 본문
    dec rcx
    jnz .loop   ← 후방 분기: "분기 함" 예측이 보통 맞음
```

### 2.2 1-bit 예측기

직전 분기 결과를 기억해 다음에도 같은 방향으로 예측.

```
상태: {분기안함, 분기함}

분기함 → 다음도 "분기함" 예측
분기안함 → 다음도 "분기안함" 예측

문제: 루프 마지막에 항상 실패!
for(i=0; i<100; i++) {
    // 99번 분기함, 마지막에 분기안함 → 매 루프마다 1회 실패
}
```

### 2.3 2-bit 포화 카운터 (Saturating Counter)

가장 많이 사용되는 기법. 4개 상태.

```
상태: [강하게 분기안함] → [약하게 분기안함] → [약하게 분기함] → [강하게 분기함]
      (Strongly Not)     (Weakly Not)        (Weakly Taken)     (Strongly Taken)

분기 발생 시: 카운터 +1 (최대 "강하게 분기함")
분기 없을 시: 카운터 -1 (최솟값 "강하게 분기안함")
```

2-bit이므로 한 번의 예외가 있어도 예측을 바꾸지 않습니다. 루프에서 마지막 한 번의 예측 실패만 발생합니다.

### 2.4 상관 예측기 (Correlating Predictor)

여러 이전 분기의 패턴을 기억하여 예측.

```c
// 이전 분기와 상관있는 예시
if (x > 0) {       // 분기 A
    if (y > 0) {   // 분기 B: A가 true일 때만 실행
        // ...
    }
}
```

분기 A가 true였다면 분기 B도 true일 가능성이 높음. 이전 분기 패턴(`[A결과]`로 인덱싱)을 사용해 정확도 향상.

### 2.5 토너먼트 예측기 (Tournament Predictor)

여러 예측기를 경쟁시켜 더 정확한 것을 선택.

```
예: AMD와 Intel의 현대 CPU
- 지역 예측기 (해당 분기의 역사)
- 전역 예측기 (모든 분기의 역사)
- 선택기 (어떤 예측기가 더 나은지 기록)
```

### 2.6 TAGE (TAgged GEometric history length) 예측기

현대 고성능 CPU(Intel Alder Lake 이후)에서 사용. 여러 길이의 분기 이력을 기하급수적으로 관리. 예측 정확도 99%+.

## 3. 분기 목표 주소 예측 (Branch Target Buffer, BTB)

분기 방향(taken/not-taken) 뿐만 아니라 **어디로 분기할지(목표 주소)**도 미리 알아야 합니다.

```
BTB: 분기 명령어 주소 → 목표 주소 캐시
     Fetch 단계에서 바로 목표 주소 사용 가능

BTB 없이: 분기 명령어를 디코드해서 주소 계산 → 추가 지연
```

---

## 4. 예측 실패 패널티

```
파이프라인 깊이와 패널티:
10단계 파이프라인: 패널티 ~10 사이클
20단계 파이프라인: 패널티 ~15 사이클

Intel Pentium 4 (31단계): 패널티 ~25 사이클
→ 예측 실패가 너무 비쌈 → 실제 성능 저하의 큰 원인
```

## 5. 프로그래머 관점에서의 분기 예측

### 5.1 분기 예측이 어려운 코드

```c
// 무작위 데이터의 조건부 합산 → 예측 불가능
long sum = 0;
for (int i = 0; i < N; i++) {
    if (arr[i] > threshold) {  // 50% 확률 → 최악의 예측률
        sum += arr[i];
    }
}
```

### 5.2 분기를 줄이는 최적화

```c
// 분기 없이 CMOV(조건부 이동)으로 구현
long sum = 0;
for (int i = 0; i < N; i++) {
    sum += (arr[i] > threshold) ? arr[i] : 0;
    // 컴파일러가 cmovg 등으로 최적화 가능
}
```

### 5.3 데이터 정렬로 예측률 향상

```c
// 무작위 배열: 예측 실패율 ~50%
qsort(arr, N, sizeof(int), cmp);  // 정렬 후

// 정렬된 배열: 처음엔 threshold 이하만 → 나중엔 이상만
// 예측 실패는 threshold 근처 한 번뿐
for (int i = 0; i < N; i++) {
    if (arr[i] > threshold) {
        sum += arr[i];
    }
}
// 정렬 후 약 3~4배 빠름 (분기 예측 성공률 향상)
```

### 5.4 힌트 제공 (GCC likely/unlikely)

```c
// 거의 항상 true인 조건
if (__builtin_expect(ptr != NULL, 1)) {  // likely true
    *ptr = 42;
}

// 거의 항상 false인 에러 처리
if (__builtin_expect(err != 0, 0)) {  // unlikely true
    handle_error();
}

// C++ 20
if [[likely]] (x > 0) { ... }
if [[unlikely]] (err) { ... }
```

## 핵심 요약

- **분기 예측**: 파이프라인이 분기 결과를 알기 전에 경로를 미리 예측하고 실행.
- **2-bit 포화 카운터**: 가장 기본적인 예측기. 패턴 학습.
- **예측 실패 패널티**: 현대 CPU에서 10~20 사이클 낭비.
- **현대 예측기(TAGE)**: 99%+ 정확도. Spectre 취약점의 원인.
- **프로그래머 최적화**: 데이터 정렬, CMOV 활용, `__builtin_expect` 힌트.
