## 비순차적 실행 (Out-of-Order Execution, OOO)

현대 고성능 CPU는 명령어를 **프로그램 순서대로 실행하지 않습니다**. 데이터 의존성이 없는 명령어는 순서를 바꿔 실행할 수 있습니다. 이를 통해 파이프라인 스톨을 숨기고 IPC를 극대화합니다.

---

## 1. 비순차적 실행의 필요성

```c
long a = *ptr1;   // I1: 메모리 로드 (200 사이클 지연 가능)
long b = a + 1;   // I2: I1에 의존 → 기다려야 함
long c = x * y;   // I3: I1, I2와 독립 → 기다릴 이유 없음!
long d = c * 2;   // I4: I3에 의존
```

순차 실행:
```
I1: [F][D][E][M200사이클 대기...][W]
I2: 기다리는 중...
I3: 기다리는 중...
I4: 기다리는 중...
```

비순차 실행:
```
I1: [F][D][E][M200사이클 대기...][W]
I3:         [E][W]  ← I1 대기 동안 실행!
I4:                 [E][W]
I2:                         [E][W]  ← I1 완료 후 실행
```

## 2. OOO CPU의 핵심 구조

```
┌─────────────────────────────────────────────────────────┐
│                         CPU                              │
│  ┌──────┐  ┌──────────┐  ┌───────────────────────────┐ │
│  │Fetch │→ │ Decode   │→ │      OOO Engine            │ │
│  │      │  │(μop 분해)│  │                           │ │
│  └──────┘  └──────────┘  │  ┌───────────────────┐    │ │
│                           │  │ Instruction Queue  │    │ │
│                           │  │  (ROB/RS)          │    │ │
│                           │  └────────┬──────────┘    │ │
│                           │           │ (Ready 명령어) │ │
│                           │  ┌────────▼──────────┐    │ │
│                           │  │  실행 유닛 (병렬)  │    │ │
│                           │  │ [ALU][ALU][FPU]   │    │ │
│                           │  │ [AGU][MUL][DIV]   │    │ │
│                           │  └────────────────────┘    │ │
│                           │  ┌────────────────────┐    │ │
│                           │  │  ROB (Reorder Buffer│    │ │
│                           │  │  순서대로 커밋)     │    │ │
│                           │  └────────────────────┘    │ │
│                           └───────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 핵심 구성 요소

**ROB (Reorder Buffer)**: 명령어를 프로그램 순서대로 나열. 실행 완료 후 **순서대로 커밋(Commit)**하여 프로그램 의미 보존.

**RS (Reservation Station / Issue Queue)**: 실행 준비가 된 명령어를 기다리는 대기실. 피연산자가 준비되면 즉시 실행 유닛으로 디스패치.

**레지스터 리네이밍 (Register Renaming)**: WAR, WAW 해저드를 제거하기 위해 논리 레지스터를 물리 레지스터로 매핑.

---

## 3. 레지스터 리네이밍

```asm
# WAR 해저드 예시
I1: movq %rax, %rbx    # rbx = rax 읽기 (RAW: rbx에 쓰기 전에 rax를 읽어야)
I2: addq $1, %rax      # rax에 쓰기 (WAR: I1이 읽기 전에 쓰면 안 됨)

# 리네이밍 후:
I1: movq p1, p2        # p1(구 rax), p2(새 rbx)
I2: addq $1, p3        # p3(새 rax) ← I1과 완전히 독립!
```

x86-64는 16개의 논리 레지스터를 수백 개의 **물리 레지스터(Physical Register File)**에 매핑합니다.

## 4. 투기적 실행 (Speculative Execution)

분기 예측과 결합하여, CPU는 분기 결과가 확정되기 전에 **예측된 경로의 명령어를 실행**합니다.

```
분기 예측: if (x > 0) { A } else { B }
CPU가 "x > 0"을 true로 예측

실행:
  분기 실행 → 결과 확인 중
  동시에: A 블록의 명령어들을 ROB에 투기적으로 실행

예측 맞으면: A 블록의 결과를 커밋 (아무 일 없었던 것처럼)
예측 틀리면: A 블록의 모든 결과를 버리고 B 블록 실행
```

### 투기적 실행의 제약

ROB에서 **커밋(Commit)** 되기 전까지:
- 레지스터 쓰기: 물리 레지스터에만 (아직 아키텍처 상태에 반영 X)
- 메모리 쓰기: 스토어 버퍼에만 (D-Cache에 아직 기록 X)

예측 실패 시 이 모든 것을 롤백(Rollback)합니다.

---

## 5. 비순차 실행의 성능 이점

```
메모리 레이턴시 숨기기 (Memory Latency Hiding):
  L1 캐시 미스 (100 사이클 지연):
  → 100 사이클 동안 독립적인 다른 명령어 실행 가능
  → 유효 메모리 지연 ≈ 0 사이클 (다른 작업으로 채움)

결과:
순차 실행 IPC: ~0.5 (메모리 지연으로)
OOO 실행 IPC: ~2.5 (지연을 숨김)
→ 5배 성능 향상!
```

## 6. OOO와 메모리 일관성

```c
// Thread 1          // Thread 2
x = 1;               y = 1;
int r1 = y;          int r2 = x;
```

OOO 실행으로 Thread 1이 `y`를 먼저 읽고 `x`를 나중에 쓸 수 있습니다. Thread 2도 마찬가지. 결과적으로 `r1 = 0, r2 = 0`이 가능합니다 (직관에 반함).

이런 상황을 **메모리 재순서화(Memory Reordering)**라 합니다. `mfence`, `lock` 접두사, `atomic` 등이 이를 막기 위해 존재합니다.

---

## 핵심 요약

- **OOO 실행**: 데이터 의존성 없는 명령어를 순서와 무관하게 실행. 메모리 지연을 숨김.
- **ROB**: 비순차 실행하되 **순서대로 커밋**하여 프로그램 정확성 보장.
- **레지스터 리네이밍**: WAR, WAW 해저드 제거. 논리→물리 레지스터 매핑.
- **투기적 실행**: 분기 결과 전에 예측 경로 실행. 맞으면 커밋, 틀리면 롤백.
- **메모리 재순서화**: OOO의 부작용. 멀티스레드 코드에서 메모리 펜스 필요.
