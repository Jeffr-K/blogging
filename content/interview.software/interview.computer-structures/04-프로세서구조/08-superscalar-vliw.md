## 명령어 수준 병렬성 (ILP)

하나의 프로그램 내에서 동시에 실행할 수 있는 명령어들이 존재합니다. 이를 **명령어 수준 병렬성(ILP, Instruction-Level Parallelism)**이라 합니다. 슈퍼스칼라와 VLIW는 ILP를 활용하는 두 가지 다른 접근법입니다.

---

## 1. 슈퍼스칼라 (Superscalar)

### 1.1 개념

슈퍼스칼라는 **한 사이클에 여러 명령어를 발행(Issue)하는** 구조입니다. 여러 실행 유닛을 병렬로 두고, 하드웨어가 자동으로 독립적인 명령어를 찾아 병렬 실행합니다.

```
4-wide 슈퍼스칼라:

사이클 1: [I1][I2][I3][I4] → 한 번에 4개 명령어 인출/발행
           ↓    ↓    ↓    ↓
         [ALU1][ALU2][FPU][AGU] (병렬 실행 유닛)
```

### 1.2 IPC (Instructions Per Cycle)

```
1-wide (스칼라): IPC ≤ 1
2-wide 슈퍼스칼라: IPC ≤ 2
4-wide 슈퍼스칼라: IPC ≤ 4 (이론적)

실제 IPC (데이터 의존성, 해저드로):
Intel Core i7 (4-wide): 실측 IPC ≈ 2~3
```

### 1.3 현대 CPU 사양

```
Intel Core i9 (Alder Lake, 2021):
- 6-wide 슈퍼스칼라 (6개 명령어/사이클 발행)
- 실행 유닛: ALU×4, AGU×3, FPU×2, Branch×1 등

AMD Ryzen (Zen 4, 2022):
- 6-wide 슈퍼스칼라
- 비순차 실행 윈도우: 320개 μops

Apple M4 (2024):
- 10-wide 슈퍼스칼라 (단일 코어 최강 IPC)
```

### 1.4 슈퍼스칼라의 병목: ILP 한계

```
ILP 추출 한계 (Wall's Law):
아무리 넓은 슈퍼스칼라도 실제 코드에서 IPC = 5 이상 달성 어려움
이유:
1. 데이터 의존성 (True Dependencies)
2. 제어 흐름 분기 (분기 예측 실패)
3. 메모리 레이턴시
```

## 2. VLIW (Very Long Instruction Word)

### 2.1 개념

슈퍼스칼라는 **하드웨어**가 런타임에 병렬성을 찾습니다. VLIW는 **컴파일러**가 컴파일 시점에 병렬성을 찾아 **여러 연산을 하나의 긴 명령어(번들)에 패키징**합니다.

```
VLIW 명령어 (128비트 예시):
[ALU 연산 | FPU 연산 | 메모리 연산 | 분기 연산]
  32비트      32비트      32비트       32비트

하드웨어는 단순히 각 슬롯의 연산을 병렬로 실행
→ 하드웨어 복잡도 감소, 클럭 주파수 향상 기대
```

### 2.2 VLIW의 장점

```
1. 하드웨어 단순화: OOO 엔진, ROB 불필요
2. 소비 전력 감소: 복잡한 하드웨어 없음
3. 빠른 결정적(Deterministic) 실행 시간: 임베디드/실시간 시스템에 적합
```

### 2.3 VLIW의 단점

```
1. 컴파일러 복잡도 극단적으로 높음
   - 컴파일러가 런타임 정보(캐시 미스, 분기 실패) 없이 최적화
   - NOP으로 슬롯을 채워야 하는 경우 공간 낭비

2. 이진 호환성(Binary Compatibility) 문제
   - 새 아키텍처(실행 유닛 수 변경)에서 기존 바이너리 실행 불가
   - 재컴파일 필요

3. 캐시 미스 처리 어려움
   - 메모리 레이턴시가 가변적 → 컴파일 타임에 스케줄 어려움
```

### 2.4 VLIW 사용 사례

```
Intel Itanium (IA-64): 가장 유명한 VLIW 아키텍처
  - 3개 연산/명령어 번들, 128비트
  - 2001년~2017년 서버 시장 타겟
  - 컴파일러 최적화 어려움으로 실패
  - x86의 OOO 성능에 패배

DSP (Digital Signal Processor):
  - TI C6000 시리즈: 8개 연산/사이클
  - 오디오, 이미지 처리 등 예측 가능한 워크로드

GPU Shader 프로세서:
  - VLIW 유사 구조 사용
  - AMD GCN 이전 구조
```

## 3. 슈퍼스칼라 vs VLIW 비교

| 특성 | 슈퍼스칼라 | VLIW |
|------|-----------|------|
| 병렬성 탐지 | 하드웨어 (런타임) | 컴파일러 (컴파일 타임) |
| 하드웨어 복잡도 | 높음 (ROB, OOO) | 낮음 |
| 소비 전력 | 높음 | 낮음 |
| 컴파일러 복잡도 | 낮음 | 매우 높음 |
| 이진 호환성 | 높음 | 낮음 |
| 예측 실행 | 쉬움 (하드웨어 지원) | 어려움 |
| 대표 | x86, ARM | Itanium, DSP |

## 4. SIMD (Single Instruction, Multiple Data)

슈퍼스칼라와 별개로, **하나의 명령어로 여러 데이터를 동시에 처리**하는 SIMD도 ILP를 활용합니다.

```c
// 일반: 4번의 add 명령어
a[0] += b[0];  a[1] += b[1];  a[2] += b[2];  a[3] += b[3];

// SSE (128비트): 1번의 addps 명령어로 4개 float 동시 처리
__m128 va = _mm_load_ps(a);
__m128 vb = _mm_load_ps(b);
__m128 vc = _mm_add_ps(va, vb);  // 4개 float을 한 번에
_mm_store_ps(a, vc);

// AVX-512: 1번으로 16개 float 동시 처리
```

## 핵심 요약

- **슈퍼스칼라**: 한 사이클에 여러 명령어 발행. 하드웨어가 독립 명령어를 찾아 병렬 실행. IPC > 1 가능.
- **VLIW**: 컴파일러가 미리 병렬성 발견하여 긴 명령어로 패키징. 하드웨어 단순. 하지만 컴파일러 복잡도와 호환성 문제로 범용 CPU에서는 실패.
- **현대 CPU**: 넓은 슈퍼스칼라(6~10-wide) + OOO + 투기적 실행 조합.
- **IPC 한계**: 실제 코드의 ILP 한계로 슈퍼스칼라를 아무리 넓게 해도 IPC = 5~6 수준에서 포화.
