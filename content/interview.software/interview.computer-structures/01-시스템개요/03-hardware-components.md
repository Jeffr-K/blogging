## 하드웨어 구성 요소

소프트웨어가 실행되는 물리적 기반을 이해하면, 성능과 병목의 원인을 훨씬 명확하게 파악할 수 있습니다. 현대 컴퓨터의 하드웨어는 크게 **프로세서(CPU)**, **메인 메모리(DRAM)**, **I/O 디바이스**, **버스(Bus)**로 구성됩니다.

---

## 1. 버스 (Bus)

버스는 컴포넌트 간에 데이터를 전달하는 **전기 신호선의 집합**입니다.

```
CPU ←───── 시스템 버스 ─────→ 메모리 버스 ←───→ 메인 메모리(DRAM)
 │                                ↑
 └──── I/O 버스 ──→ I/O 브리지 ───┘
              ↓
     [USB] [디스크 컨트롤러] [그래픽 카드]
```

### 버스의 종류

| 버스 종류 | 역할 | 대역폭 |
|----------|------|--------|
| 시스템 버스 (FSB) | CPU ↔ 메모리 브리지 | 수십 GB/s |
| 메모리 버스 | 메모리 컨트롤러 ↔ DRAM | 수십~수백 GB/s |
| I/O 버스 (PCIe) | CPU ↔ GPU, NVMe SSD | PCIe 4.0 x16: ~32 GB/s |
| USB | 주변장치 연결 | USB 3.2: 최대 2 GB/s |

**버스 폭(Bus Width)**: 한 번에 전송할 수 있는 비트 수. 64비트 시스템에서 메모리 버스는 64비트(8바이트)씩 데이터를 전송합니다.

**버스 클럭(Bus Clock)**: 버스가 데이터를 전송하는 주파수. CPU 클럭보다 훨씬 낮습니다.

---

## 2. 메인 메모리 (Main Memory / DRAM)

CPU가 프로그램을 실행할 때 코드와 데이터를 임시 저장하는 공간입니다.

### DRAM의 특성

- **Dynamic RAM**: 커패시터(Capacitor)에 전하를 저장. 주기적인 리프레시(Refresh) 필요.
- **휘발성(Volatile)**: 전원이 끊기면 데이터 소실.
- **랜덤 접근(Random Access)**: 임의의 주소에 동일한 시간에 접근 가능.

### 메인 메모리의 논리적 구조

메모리는 바이트 배열로 볼 수 있습니다. 각 바이트는 0부터 시작하는 주소(Address)를 가집니다.

```
주소:  0x0000  0x0001  0x0002  0x0003  ...  0xFFFF
데이터: [0x48]  [0x65]  [0x6C]  [0x6C]  ...
```

64비트 CPU는 이론적으로 2⁶⁴ = 16 엑사바이트(EB)의 주소 공간을 가지지만, 실제로는 물리 메모리 크기에 제한됩니다.

## 3. 프로세서 (CPU)

CPU(Central Processing Unit)는 메모리에서 명령어를 읽어 실행하는 엔진입니다.

### 3.1 CPU의 핵심 구성 요소

```
┌───────────────────────────────┐
│              CPU              │
│  ┌─────────┐  ┌────────────┐  │
│  │레지스터  │  │    ALU     │  │
│  │(PC, IR, │  │(산술/논리  │  │
│  │ GPR...) │  │  연산장치) │  │
│  └─────────┘  └────────────┘  │
│  ┌─────────────────────────┐  │
│  │   제어 장치 (Control Unit)│  │
│  └─────────────────────────┘  │
│  ┌─────────────────────────┐  │
│  │   캐시 (L1/L2/L3)       │  │
│  └─────────────────────────┘  │
└───────────────────────────────┘
```

**레지스터(Register)**: CPU 내부의 초고속 저장 공간. x86-64는 16개의 범용 레지스터(rax, rbx, rcx, rdx, rsi, rdi, rsp, rbp, r8~r15).

**PC (Program Counter)**: 다음 실행할 명령어의 메모리 주소를 가리킵니다.

**ALU (Arithmetic Logic Unit)**: 덧셈, 뺄셈, AND, OR 등 실제 연산을 수행합니다.

**제어 장치(Control Unit)**: 명령어를 해석하고 ALU, 메모리, 레지스터에 제어 신호를 보냅니다.

### 3.2 명령어 실행 사이클

```
Fetch → Decode → Execute → Write-back → (반복)
  ↑                                         |
  └─────────────────────────────────────────┘
```

1. **Fetch**: PC가 가리키는 주소에서 명령어를 메모리에서 가져옴
2. **Decode**: 명령어 해석 (어떤 연산? 어떤 피연산자?)
3. **Execute**: ALU가 연산 수행
4. **Write-back**: 결과를 레지스터나 메모리에 저장
5. **PC 증가**: 다음 명령어 주소로 이동

## 4. I/O 디바이스

I/O 디바이스는 컴퓨터와 외부 세계를 연결합니다.

### 주요 I/O 디바이스와 속도 비교

```
레지스터           ~1 사이클       (< 1ns)
L1 캐시            ~4 사이클       (~1ns)
L2 캐시            ~12 사이클      (~4ns)
L3 캐시            ~40 사이클      (~15ns)
메인 메모리(DRAM)  ~200 사이클     (~60ns)
NVMe SSD          ~100,000 사이클  (~30μs)
SATA SSD          ~500,000 사이클  (~150μs)
HDD               ~10,000,000 사이클 (~3ms)
네트워크(LAN)     ~수십ms
```

이 속도 차이가 **메모리 계층 구조**와 **캐시**가 필요한 근본적인 이유입니다.

### I/O 디바이스와 CPU의 소통 방법

**메모리 맵 I/O(Memory-Mapped I/O)**: 디바이스 레지스터를 메모리 주소 공간의 일부에 매핑. CPU가 특정 주소에 읽기/쓰기하면 디바이스를 제어.

**DMA(Direct Memory Access)**: CPU가 아닌 DMA 컨트롤러가 직접 메모리와 디바이스 간 데이터를 전송. CPU는 전송 시작과 완료 인터럽트만 처리.

---

## 5. 전체 데이터 흐름 예시

`printf("Hello")` 실행 시 데이터 흐름:

```
1. CPU가 메모리에서 printf 명령어 Fetch
2. "Hello" 문자열이 메모리에 있음
3. printf 시스템 콜 → 커널 모드로 전환
4. 커널이 I/O 버스를 통해 디스플레이 컨트롤러에 데이터 전송
5. 디스플레이 컨트롤러가 화면에 "Hello" 출력
```

---

## 핵심 요약

- **버스**: 컴포넌트 간 데이터 고속도로. 폭과 클럭이 대역폭 결정.
- **메인 메모리(DRAM)**: 실행 중 코드와 데이터를 저장. 휘발성.
- **CPU**: Fetch-Decode-Execute-Writeback 사이클로 명령어 실행.
- **I/O 디바이스**: 레지스터에서 HDD까지 속도 차이가 수백만 배. 이 차이가 캐시의 존재 이유.
