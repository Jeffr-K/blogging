## Amdahl의 법칙

1967년 IBM 엔지니어 Gene Amdahl이 제안한 법칙으로, **시스템 일부를 개선했을 때 전체 성능이 얼마나 향상되는지**를 수식으로 표현합니다. 병렬 프로그래밍, 하드웨어 최적화, 시스템 설계 모두에 적용되는 핵심 원리입니다.

---

## 1. 공식

```
Speedup = 1 / ((1 - p) + p/s)

p = 개선 가능한 부분의 비율 (0 ~ 1)
s = 해당 부분의 속도 향상 배수
```

**직관적 해석**: 전체 작업에서 개선 불가능한 부분 `(1 - p)`가 존재하면, 개선 가능한 부분 `p`를 아무리 빠르게 해도 전체 성능은 `1 / (1 - p)` 이상 좋아질 수 없습니다.

---

## 2. 예제 계산

### 2.1 기본 예제

어떤 작업의 60%가 병렬화 가능하고, 나머지 40%는 순차 실행이 불가피하다고 합시다.

```
병렬화 가능 부분: p = 0.6
CPU 코어 수: s = 4개 → 병렬 부분이 4배 빨라짐

Speedup = 1 / ((1 - 0.6) + 0.6/4)
        = 1 / (0.4 + 0.15)
        = 1 / 0.55
        ≈ 1.82배
```

4배 빠른 병렬 처리를 추가해도 전체 속도는 고작 **1.82배** 향상됩니다.

### 2.2 코어를 무한히 늘리면?

```
s → ∞ (무한히 많은 코어):
Speedup = 1 / (1 - p)

p = 0.6: 최대 Speedup = 1 / 0.4 = 2.5배
p = 0.9: 최대 Speedup = 1 / 0.1 = 10배
p = 0.99: 최대 Speedup = 1 / 0.01 = 100배
```

### 2.3 시각적 이해

```
순차 부분(40%)이 병목:

CPU 1개:  [===순차===][=====병렬=====]  → 100%
CPU 4개:  [===순차===][==병렬==]         → 55%의 시간 (1.82배)
CPU ∞개:  [===순차===][]                → 40%의 시간 (2.5배)

아무리 병렬화해도 순차 부분(40%) 이하로는 불가능!
```

## 3. 구체적 시나리오별 분석

### 3.1 웹 서버 최적화

```
전체 요청 처리 시간 구성:
- DB 쿼리: 70% (개선 가능)
- 직렬 처리 (락 획득 등): 30% (개선 불가능)

DB를 10배 빠른 것으로 교체하면:
Speedup = 1 / (0.3 + 0.7/10)
        = 1 / (0.3 + 0.07)
        = 1 / 0.37
        ≈ 2.7배
```

**교훈**: DB를 10배 빠르게 해도 전체는 2.7배 빠릅니다. 순차 30%가 병목.

### 3.2 멀티코어 CPU 성능

```
프로그램의 95%가 병렬화 가능한 경우:

2코어:   1/(0.05 + 0.95/2)   = 1.90배
4코어:   1/(0.05 + 0.95/4)   = 3.48배
8코어:   1/(0.05 + 0.95/8)   = 5.93배
16코어:  1/(0.05 + 0.95/16)  = 9.14배
32코어:  1/(0.05 + 0.95/32)  = 12.4배
∞코어:   1/0.05              = 20배 (이론적 한계)
```

코어를 2배씩 늘려도 성능 향상은 점점 줄어듭니다.

---

## 4. 역 Amdahl 법칙 (Gustafson's Law)

Amdahl의 법칙은 **고정된 문제 크기**를 전제로 합니다. 하지만 실제로는 더 많은 코어를 추가하면 **더 큰 문제를 풀 수 있습니다**.

Gustafson(1988)은 이 관점을 제시합니다:

```
코어가 많으면 → 동일 시간에 더 큰 문제 해결 가능
             → 병렬 부분이 더 커지는 효과
```

예를 들어, 기상 예측 모델에서 코어를 늘리면 해상도를 높여 더 정밀한 예측이 가능합니다. 문제 크기 자체가 스케일됩니다.

## 5. 실무 적용

### 5.1 최적화 우선순위 결정

```
최적화 전 프로파일링 결과:
함수 A: 실행 시간 50% 차지
함수 B: 실행 시간 30% 차지
함수 C: 실행 시간 20% 차지

함수 C를 10배 빠르게 최적화해도:
Speedup = 1 / (0.8 + 0.2/10) = 1 / 0.82 ≈ 1.22배

함수 A를 2배 빠르게 최적화하면:
Speedup = 1 / (0.5 + 0.5/2) = 1 / 0.75 ≈ 1.33배
```

**작은 부분을 극적으로 최적화하는 것보다, 큰 부분을 조금 최적화하는 것이 더 효과적**입니다.

### 5.2 마이크로서비스 분산 시스템

```
마이크로서비스 A: 200ms
마이크로서비스 B: 50ms  ← 아무리 최적화해도 효과 미미
마이크로서비스 C: 10ms

전체 응답시간을 줄이려면 A를 최적화해야 함
```

### 5.3 공식 기억법

```
병목이 있는 한, 아무리 나머지를 빠르게 해도 한계가 있다.
→ "병목을 찾아라(Find the bottleneck)"
→ "측정 없이는 최적화 없다(No optimization without profiling)"
```

## 핵심 요약

- **Amdahl의 법칙**: 전체 성능 향상은 순차(개선 불가능) 부분에 의해 제한됩니다.
- **공식**: `Speedup = 1 / ((1-p) + p/s)`
- **교훈 1**: 성능 개선 전에 **병목(bottleneck)**을 먼저 찾아야 합니다. 프로파일링이 필수.
- **교훈 2**: 작은 부분의 극적 최적화보다 큰 부분의 소폭 최적화가 더 효과적입니다.
- **교훈 3**: 코어를 무한히 늘려도 순차 부분이 전체 성능의 상한선을 결정합니다.
