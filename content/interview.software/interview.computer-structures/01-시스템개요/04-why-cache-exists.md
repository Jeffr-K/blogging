## 캐시가 존재하는 이유

현대 컴퓨터에서 CPU는 클럭당 수십억 개의 연산을 수행할 수 있지만, 메인 메모리(DRAM)에서 데이터를 가져오는 데는 수백 사이클이 걸립니다. 이 **속도 간격(Speed Gap)**이 캐시가 탄생한 근본적인 이유입니다.

---

## 1. 속도 간격 (The Speed Gap)

### 1.1 역사적 관점

1980년대 이후 CPU와 메모리의 성능 향상 속도가 달라졌습니다.

```
성능 향상 속도 (연간):
CPU: ~55% 향상 (무어의 법칙 + 마이크로아키텍처 혁신)
DRAM: ~7% 향상 (물리적 한계)

결과: CPU와 메모리 간 속도 격차가 매년 벌어짐
1980년: CPU가 DRAM보다 약 1배 빠름
2000년대: CPU가 DRAM보다 약 100~200배 빠름
```

### 1.2 현재 수치

```
CPU 레지스터 접근:   1 사이클    (0.3ns @ 3GHz)
L1 캐시 접근:        4 사이클    (~1.2ns)
L2 캐시 접근:       12 사이클    (~4ns)
L3 캐시 접근:       40 사이클    (~13ns)
메인 메모리 접근:   200 사이클   (~60ns)
```

CPU가 메모리에서 데이터를 기다리는 동안 **수백 개의 연산을 그냥 낭비**하는 셈입니다. 이 시간을 **메모리 레이턴시(Memory Latency)**라 합니다.

---

## 2. 해결책: 캐시 메모리

캐시는 CPU와 메인 메모리 사이에 위치한 **소용량 고속 메모리**입니다. SRAM(Static RAM)으로 구현되어 DRAM보다 훨씬 빠르지만, 가격이 비싸서 용량이 작습니다.

```
┌────────┐    ┌──────┐    ┌──────┐    ┌──────┐    ┌──────────┐
│  CPU   │───→│  L1  │───→│  L2  │───→│  L3  │───→│  DRAM    │
│        │    │ 32KB │    │256KB │    │  8MB │    │  16GB    │
└────────┘    │ 1ns  │    │ 4ns  │    │ 13ns │    │  60ns    │
              └──────┘    └──────┘    └──────┘    └──────────┘
              (빠름, 작음) ←────────────────────→ (느림, 큼)
```

---

## 3. 캐시가 효과적인 이유: 지역성 (Locality)

캐시가 효과를 발휘하는 이유는 **지역성(Locality)의 원리** 덕분입니다. 프로그램은 데이터를 균등하게 사용하지 않고, 특정 데이터를 집중적으로 사용하는 경향이 있습니다.

### 3.1 시간 지역성 (Temporal Locality)

최근에 접근한 데이터는 **가까운 미래에 다시 접근**될 가능성이 높습니다.

```c
// 루프 변수 i는 반복마다 접근됨 → 시간 지역성 높음
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += arr[i];  // sum과 i는 매 반복 접근
}
```

`sum`과 `i`는 캐시에 올려두면 계속 재사용됩니다.

### 3.2 공간 지역성 (Spatial Locality)

특정 주소를 접근하면 **인접한 주소도 곧 접근**될 가능성이 높습니다.

```c
// arr[0], arr[1], arr[2]... 순서대로 접근 → 공간 지역성 높음
for (int i = 0; i < n; i++) {
    sum += arr[i];  // 배열은 연속 메모리 → 다음 원소도 캐시에 있음
}
```

캐시는 데이터를 **캐시 라인(Cache Line)** 단위(보통 64바이트)로 가져오기 때문에, `arr[0]`을 가져올 때 `arr[1]`~`arr[15]`도 함께 캐시에 올라옵니다.

## 4. 캐시 히트와 캐시 미스

**캐시 히트(Cache Hit)**: 요청한 데이터가 캐시에 있을 때. 빠름.  
**캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없을 때. 메인 메모리에서 가져옴. 느림.

### 실제 영향: 행 우선 vs 열 우선 접근

```c
// 방법 1: 행 우선 (Row-Major) 접근 → 공간 지역성 좋음
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += A[i][j];   // A[0][0], A[0][1], A[0][2] ... 연속 접근

// 방법 2: 열 우선 (Column-Major) 접근 → 캐시 미스 폭발
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += A[j][i];   // A[0][0], A[1][0], A[2][0] ... 비연속 접근
```

C언어에서 2차원 배열은 **행 우선**으로 저장됩니다. 열 우선 접근은 캐시 라인을 비효율적으로 사용하여 대규모 행렬에서 **수십 배 느릴 수 있습니다**.

```
N=4096 행렬 기준 (실제 측정):
행 우선: ~50ms
열 우선: ~500ms (약 10배 느림)
```

## 5. 캐시 적중률 (Hit Rate)

캐시 적중률이 성능에 미치는 영향은 매우 큽니다.

```
평균 접근 시간 = 히트율 × L1 시간 + (1-히트율) × 메모리 시간

히트율 99%:  0.99×1 + 0.01×200 = 0.99 + 2.0  = 2.99 사이클
히트율 97%:  0.97×1 + 0.03×200 = 0.97 + 6.0  = 6.97 사이클  (2.3배 느림!)
히트율 90%:  0.90×1 + 0.10×200 = 0.90 + 20.0 = 20.9 사이클  (7배 느림!)
```

히트율 2% 하락이 성능을 2배 이상 저하시킵니다. 캐시 적중률이 얼마나 중요한지 알 수 있습니다.

---

## 6. SRAM vs DRAM 비교

| 특성 | SRAM (캐시) | DRAM (메모리) |
|------|------------|--------------|
| 구현 방식 | 플립플롭(6 트랜지스터) | 커패시터(1 트랜지스터) |
| 속도 | ~1ns | ~60ns |
| 용량 | 수 KB ~ 수십 MB | 수 GB ~ 수백 GB |
| 가격 (GB당) | 매우 비쌈 | 저렴 |
| 리프레시 필요 | 불필요 | 필요 |
| 소비 전력 | 낮음 | 상대적으로 높음 |

---

## 핵심 요약

- **속도 간격**: CPU는 DRAM보다 200배 빠릅니다. 이 격차가 캐시의 존재 이유입니다.
- **캐시**: CPU와 DRAM 사이의 소용량 고속(SRAM) 버퍼.
- **지역성**: 시간 지역성(재사용)과 공간 지역성(인접 접근)이 캐시를 효과적으로 만듭니다.
- **히트율**: 99%와 97%의 차이가 2배 성능 차이를 만들 수 있습니다. 캐시 친화적 코드가 중요합니다.
