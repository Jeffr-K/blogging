## 운영체제의 추상화

운영체제(OS)는 하드웨어 위에서 동작하며, 복잡한 하드웨어를 **단순하고 일관된 인터페이스**로 감싸줍니다. OS가 제공하는 세 가지 핵심 추상화는 **프로세스**, **가상 메모리**, **파일**입니다.

```
애플리케이션
    ↕ (시스템 콜)
┌──────────────────────────────┐
│         운영체제 (OS)         │
│  ┌────────┐ ┌────────────┐   │
│  │프로세스 │ │ 가상 메모리│   │
│  └────────┘ └────────────┘   │
│          ┌──────┐            │
│          │ 파일  │            │
│          └──────┘            │
└──────────────────────────────┘
    ↕ (하드웨어 인터페이스)
CPU + DRAM + 디스크 + 네트워크
```

---

## 1. 프로세스 (Process) — CPU의 추상화

### 1.1 프로세스란?

프로세스는 **실행 중인 프로그램의 추상화**입니다. 각 프로세스는 마치 자신이 CPU를 독점하고 있는 것처럼 동작합니다.

실제로는 OS의 **스케줄러(Scheduler)**가 여러 프로세스를 매우 빠르게 번갈아 실행합니다(보통 수 ms 단위). 이를 **시분할(Time-Sharing)**이라 합니다.

### 1.2 문맥 교환 (Context Switch)

OS가 한 프로세스에서 다른 프로세스로 전환할 때 발생합니다.

```
프로세스 A 실행
    → OS가 A의 상태(레지스터, PC) 저장 → PCB(Process Control Block)
    → OS가 B의 상태를 PCB에서 복원
프로세스 B 실행
    → OS가 B의 상태 저장
    → OS가 A의 상태 복원
프로세스 A 실행 (이어서)
```

**PCB(Process Control Block)**에 저장되는 정보:
- 프로그램 카운터(PC)
- CPU 레지스터 값
- 메모리 맵 정보
- 열린 파일 목록
- 우선순위, 프로세스 상태

### 1.3 프로세스가 보는 세계

```
프로세스가 인식하는 시스템:
  - CPU: 나만 쓰는 전용 CPU
  - 메모리: 0부터 시작하는 연속적인 주소 공간
  - 파일: 번호(FD)로 접근하는 I/O 추상화
```

## 2. 가상 메모리 (Virtual Memory) — 메모리의 추상화

### 2.1 가상 메모리란?

각 프로세스에게 **독립적인 메모리 주소 공간**을 제공합니다. 프로세스는 자신이 전체 메모리를 독점하는 것처럼 생각합니다.

```
프로세스 A의 가상 주소 공간:
┌──────────────────┐ ← 0xFFFFFFFFFFFFFFFF (최상위)
│   커널 공간       │ ← OS 코드, 데이터
├──────────────────┤ ← 0x7FFFFFFF (보통)
│   스택 (Stack)   │ ↓ (아래로 성장)
├──────────────────┤
│      ...         │ (미사용)
├──────────────────┤
│   힙 (Heap)      │ ↑ (위로 성장)
├──────────────────┤
│ BSS (초기화 안됨) │
├──────────────────┤
│ DATA (초기화됨)   │
├──────────────────┤
│ TEXT (코드)       │
└──────────────────┘ ← 0x0000000000000000 (최하위)
```

### 2.2 가상 → 물리 주소 변환

OS와 CPU의 MMU(Memory Management Unit)가 협력하여 가상 주소를 물리 주소로 변환합니다.

```
프로세스 A: 가상 0x1000 → 물리 0xA000
프로세스 B: 가상 0x1000 → 물리 0xC000
```

같은 가상 주소라도 다른 물리 주소를 가리키므로, 프로세스 간 메모리 충돌이 원천적으로 불가능합니다.

### 2.3 가상 메모리의 이점

1. **격리(Isolation)**: 프로세스 A가 프로세스 B의 메모리에 접근 불가
2. **공유(Sharing)**: 동일한 라이브러리(libc.so)를 여러 프로세스가 물리 메모리 한 카피를 공유
3. **단순화**: 모든 프로세스가 동일한 가상 주소 레이아웃을 가짐 → 프로그래머 편의
4. **확장성**: 물리 메모리보다 큰 가상 주소 공간 사용 가능 (페이지 폴트 + 스왑)

## 3. 파일 (File) — I/O의 추상화

### 3.1 파일이란?

유닉스의 철학: **"모든 것은 파일이다(Everything is a file)"**

파일은 바이트의 시퀀스입니다. OS는 모든 I/O 디바이스를 파일로 추상화합니다.

| 실제 자원 | 파일 추상화 |
|----------|-----------|
| 디스크 파일 | `/home/user/data.txt` |
| 터미널 | `/dev/tty` |
| 네트워크 소켓 | `socket fd` |
| 파이프 | `pipe fd` |
| GPU 디바이스 | `/dev/nvidia0` |
| 프로세스 정보 | `/proc/1234/status` |

### 3.2 파일 디스크립터 (File Descriptor)

파일에 접근할 때 OS는 **정수형 핸들**인 파일 디스크립터(FD)를 반환합니다.

```c
// 표준 FD (프로세스 시작 시 자동으로 열림)
0: stdin  (표준 입력)
1: stdout (표준 출력)
2: stderr (표준 에러)

// 파일 열기
int fd = open("data.txt", O_RDONLY);  // fd = 3 (다음 사용 가능한 번호)

// 모든 I/O에 동일한 인터페이스
read(fd, buf, 100);   // 파일 읽기
read(0, buf, 100);    // 키보드 읽기 (stdin)
read(sockfd, buf, 100); // 네트워크 읽기

// 닫기
close(fd);
```

### 3.3 통합 추상화의 힘

파일 추상화 덕분에 아래와 같은 우아한 조합이 가능합니다.

```bash
# ls 명령의 출력을 grep 명령의 입력으로 연결
ls -la | grep ".txt"

# 내부적으로:
# ls의 stdout(FD 1) → 파이프 → grep의 stdin(FD 0)
# 두 프로그램은 서로 상대가 파이프인지, 터미널인지, 파일인지 모름
```

## 4. 세 가지 추상화의 관계

```
┌─────────────────────────────────────────────┐
│                  프로세스                    │
│  ┌────────────────────┐  ┌────────────────┐ │
│  │    가상 메모리      │  │  파일 디스크립터│ │
│  │ (코드, 데이터,      │  │  테이블         │ │
│  │  힙, 스택)         │  │  [0] stdin      │ │
│  │                   │  │  [1] stdout     │ │
│  │  가상주소 → 물리주소│  │  [2] stderr     │ │
│  └────────────────────┘  │  [3] data.txt   │ │
│                          └────────────────┘ │
└─────────────────────────────────────────────┘
```

프로세스 = 가상 메모리 주소 공간 + 파일 디스크립터 테이블 + 실행 상태

---

## 핵심 요약

- **프로세스**: CPU의 추상화. 시분할로 모든 프로세스가 CPU를 독점하는 환상을 제공.
- **가상 메모리**: 물리 메모리의 추상화. 프로세스 간 격리, 공유, 주소 공간 단순화.
- **파일**: I/O의 추상화. 디스크, 네트워크, 터미널 등 모든 것을 동일한 인터페이스로.
- 이 세 추상화가 현대 멀티태스킹 운영체제의 근간입니다.
