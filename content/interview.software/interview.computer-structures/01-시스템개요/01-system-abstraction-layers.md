## 컴퓨터 시스템의 추상화 계층

컴퓨터 시스템을 이해하는 핵심 열쇠는 **추상화(Abstraction)**입니다. 복잡한 하드웨어를 직접 다루지 않고도 애플리케이션을 만들 수 있는 이유는, 각 계층이 아래 계층의 복잡성을 감추고 단순한 인터페이스만 노출하기 때문입니다.

---

## 1. 추상화 계층 구조

컴퓨터 시스템은 아래에서 위로 쌓이는 계층 구조를 가집니다.

```
┌──────────────────────────────┐
│      애플리케이션 (Application) │  ← 우리가 작성하는 코드
├──────────────────────────────┤
│   알고리즘 / 자료구조           │  ← 문제 해결 전략
├──────────────────────────────┤
│   프로그래밍 언어 / 컴파일러     │  ← C, Java, Python
├──────────────────────────────┤
│   운영체제 (OS)               │  ← 프로세스, 파일, 가상 메모리
├──────────────────────────────┤
│   명령어 집합 구조 (ISA)        │  ← x86-64, ARM
├──────────────────────────────┤
│   마이크로아키텍처              │  ← 파이프라인, 캐시
├──────────────────────────────┤
│   디지털 논리 회로              │  ← 게이트, 플립플롭
├──────────────────────────────┤
│   트랜지스터 / 반도체           │  ← 물리 전자공학
└──────────────────────────────┘
```

각 계층은 **인터페이스(Interface)**를 통해 위 계층과 소통하고, 아래 계층의 구현 세부사항을 숨깁니다. 이를 **정보 은닉(Information Hiding)**이라 합니다.

---

## 2. 프로그래머가 주목해야 할 세 가지 추상화

CSAPP은 특히 프로그래머 관점에서 세 가지 핵심 추상화를 강조합니다.

### 2.1 파일(File) — I/O 디바이스의 추상화

키보드, 디스플레이, 디스크, 네트워크 소켓 등 모든 입출력 장치를 **파일**이라는 하나의 개념으로 추상화합니다.

```c
// 파일을 읽든, 소켓에서 읽든, 동일한 인터페이스
int fd = open("data.txt", O_RDONLY);  // 파일
int sock = socket(...);               // 네트워크 소켓

read(fd, buf, size);   // 동일한 read() 시스템 콜
read(sock, buf, size); // 동일한 인터페이스
```

유닉스의 "모든 것은 파일이다(Everything is a file)" 철학이 여기서 나옵니다.

### 2.2 가상 메모리(Virtual Memory) — 물리 메모리의 추상화

각 프로세스는 자신이 메모리 전체를 혼자 독점하는 것처럼 느낍니다. 실제로는 OS와 하드웨어(MMU)가 협력하여 가상 주소를 물리 주소로 변환합니다.

```
프로세스 A의 가상 주소 0x400000  →  물리 주소 0x1A2B000
프로세스 B의 가상 주소 0x400000  →  물리 주소 0x3C4D000
```

두 프로세스가 같은 가상 주소를 가지더라도 서로 다른 물리 메모리를 가리킵니다. 프로세스 간 격리가 자연스럽게 달성됩니다.

### 2.3 프로세스(Process) — CPU와 메모리의 추상화

프로세스는 "실행 중인 프로그램"의 추상화입니다. 각 프로세스는 마치 CPU를 혼자 점유하는 것처럼 실행되지만, 실제로 OS의 스케줄러가 CPU를 시분할(Time-Sharing)하여 여러 프로세스를 번갈아 실행합니다.

---

## 3. 왜 추상화 계층을 이해해야 하는가?

### 3.1 성능 문제의 근원을 찾기 위해

코드가 느린 이유는 종종 아래 계층에 있습니다.

- `List.contains()` 가 O(n)인 이유 → 자료구조 계층
- 네트워크 요청이 느린 이유 → OS I/O, TCP 스택
- 루프가 예상보다 느린 이유 → 캐시 미스 (마이크로아키텍처 계층)

### 3.2 계층 경계를 넘는 최적화

때로는 한 계층의 추상화를 뚫고 아래 계층에 직접 접근해야 최적화가 가능합니다.

```c
// 일반적인 파일 읽기 (버퍼링 있음)
FILE *f = fopen("data.bin", "rb");
fread(buf, 1, size, f);

// 직접 시스템 콜 (버퍼링 없음, 더 낮은 계층)
int fd = open("data.bin", O_RDONLY | O_DIRECT);
read(fd, buf, size);  // 커널 캐시를 우회
```

### 3.3 보안 취약점 이해

버퍼 오버플로우, Spectre/Meltdown 같은 취약점은 추상화 계층 사이의 경계가 무너질 때 발생합니다. 계층 구조를 이해해야 공격과 방어 모두 가능합니다.

---

## 4. 추상화의 비용 (Abstraction Cost)

추상화는 공짜가 아닙니다.

| 추상화 | 비용 |
|--------|------|
| 함수 호출 | 스택 프레임 생성, 레지스터 저장/복원 |
| 시스템 콜 | 유저 모드 → 커널 모드 전환 (~수백 ns) |
| 가상 메모리 | TLB 탐색, 페이지 테이블 워크 |
| 언어 런타임 | GC 오버헤드, JIT 컴파일 |

고성능 시스템(게임 엔진, DB 엔진, 운영체제)을 설계할 때는 이 비용을 항상 염두에 두어야 합니다.

---

## 핵심 요약

- 컴퓨터 시스템은 **하드웨어 → ISA → OS → 언어 → 애플리케이션** 순으로 쌓인 추상화 계층입니다.
- 프로그래머에게 중요한 세 가지 추상화는 **파일(I/O)**, **가상 메모리**, **프로세스(CPU)**입니다.
- 추상화는 복잡성을 숨기지만, **성능과 보안의 관점에서 계층 아래를 이해하는 능력**이 뛰어난 엔지니어를 만듭니다.
