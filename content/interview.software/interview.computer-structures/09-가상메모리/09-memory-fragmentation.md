## 메모리 단편화

메모리가 충분하지만 효율적으로 사용되지 못해 **낭비가 발생하는 현상**입니다.

---

## 1. 내부 단편화 (Internal Fragmentation)

```
정의: 할당된 블록 내부의 낭비 공간

발생 원인:
  ① 정렬 요구사항: malloc(1) → 16바이트 할당
  ② 헤더/풋터 오버헤드: 8~16바이트
  ③ 최소 블록 크기: 해제 블록에 prev/next 포인터 필요

예:
  malloc(1)  → 블록 크기 16바이트, 내부 낭비 15바이트 (94%)
  malloc(15) → 블록 크기 16바이트, 내부 낭비 1바이트 (6%)
  malloc(17) → 블록 크기 32바이트, 내부 낭비 15바이트 (47%)

측정:
  내부 단편화 = (할당된 블록 크기 합) - (요청 크기 합)
  
해결:
  → 최소 블록 크기 최소화 (포인터 압축 등)
  → 정렬 요구를 줄일 수 없음 (하드웨어 요구사항)
```

---

## 2. 외부 단편화 (External Fragmentation)

```
정의: 총 가용 메모리는 충분하지만 
      연속된 공간이 없어 할당 실패

예시:
  힙 상태:
  [할당 20B][해제 10B][할당 30B][해제 10B][할당 20B]
  
  총 가용: 20바이트
  malloc(15) → 실패! (연속된 15바이트 없음)

발생 조건:
  임의 순서로 malloc/free 반복 → 힙이 '스위스 치즈'처럼 구멍
  작은 해제 블록들이 흩어져 있음

해결 방법:
  ① 합병(Coalescing): 인접 해제 블록 즉시 합치기
  ② 더 나은 배치 정책: Best Fit
  ③ 분리 가용 리스트: 크기별 관리로 단편화 분산
```

---

## 3. 단편화 비교

```
내부 단편화 vs 외부 단편화:

          │ 내부 단편화        │ 외부 단편화
──────────┼────────────────────┼────────────────────
위치      │ 블록 내부          │ 블록들 사이
측정      │ 쉬움 (계산 가능)   │ 어려움 (미래 요청 패턴 의존)
해결책    │ 정렬 완화, 오버헤드 줄임 │ 합병, 압축, 좋은 배치
주요 원인 │ 정렬, 최소 크기    │ 임의 할당/해제 패턴
```

## 4. 메모리 압축 (Memory Compaction)

```
GC 언어에서 사용하는 외부 단편화 완전 해결법:

────────────────────────────
[A][_][B][_][_][C][_][D][_]   ← 단편화된 힙
────────────────────────────
      ↓ 압축 (Compaction)
────────────────────────────
[A][B][C][D][____________]    ← 연속된 가용 공간
────────────────────────────

필요 조건:
  모든 포인터를 업데이트 가능해야 함
  → C/C++에서는 불가능 (날 포인터)
  → Java, Python, Go 등 GC 언어에서 가능

단계:
  1. Mark: 살아있는 객체 표시
  2. Compact: 살아있는 객체를 한쪽으로 이동
  3. Update: 모든 포인터를 새 주소로 갱신
```

## 5. 단편화를 줄이는 할당 전략

```
크기 고정 할당기 (Slab Allocator):
  같은 크기 객체만 관리하는 전용 풀
  내부/외부 단편화 모두 최소화
  예: Linux 커널의 slab allocator (task_struct, inode 등)

버디 시스템 (Buddy System):
  2의 거듭제곱 크기 블록으로 관리
  분할: 2^n → 2^(n-1) + 2^(n-1) (버디 쌍)
  합병: 두 버디가 모두 해제되면 자동 합병
  장점: 합병이 O(log n)으로 빠름
  단점: 내부 단편화 최대 50%

예: malloc(33) → 64바이트 블록 할당 (가장 가까운 2^n)
```


## 핵심 요약

- **내부 단편화**: 블록 내 낭비. 정렬·최소 크기 때문에 불가피.
- **외부 단편화**: 흩어진 해제 블록들. 합병과 좋은 배치 정책으로 완화.
- **합병**: 인접 해제 블록을 즉시 합쳐 외부 단편화 방지.
- **압축**: GC 언어에서 모든 객체를 이동시켜 연속 공간 확보.
- **Slab/Buddy**: 특수 목적 할당기로 단편화 최소화.
