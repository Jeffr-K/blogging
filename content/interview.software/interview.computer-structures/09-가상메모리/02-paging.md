## 페이징 (Paging)

가상 주소를 물리 주소로 변환하는 핵심 메커니즘입니다. 메모리를 고정 크기 **페이지(Page)** 단위로 관리합니다.

---

## 1. 페이지와 프레임

```
페이지 (Page):
  가상 메모리를 나누는 고정 크기 블록
  일반적으로 4 KB (x86-64 기본)
  큰 페이지: 2 MB, 1 GB (huge pages)

프레임 (Frame / Physical Page):
  물리 메모리를 나누는 같은 크기 블록

관계:
  가상 페이지 n → 물리 프레임 m 으로 매핑
  (매핑 정보: 페이지 테이블에 저장)

예 (4 KB 페이지):
  4 GB 가상 주소 공간 → 4GB / 4KB = 1M 개의 페이지
  4 GB 물리 메모리    → 1M 개의 프레임
```

---

## 2. 가상 주소 구조 (x86-64, 4 KB 페이지)

```
48비트 가상 주소 구조:
┌──────────┬──────────┬──────────┬──────────┬─────────────┐
│  PGD (9) │  PUD (9) │  PMD (9) │  PT  (9) │ Offset (12) │
└──────────┴──────────┴──────────┴──────────┴─────────────┘
  비트 47-39  비트 38-30  비트 29-21  비트 20-12  비트 11-0

Page Global Directory   → Page Upper Directory
→ Page Middle Directory → Page Table
→ + Offset = 물리 주소

단순화 (32비트 또는 1단계 예시):
┌──────────────────┬──────────────┐
│ 가상 페이지 번호  │  페이지 오프셋  │
│   (VPN, 20비트)  │   (12비트)   │
└──────────────────┴──────────────┘
VPN → 페이지 테이블에서 물리 프레임 번호(PFN) 조회
물리 주소 = PFN × 4096 + Offset
```

---

## 3. 페이지 테이블 (Page Table)

```
페이지 테이블 엔트리 (PTE, Page Table Entry):
┌────────────────────────┬───┬───┬───┬───┬───┐
│ 물리 프레임 번호 (PFN)  │ D │ A │ U │ W │ P │
└────────────────────────┴───┴───┴───┴───┴───┘
                            D: Dirty (수정됨)
                            A: Accessed (접근됨)
                            U: User (유저 접근 가능)
                            W: Writable (쓰기 가능)
                            P: Present (현재 물리 메모리에 있음)

P=0 (Present 비트 꺼짐):
  → 페이지가 디스크에 있음
  → 접근 시 Page Fault 발생!
```

---

## 4. 주소 변환 과정

```
1. CPU가 가상 주소 VA 생성
2. MMU가 VA를 VPN + Offset으로 분리
3. CR3 레지스터(페이지 테이블 기준 주소) 참조
4. 페이지 테이블에서 VPN → PTE 조회
5. PTE의 Present 비트 확인:
   P=1: PFN 추출 → 물리 주소 = PFN:Offset
   P=0: Page Fault → OS가 디스크에서 로드
6. 물리 주소로 메모리 접근

예:
  VA = 0x12345
  VPN = 0x12 (상위 비트)
  Offset = 0x345 (하위 12비트)
  페이지 테이블[0x12].PFN = 0x7A
  PA = 0x7A000 + 0x345 = 0x7A345
```

---

## 5. 페이지 테이블의 메모리 비용

```
문제: 페이지 테이블 자체도 메모리를 차지함

32비트 시스템, 4KB 페이지:
  페이지 수 = 2^32 / 2^12 = 2^20 = 1M 개
  PTE 크기 = 4 바이트
  페이지 테이블 = 4MB (프로세스당!)
  
64비트 시스템, 4KB 페이지:
  페이지 수 = 2^48 / 2^12 = 2^36 = 64G 개
  단순 계산 시 페이지 테이블 = 256GB...

해결책:
  → 다단계 페이지 테이블 (Multi-Level Page Table)
  → 실제 사용하는 부분만 할당
  → 희소 주소 공간에 효율적
```

---

## 6. 메모리 보호

```
페이지 단위로 접근 권한 설정:
  텍스트 영역: Read + Execute (쓰기 불가)
  데이터/힙/스택: Read + Write (실행 불가)
  커널 영역: User 비트 = 0 (유저 모드 접근 불가)

접근 위반 시:
  → Protection Fault (Segmentation Fault)
  → OS가 SIGSEGV 시그널 발송
  → 프로세스 종료

NX 비트 (No-eXecute):
  스택/힙에 코드 실행 방지
  버퍼 오버플로우 공격 방어
```

---

## 핵심 요약

- **페이징**: 가상/물리 메모리를 4KB 페이지 단위로 관리.
- **PTE**: 물리 프레임 번호 + 접근 권한 + Present 비트.
- **주소 변환**: VPN → 페이지 테이블 조회 → PFN + Offset = PA.
- **Present=0**: 페이지 폴트 발생 → OS가 디스크에서 로드.
- **보호**: 페이지별 R/W/X 권한으로 메모리 보호.
