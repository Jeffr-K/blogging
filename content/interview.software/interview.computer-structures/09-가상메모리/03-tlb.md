## TLB (Translation Lookaside Buffer)

페이지 테이블 조회는 메모리 접근이 필요합니다. 이를 가속하기 위한 **주소 변환 전용 캐시**가 TLB입니다.

---

## 1. TLB가 필요한 이유

```
페이지 테이블 조회 비용:
  4단계 페이지 테이블 (x86-64):
    1. CR3 → PGD 테이블 (메모리 접근 1회)
    2. PGD → PUD 테이블 (메모리 접근 1회)
    3. PUD → PMD 테이블 (메모리 접근 1회)
    4. PMD → PT 테이블  (메모리 접근 1회)
    5. 최종 데이터 접근  (메모리 접근 1회)
    → 데이터 1개 읽으려고 메모리를 5번 접근!

TLB 해결:
  VPN → PFN 변환 결과를 캐시
  TLB 히트 시 메모리 접근 없이 즉시 PA 획득
  TLB 히트율: 일반적으로 99% 이상
```

---

## 2. TLB 구조

```
TLB는 CPU 내부의 작은 완전 연관(Fully Associative) 캐시:

┌─────────┬─────────┬────────────────┬───────┐
│  Valid  │   Tag   │ 물리 프레임(PFN) │ Prot  │
│  (1비트) │  (VPN)  │                │ 권한  │
├─────────┼─────────┼────────────────┼───────┤
│    1    │ 0x12345 │   0x7A         │ R/W   │
│    1    │ 0x00001 │   0x03         │ R/X   │
│    0    │    -    │    -           │  -    │
└─────────┴─────────┴────────────────┴───────┘

크기: 보통 32~1024 엔트리
구분: L1 TLB (코드/데이터 분리) + L2 TLB (통합)
```

---

## 3. TLB 동작 흐름

```
CPU가 VA 접근:
           ┌─────────────┐
           │ VA → VPN분리 │
           └──────┬──────┘
                  ↓
           ┌─────────────┐     HIT     ┌──────────────────┐
           │  TLB 조회    │ ──────────→ │ PFN + Offset = PA │
           └──────┬──────┘             └──────────────────┘
                  │ MISS
                  ↓
           ┌─────────────┐
           │ 페이지 테이블 │ ← 메모리에서 PTE 조회 (4회 접근)
           │  워크       │
           └──────┬──────┘
                  ↓
           ┌─────────────┐
           │ TLB 업데이트 │ ← 새 매핑 저장
           └──────┬──────┘
                  ↓
           ┌─────────────┐
           │ PA로 접근   │
           └─────────────┘
```

---

## 4. TLB 미스(Miss) 처리 방식

```
하드웨어 TLB 워크 (x86, ARM):
  CPU 하드웨어가 직접 페이지 테이블 탐색
  OS 개입 없음, 빠름
  페이지 테이블 형식이 하드웨어에 고정됨

소프트웨어 TLB 워크 (MIPS, SPARC):
  TLB 미스 → OS 핸들러 호출
  OS가 직접 TLB 엔트리 채움
  느리지만 페이지 테이블 형식 자유로움
```

---

## 5. TLB 플러시 (Flush)

```
컨텍스트 스위칭 문제:
  프로세스 A: VA 0x1000 → PA 0x5000
  프로세스 B: VA 0x1000 → PA 0x8000
  → 프로세스 전환 시 TLB 내용이 잘못됨!

해결 방법:

방법 1: 전체 TLB 플러시
  컨텍스트 스위칭마다 TLB 전체 무효화
  단순하지만 성능 저하 (TLB 워밍업 비용)
  x86: mov cr3, ... 명령어가 자동으로 플러시

방법 2: ASID (Address Space ID)
  각 TLB 엔트리에 프로세스 ID 태그 추가
  다른 프로세스의 TLB 엔트리를 무효화할 필요 없음
  ARM, x86 (PCID) 지원
  
  TLB 엔트리: VPN + ASID → PFN
  ASID가 다르면 히트하지 않음
```

---

## 6. TLB와 캐시의 상호작용

```
VIVT (Virtual Index, Virtual Tag):
  가상 주소로 캐시 인덱스와 태그 계산
  TLB 조회 전에 캐시 접근 가능 → 빠름
  문제: 동일 VA가 다른 PA에 매핑 시 동의어(Alias) 문제

PIPT (Physical Index, Physical Tag):
  물리 주소로 캐시 접근
  TLB 변환 후 캐시 접근 → 느림
  동의어 문제 없음, 안전

VIPT (Virtual Index, Physical Tag): ← 일반적
  가상 주소로 인덱스, 물리 주소로 태그
  TLB 조회와 캐시 인덱싱을 병렬로!
  페이지 오프셋 비트만 인덱스로 사용 시 동의어 문제 없음
  L1 캐시에서 주로 사용
```

---

## 핵심 요약

- **TLB**: VA→PA 변환 결과를 저장하는 CPU 내부 캐시.
- **TLB 히트**: 페이지 테이블 접근 없이 즉시 PA 획득.
- **TLB 미스**: 페이지 테이블 워크 후 TLB 업데이트.
- **플러시 문제**: 컨텍스트 스위칭 시 TLB 무효화 필요 (ASID로 개선).
- **히트율 99%+**: 지역성 덕분에 TLB는 매우 효과적.
