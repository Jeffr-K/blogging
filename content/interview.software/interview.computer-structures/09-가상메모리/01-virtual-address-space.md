## 가상 주소 공간 (Virtual Address Space)

모든 프로세스는 각자 독립적인 메모리 공간을 가진 것처럼 동작합니다. 이것이 **가상 주소 공간**입니다.

---

## 1. 왜 가상 메모리가 필요한가

```
물리 메모리(DRAM)의 한계:
  ✗ 여러 프로세스가 같은 주소를 사용하면 충돌
  ✗ 프로세스가 다른 프로세스 메모리를 침범 가능
  ✗ 물리 메모리보다 큰 프로그램은 실행 불가

가상 메모리로 해결:
  ✓ 각 프로세스에게 독립된 주소 공간 제공 (고립성)
  ✓ 물리 메모리보다 큰 프로그램도 실행 가능 (용량 확장)
  ✓ 메모리 보호: 다른 프로세스 접근 차단 (보안)
  ✓ 공유 메모리, COW 등 효율적 공유 가능 (편의성)
```

## 2. 가상 주소 공간의 구조 (x86-64 Linux)

```
가상 주소 공간 (64비트: 이론상 16 EB, 실제 48비트 = 256 TB)

높은 주소 ┌─────────────────────┐ 0xFFFFFFFFFFFFFFFF
          │   커널 공간          │ (kernel space: 128 TB)
          │  (사용자 접근 불가)   │
          ├─────────────────────┤ 0xFFFF800000000000
          │        비어있음       │ (canonical hole)
          ├─────────────────────┤ 0x00007FFFFFFFFFFF
          │   스택 (Stack)       │ ↓ 아래로 성장
          │        ...           │
          │   공유 라이브러리     │
          │        ...           │
          │   힙 (Heap)          │ ↑ 위로 성장
          │   BSS (초기화 안 됨) │
          │   데이터 (Data)      │
낮은 주소  │   텍스트 (Code)      │ 0x400000
          └─────────────────────┘ 0x0 (접근 불가: NULL 보호)
```

## 3. 세그먼트별 역할

```
텍스트(Text) 세그먼트:
  - 실행 코드 (기계어 명령어)
  - 읽기 전용 (쓰기 시 Segfault)
  - 여러 프로세스가 공유 가능

데이터(Data) 세그먼트:
  - 초기화된 전역 변수, static 변수
  예: int x = 10; (전역)

BSS 세그먼트:
  - 초기화되지 않은 전역 변수, static 변수
  - 실행 파일에 크기만 기록 (0으로 채워짐)
  예: int arr[1000]; (전역)

힙(Heap):
  - malloc/free로 관리되는 동적 메모리
  - brk/sbrk 시스템 콜로 크기 조절
  - 낮은 주소 → 높은 주소 방향으로 성장

스택(Stack):
  - 지역 변수, 함수 호출 프레임
  - 높은 주소 → 낮은 주소 방향으로 성장
  - 스택 오버플로우: 스택이 힙 방향으로 넘침
```

## 4. 가상 주소 vs 물리 주소

```
가상 주소 (VA, Virtual Address):
  프로세스가 사용하는 주소
  예: 0x7fff1234 → 이 프로세스만의 고유한 주소 공간

물리 주소 (PA, Physical Address):
  실제 DRAM 칩의 주소
  예: 0x2abc0000 → 실제 메모리 위치

주소 변환 (Address Translation):
  VA → PA 변환은 MMU(Memory Management Unit) 하드웨어가 담당
  변환 정보는 페이지 테이블(Page Table)에 저장
  
  프로세스 A: VA 0x1000 → PA 0x5000
  프로세스 B: VA 0x1000 → PA 0x8000
  → 같은 가상 주소가 다른 물리 주소에 매핑!
```

## 5. 주소 공간 격리의 이점

```
보안:
  프로세스 A는 프로세스 B의 메모리를 직접 읽을 수 없음
  커널 공간은 유저 모드에서 접근 불가

안정성:
  한 프로세스의 잘못된 메모리 접근이 다른 프로세스에 영향 없음
  Segmentation Fault → 해당 프로세스만 종료

유연성:
  모든 프로세스가 동일한 가상 주소에 로드될 수 있음
  (컴파일러가 고정 주소 가정 가능)
```

---

## 핵심 요약

- **가상 주소 공간**: 각 프로세스에게 독립적인 메모리 공간의 환상을 제공.
- **구조**: 텍스트 → 데이터 → BSS → 힙 ↑ ... ↓ 스택.
- **VA → PA**: MMU가 페이지 테이블을 통해 변환.
- **격리**: 같은 가상 주소가 프로세스마다 다른 물리 주소에 매핑됨.
- **커널 공간**: 상위 절반, 유저 모드에서 접근 불가.
