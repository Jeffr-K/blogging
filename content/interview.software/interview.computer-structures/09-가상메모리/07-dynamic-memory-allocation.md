## 동적 메모리 할당

`malloc`과 `free`는 어떻게 힙(Heap) 메모리를 관리할까요? 내부 구현 원리를 이해합니다.

---

## 1. 힙(Heap) 영역

```
프로세스 주소 공간:
  텍스트 → 데이터 → BSS → [힙] ↑↑↑ ... ↓↓↓ [스택]

힙 경계:
  brk 포인터: 힙의 현재 끝 (높은 주소 방향으로 이동)
  
시스템 콜:
  brk(addr)  : brk 포인터를 addr로 설정
  sbrk(inc)  : brk 포인터를 inc만큼 증가
  mmap(...)  : 큰 블록(>128KB) 할당 시 사용
```

---

## 2. malloc 구현의 핵심: 블록 구조

```
힙은 블록들의 연속:

할당된 블록:
  ┌──────────┬──────────────────────────────┐
  │  헤더    │           페이로드            │
  │ (크기|1) │    (사용자에게 반환된 공간)    │
  └──────────┴──────────────────────────────┘

해제된 블록:
  ┌──────────┬─────────┬─────────┬──────────┐
  │  헤더    │ 이전 포인터 │ 다음 포인터 │  풋터  │
  │ (크기|0) │  (prev) │  (next) │ (크기|0) │
  └──────────┴─────────┴─────────┴──────────┘

헤더/풋터:
  크기 (상위 비트들) + 할당 여부 (최하위 비트)
  크기는 항상 8바이트 정렬 → 최하위 3비트 사용 가능
```

---

## 3. 가용 리스트 (Free List)

```
해제된 블록들을 연결 리스트로 관리:

방법 1: 묵시적 가용 리스트 (Implicit Free List)
  모든 블록을 헤더의 크기 필드로 연결
  malloc 시 전체 스캔 필요 → O(n) 검색

방법 2: 명시적 가용 리스트 (Explicit Free List)
  해제된 블록만 포인터로 연결 (prev/next)
  malloc 시 해제 블록만 순회 → 더 빠름

방법 3: 분리 가용 리스트 (Segregated Free List)
  크기 클래스별로 별도 리스트 유지
  예: {1~8바이트}, {9~16}, {17~32}, ..., {>2048}
  원하는 크기의 리스트에서 먼저 탐색 → 매우 빠름
  glibc의 ptmalloc, jemalloc, tcmalloc이 사용
```

## 4. 배치 정책 (Placement Policy)

```
malloc(size) 시 적합한 가용 블록 선택:

First Fit: 처음 발견한 충분히 큰 블록 사용
  장점: 빠름
  단점: 낮은 주소에 작은 단편화 집중

Next Fit: 이전 검색 위치부터 탐색
  First Fit보다 단편화 분산

Best Fit: 가장 딱 맞는(낭비 최소) 블록 선택
  장점: 단편화 최소
  단점: 전체 탐색 필요 → 느림

실제: 분리 가용 리스트 + 크기 클래스 근사 Best Fit
```

## 5. 분할과 합병 (Splitting & Coalescing)

```
분할 (Splitting):
  찾은 블록이 요청보다 훨씬 크면 분할
  앞부분: 할당, 뒷부분: 새 해제 블록으로
  
  free: [100바이트] → malloc(32) 
  → [32바이트 할당] + [68바이트 해제]

합병 (Coalescing):
  free() 시 인접한 해제 블록과 합병
  외부 단편화 방지

  즉시 합병 (Immediate Coalescing):
    free() 호출 즉시 인접 블록 확인 후 합병
    풋터 필요 (역방향 합병을 위해)

  지연 합병 (Deferred Coalescing):
    잠시 합병 미루다 필요 시 일괄 처리
    성능 최적화 가능
```

## 6. glibc malloc (ptmalloc2) 전략

```
청크 (Chunk) 구조:
  최소 크기: 32바이트 (64비트 시스템)
  정렬: 16바이트 경계

Bin 종류:
  Fast bin: 최대 160바이트, LIFO, 합병 없음 (빠름)
  Small bin: 최대 1024바이트, FIFO, 크기별 bin
  Large bin: 1024바이트 초과, 크기 범위별 bin
  Unsorted bin: free 직후 임시 보관

큰 할당 (>128KB):
  mmap()으로 직접 OS에서 메모리 획득
  free() 시 munmap()으로 즉시 OS 반환
```

## 7. 일반적인 실수와 오류

```c
// 1. 메모리 누수 (Memory Leak)
void *p = malloc(100);
p = malloc(200); // 첫 번째 100바이트 영원히 해제 불가!

// 2. 이중 해제 (Double Free)
free(p);
free(p); // 힙 손상! 보안 취약점

// 3. 댕글링 포인터 (Dangling Pointer)
free(p);
*p = 1; // 해제된 메모리 사용 - 미정의 동작

// 4. 힙 버퍼 오버플로우
char *buf = malloc(10);
buf[15] = 'x'; // 다른 청크 헤더 손상 → 힙 손상
```

## 핵심 요약

- **힙 블록**: 헤더(크기+할당여부) + 페이로드 + (풋터).
- **가용 리스트**: 해제 블록을 연결 리스트로 관리 (분리 리스트가 효율적).
- **배치**: First/Best Fit → 실제는 크기 클래스별 근사 Best Fit.
- **분할**: 큰 블록에서 필요한 만큼만 잘라 할당.
- **합병**: 인접 해제 블록을 합쳐 외부 단편화 방지.
- **큰 할당**: mmap()으로 OS에서 직접 획득.
