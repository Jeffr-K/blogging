## 페이지 폴트 (Page Fault)

접근하려는 가상 페이지가 물리 메모리에 없을 때 발생하는 **폴트(Fault)** 예외입니다.

---

## 1. 페이지 폴트의 종류

```
1. 메이저 폴트 (Major/Hard Page Fault):
   페이지가 디스크(스왑 공간)에 있음
   디스크 I/O 발생 → 느림 (밀리초 단위)
   예: 처음 접근하는 파일 매핑, 스왑된 페이지

2. 마이너 폴트 (Minor/Soft Page Fault):
   페이지가 이미 메모리에 있지만 페이지 테이블 미등록
   디스크 I/O 없음 → 빠름 (마이크로초 단위)
   예: fork() 후 COW 페이지, 공유 라이브러리

3. 무효 폴트 (Invalid Page Fault):
   접근 권한 위반 또는 매핑되지 않은 주소
   → Segmentation Fault (SIGSEGV)
   예: NULL 포인터 역참조, 스택 오버플로우
```

---

## 2. 페이지 폴트 처리 흐름

```
① CPU가 가상 주소 VA에 접근
② MMU가 페이지 테이블 확인 → Present 비트 = 0
③ 하드웨어: 현재 프로세스 상태 저장 + 페이지 폴트 핸들러 호출

④ OS 페이지 폴트 핸들러:
   a. VA가 유효한 매핑인지 확인 (VMA 구조체 탐색)
      유효하지 않음 → SIGSEGV 발송
   b. 접근 권한 확인 (쓰기/실행 권한)
      위반 → SIGSEGV 발송
   c. 페이지를 어디서 가져올지 결정:
      - 처음 접근하는 익명 페이지 → 0으로 채운 새 프레임
      - 파일 매핑 → 파일에서 읽기
      - 스왑 공간 → 디스크에서 읽기

⑤ 물리 프레임 확보:
   여유 프레임 있음 → 바로 사용
   없음 → 페이지 교체(eviction) 수행

⑥ 페이지를 물리 메모리에 로드

⑦ 페이지 테이블 업데이트 (PTE의 PFN 설정, Present=1)

⑧ TLB 업데이트

⑨ 원래 명령어 재실행 (폴트는 같은 명령어 재시도!)
```

---

## 3. 디맨드 페이징 (Demand Paging)

```
프로그램 실행 시 전체를 메모리에 로드하지 않음:
  실행 파일 로드 시: 페이지 테이블만 설정 (Present=0)
  실제 접근 시: 그때 페이지 폴트 → 필요한 페이지만 로드

장점:
  ✓ 빠른 프로그램 시작 (모든 코드 로드 불필요)
  ✓ 실제 사용하는 메모리만 물리 메모리 차지
  ✓ 사용 안 하는 코드 경로의 페이지는 아예 안 로드됨

단점:
  ✗ 초기 실행 시 잦은 페이지 폴트 (Cold Start)
```

---

## 4. 스왑(Swap) 공간

```
물리 메모리 부족 시:
  OS가 일부 페이지를 디스크의 스왑 공간으로 이동
  해당 PTE: Present=0, 디스크 위치 정보 저장

스왑 아웃 (Eviction):
  LRU 등 교체 알고리즘으로 희생 페이지 선택
  Dirty 페이지: 디스크에 써야 함
  Clean 페이지: 디스크에 이미 있음 → 그냥 버림

스왑 인 (Page In):
  페이지 폴트 → 디스크에서 다시 로드

스왑 폭풍 (Thrashing):
  물리 메모리 심각 부족 → 끊임없이 스왑 in/out
  CPU 시간의 대부분을 페이지 교체에 소비
  → 시스템 사실상 마비

Linux: /proc/[pid]/status의 MajFlt, MinFlt 통계 확인 가능
```

---

## 5. 스택 성장

```
스택은 동적으로 커짐:
  함수 호출 깊어짐 → 스택 포인터가 낮은 주소로 이동
  스택 한계 아래 주소 접근 → 페이지 폴트

OS의 처리:
  1. 폴트 주소가 스택 포인터 근처인지 확인
  2. 스택 한계 내에 있으면 새 스택 페이지 할당
  3. 스택 한계 초과 → SIGSEGV (스택 오버플로우)

Linux 기본 스택 한계: 8MB (ulimit -s로 확인/변경)
```

---

## 핵심 요약

- **페이지 폴트**: Present=0인 페이지 접근 시 발생하는 폴트.
- **메이저**: 디스크 I/O 필요 (느림). **마이너**: 이미 메모리에 있음 (빠름).
- **처리**: OS가 프레임 확보 → 페이지 로드 → PTE 업데이트 → 재실행.
- **디맨드 페이징**: 필요할 때만 로드 → 메모리 효율적 사용.
- **스래싱**: 메모리 부족으로 페이지 폴트가 폭발적으로 발생하는 상태.
