## 마이그레이션 표준 7단계 완전 분석

어떤 데이터베이스 마이그레이션이든 실패하지 않기 위해 지켜야 할 철칙과도 같은 7단계 표준 프로세스가 있습니다. 10년 차 엔지니어들이 현장에서 체득한 이 금과옥조 같은 절차들을 상세하게 해부해 봅니다.

---

### Phase 1: 사전 분석 (Discovery & Assessment)

이전하려는 소스 DB에 무엇이 들어있는지 명확히 알아야 합니다.

- **조사 대상**: 전체 데이터 크기(GB/TB), 초당 트랜잭션 수(TPS), 테이블 수, 인덱스 현황, View와 Stored Procedure 보유 여부.
- **산출물**: 마이그레이션 범위와 이기종 간의 데이터 타입 매핑 정의서.

### Phase 2: 타겟 설계 (Design & Provisioning)

데이터가 도착할 목적지의 그릇을 그립니다.

- **조사 대상**: CPU 수, 메모리 크기, 디바이스 IOPS 사양 등 타겟 DB의 인스턴스 사양 설계.
- **산출물**: 네트워크 토폴로지(VPC, 서브넷 설계) 및 방화벽 설정(Security Group) 규칙.

### Phase 3: 스키마 변환 (Schema Conversion)

엔진이 다르다면 옷을 갈아입어야 합니다. (같은 엔진이라면 이 단계는 건너뜜니다.)

- **조사 대상**: 소스 DB와 타겟 DB의 SQL 호환성 확인. 데이터 타입 변환 필요 여부.
- **산출물**: 타겟 DB에 최적화된 테이블 정의(DDL) 및 인덱스 생성 스크립트.

### Phase 4: 초기 복제 (Initial Load / Full Load)

현재 시점의 데이터를 통째로 복사합니다.

- **조사 대상**: 대용량 데이터를 빠르고 안전하게 전송할 수 있는 병렬 복제 방식 선정.
- **산출물**: 타겟 DB가 1차적으로 소스 DB의 과거 어느 한 시점과 동일한 상태가 됩니다.

### Phase 5: 증분 동기화 (Ongoing Replication / CDC)

초기 복제 중에 발생한 새로운 데이터 변경 건들을 추적합니다.

- **조사 대상**: 소스 DB의 바이너리 로그(Binlog)나 WAL 로그를 실시간으로 읽어 타겟으로 흘려보내기(CDC - Change Data Capture).
- **산출물**: 소스와 타겟 사이의 데이터 시차가 0에 가깝도록 실시간 동기화 상태 유지.

### Phase 6: 데이터 정합성 검증 (Validation)

"데이터가 과연 단 한 건도 안 틀리고 다 넘어왔는가?"

- **조사 대상**: 행 개수 대조(H-count), 집계 함수의 결과 대조(Check-sum), 랜덤 샘플링 데이터 전체 대조.
- **산출물**: 정합성이 입증된 최종 검토 보고서.

### Phase 7: 서비스 전환 (Cut-over)

애플리케이션이 바라보는 DB의 입구를 구(Old)에서 신(New)으로 전격 변경합니다.

- **조사 대상**: 서비스 일시 정지 -> 서비스 전환 -> 정상 작동 확인.
- **산출물**: 마이그레이션 성공 판정 및 시스템 정상 인계.

---

### 결론: "속도보다 정교함이 이긴다"

각 단계는 생략할 수 없는 고유의 가치를 지니고 있습니다. 특히 Phase 1의 정확한 사전 분석이 뒷단에서의 모든 삽질을 80% 이상 줄여준다는 사실을 잊지 마시기 바랍니다.
