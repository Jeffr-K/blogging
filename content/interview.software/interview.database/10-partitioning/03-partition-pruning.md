## 파티션 프루닝(Partition Pruning)의 작동 원리

파티셔닝을 해서 조회가 빨라지는 가장 큰 이유는 바로 **파티션 프루닝(Partition Pruning)** 때문입니다. '프루닝(Pruning)'은 나뭇가지를 치는 것을 의미하며, 쿼리와 관계없는 파티션을 아예 검색 대상에서 제외하는 똑똑한 기술입니다.

---

### 1. 프루닝의 물리적 원리

예를 들어, 1년 치 주문 데이터가 월별(1월~12월)로 12개의 파티션에 나뉘어 있다고 가정해 봅시다.

```sql
SELECT * FROM orders WHERE order_date BETWEEN '2024-03-01' AND '2024-03-31';
```

이 쿼리가 실행되면 데이터베이스 엔진은 다음과 같이 작동합니다.

1. **분석**: 쿼리 조건이 `2024-03`임을 인지합니다.
2. **가지치기**: 전체 12개 파티션 중 '3월 파티션' 하나만 남기고 나머지 11개는 **"열어보지도 않습니다."**
3. **스캔**: 단 하나의 작은 파티션 내부만 뒤져서 결과를 가져옵니다.

### 2. 성능 차이의 이유

- **I/O 감소**: 12개를 볼 것을 1개만 보므로 디스크 읽기 량이 1/12로 줄어듭니다.
- **인덱스 크기 축소**: 파티션별로 인덱스가 따로 있다면(Local Index), 탐색해야 할 트리 깊이가 얕아져 검색 속도가 비약적으로 빨라집니다.

### 3. 실무에서의 주의사항: 프루닝이 안 되는 경우

모든 쿼리가 마법처럼 프루닝되는 것은 아닙니다. 다음과 같은 경우 엔진은 프루닝을 포기하고 모든 파티션을 다 뒤지게 됩니다. (Full Table Scan)

- **파티션 키 가공**: `WHERE MONTH(order_date) = 3` 처럼 키를 함수로 감싸면 프루닝이 작동하지 않습니다.
- **부적절한 조건형**: 파티션 키가 아닌 컬럼으로만 검색할 경우, 엔진은 어느 파티션에 데이터가 있을지 모르기 때문에 결국 전체를 뒤져야 합니다.

---

### 전문가의 한마디

파티션 프루닝이 잘 되고 있는지 확인하려면 반드시 `EXPLAIN` (MySQL) 또는 `EXPLAIN ANALYZE` (PostgreSQL) 명령을 사용해야 합니다. 결과의 `partitions` 컬럼을 보고, 의도한 특정 파티션만 접근하고 있는지 수시로 확인하는 습관이 좋은 성능을 보장합니다.
