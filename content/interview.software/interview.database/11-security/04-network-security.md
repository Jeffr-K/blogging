## 네트워크 및 액세스 제어

아무리 강력한 비밀번호를 가진 데이터베이스라도, 인터넷 전체(0.0.0.0/0)에 문이 열려있다면 전 세계 해커의 놀이터가 됩니다. 데이터베이스를 외부로부터 격리하는 네트워크 설계 원칙을 정리합니다.

---

### 1. 프라이빗 서브넷(Private Subnet) 설계

데이터베이스 서버는 절대로 **퍼블릭 IP(Public IP)**를 가져서는 안 됩니다.

- 오직 사내망이나 특정 애플리케이션 서버가 위치한 **프라이빗 서브넷**에 배치해야 합니다.
- 외부 개발자가 DB를 조회해야 한다면, VPN을 타거나 `Bastion Host`라는 징검다리 서버를 통해서만 접근하도록 제한해야 합니다.

### 2. 보안 그룹(Security Group)과 방화벽

물리적인 혹은 가상적인 방화벽을 통해 접근을 2중으로 차단합니다.

- **Port 제한**: 기본 포트인 3306(MySQL), 5432(PostgreSQL) 등을 사용하되, 오직 소스 IP가 애플리케이션 서버의 IP 대역인 경우만 패킷을 통과시킵니다.
- **아웃바운드 차단**: DB 서버가 외부 인터넷으로 나가는 통로도 차단하는 것이 좋습니다. 해커가 탈취한 서버에서 데이터를 외부 전송하는 것을 막아주기 때문입니다.

### 3. 접근 제어 게이트웨이

대규모 엔터프라이즈 환경에서는 개별 서버 설정만으로는 관리가 힘듭니다.

- DB 접근 제어 솔루션(예: 샤드, 쿼리 파이 등)을 도입하여, 누가 어떤 쿼리를 날리는지 중간에서 검문하고 기록하는 구조를 가져갑니다.

3. **불필요한 포트가 열려있는가?**: (DB 포트 외에는 닫아야 합니다.)

네트워크 보안은 **"보이지 않게 하는 것"**에서 시작합니다. 공격자가 우리 DB 서버에 패킷 하나라도 보낼 수 없도록 물리적인 장벽을 탄탄히 쌓으시길 바랍니다.
