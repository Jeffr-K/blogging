## Nested Loop Join (NLJ): 이중 루프 기반의 조인 메커니즘

데이터베이스 엔진에서 가장 널리 사용되는 조인 방식인 **네스티드 루프 조인(Nested Loop Join)**은 프로그래밍의 중첩 반복문(Loop)과 유사한 알고리즘을 사용합니다. 선행 테이블의 추출된 행마다 후행 테이블의 대응되는 데이터를 실시간으로 탐색하는 방식입니다.

이 알고리즘은 **인덱스(Index)**와 결합할 때 성능이 극대화됩니다. NLJ의 작동 원리와 드리븐(Driven) 테이블 인덱스 유무에 따른 비용 차이를 분석합니다.

---

## 1. NLJ의 물리적 작동 프로세스

1.  **Outer Loop (드라이빙 테이블)**: 조건에 맞는 선행 테이블(A)의 레코드를 순차적으로 스캔합니다.
2.  **Inner Loop (드리븐 테이블)**: 선행 테이블에서 추출된 개별 레코드의 키 값을 사용하여 후행 테이블(B)에서 매칭되는 데이터를 탐색합니다.
3.  **Result Combination**: 탐색에 성공한 행들을 결합하여 최종 결과셋에 포함시킵니다.

### 1.1 인덱스 유무에 따른 성능 격차

- **드리븐 테이블 인덱스 확보**: 선행 테이블의 각 행마다 후행 테이블의 인덱스 트리(B+Tree)를 타고 즉각적으로 데이터를 찾아냅니다 (`eq_ref` 또는 `ref` 스캔). (최고 성능)
- **인덱스 부재**: 선행 테이블에서 추출된 결과가 100건일 경우, 후행 테이블을 100번 풀 스캔(Full Scan)해야 하는 최악의 상황이 발생합니다.

---

## 2. 드라이빙 테이블(Driving Table) 선정 전략

조인 연산의 전체 비용은 **(선행 테이블 추출 건수 * 후행 테이블 조인 탐색 비용)**으로 산출됩니다.

- **데이터셋 최소화**: 필터링 조건에 의해 최종적으로 추출되는 행 수가 더 적은 테이블을 드라이빙(Outer)으로 선정하는 것이 루프 횟수를 줄이는 정석입니다.
- **인덱스 매칭**: 드리븐(Inner) 테이블의 조인 컬럼에는 반드시 유효한 인덱스가 존재해야 합니다.

현대적인 옵티마이저는 통계 정보를 기반으로 조인 순서를 자동 결정하지만, 쿼리가 극도로 복잡한 경우 `STRAIGHT_JOIN` 힌트를 사용하여 명시적으로 드라이빙 테이블을 고정해야 할 수 있습니다.

---

## 3. Block Nested Loop (BNL) 최적화 기법

드리븐 테이블에 적절한 인덱스가 없는 상황에서 성능 추락을 방어하기 위해 엔진은 **조인 버퍼(Join Buffer)** 메모리를 활용합니다.

- **작동 원리**: 드라이빙 테이블의 데이터를 조인 버퍼에 최대한 적재한 뒤, 드리븐 테이블을 단 한 번 풀 스캔하면서 버퍼 내 모든 데이터를 일괄 대조합니다.
- **효과**: 후행 테이블의 물리적 풀 스캔 횟수를 획기적으로 낮추어 I/O 부하를 경감시키는 최후의 보루 역할을 합니다.

---

## 4. 결론

Nested Loop Join은 **"작은 결과 집합으로 큰 집합의 인덱스를 탐색하는 기술"**입니다.

1. 드리븐 테이블의 조인 컬럼 인덱스 구성은 성능 보장을 위한 필수 조건입니다.
2. 필터링 후의 데이터 유량이 적은 테이블이 드라이빙 역할을 수행하도록 쿼리를 설계하십시오.
3. 조인 버퍼 설정을 통해 인덱스 부재 상황에서의 최악의 성능 저하를 방어하십시오.
