## 슬로우 쿼리 로그: 성능 저하의 객관적 지표

데이터베이스 성능 저하의 근본 원인을 파악하기 위해서는 실행되는 수많은 쿼리 중 물리적 리소스를 과도하게 점유하는 대상을 식별해야 합니다. **슬로우 쿼리 로그(Slow Query Log)**는 설정된 임계 시간(Long Query Time)을 초과하는 쿼리를 자동으로 기록하여 최적화가 필요한 병목 지점을 명확히 제시합니다.

본 아티클에서는 슬로우 쿼리 로그의 활성화 전략과 전문 분석 도구를 활용한 실전 프로파일링 기법을 분석합니다.

---

## 1. 슬로우 쿼리 활성화 및 핵심 파라미터 설계

단순한 로그 기록을 넘어, 어떤 수준의 쿼리를 성능 개선 대상으로 삼을 것인지 결정하는 파라미터 설계가 중요합니다.

- **`long_query_time`**: 로그에 기록될 쿼리의 최소 실행 시간(초)을 정의합니다. 성능 민감도가 높은 서비스의 경우 0.1~0.5초 사이의 낮은 임계값 설정을 권장합니다.
- **`log_queries_not_using_indexes`**: 실행 시간과 관계없이 인덱스를 사용하지 않는 모든 쿼리를 기록합니다. 데이터 규모 증가 시 성능 급락의 원인이 되는 인덱스 누락을 사전에 탐지하기 위한 필수 설정입니다.
- **물리적 오버헤드**: 로그 기록 행위 자체도 미세한 디스크 I/O 부하를 발생시키므로, 트래픽이 극도로 높은 프로덕션 환경에서는 샘플링 기법이나 적절한 임계값 조율이 수반되어야 합니다.

---

## 2. 전문 분석 도구 활용: pt-query-digest (Percona Toolkit)

방대한 양의 슬로우 쿼리 로그 텍스트 파일은 패턴 분석과 우선순위 선정이 어렵습니다. 이를 위해 **pt-query-digest**와 같은 정교한 분석 도구가 필요합니다.

- **쿼리 패턴 그룹화(Ranking)**: 유사한 형태의 쿼리들을 추상화하여 그룹화하고, 각 그룹이 전체 응답 시간(Total Response Time)에서 차지하는 비중을 산출합니다.
- **핵심 성능 지표 분석**: `Query count`(호출 빈도), `Mean query time`(평균 소요 시간), `Rows examined`(스캔한 행 수)를 대조하여, 물리적 스캔 효율이 낮으면서 빈도가 높은 쿼리를 최우선 튜닝 대상으로 선정합니다.

---

## 3. 세부 단계별 프로파일링: SHOW PROFILE

특정 쿼리의 지연 원인이 I/O인지, CPU 연산인지, 혹은 잠금 대기인지 판별하기 위해 단계별 프로파일링을 수행합니다.

```sql
SET profiling = 1;
-- 분석 대상 쿼리 실행
SHOW PROFILE FOR QUERY 1;
```

- **실행 단계별 시간 계측**: `checking permissions`, `opening tables`, `Sending data`, `Sorting result` 등 쿼리 실행의 전 과정에 대한 소요 시간을 마이크로초 단위로 추적합니다.
- **병목 지점 진단**: 만약 **`Sending data`**에서 지연이 발생한다면 인덱스 최적화 및 결과셋 크기 조절이 필요하며, **`Waiting for table lock`**이 길다면 트랜잭션 격리 및 동시성 제어 구조의 결함을 의미합니다.

---

## 4. 결론

슬로우 쿼리 로그는 **데이터베이스 성능 상태를 증명하는 물리적 기록**입니다.

1. 측정이 불가능한 성능은 개선할 수도 없습니다. 슬로우 쿼리 로그를 상시 가동하여 성능 가시성을 확보하십시오.
2. 복잡한 로그 데이터는 `pt-query-digest`와 같은 전문 툴을 거쳐 정제된 우선순위 리스트로 변환하십시오.
3. 쿼리 프로파일링을 통해 병목의 물리적 근거(I/O, CPU, Lock)를 명확히 진단하고 개선안을 도출하십시오.

이 지식을 바탕으로 이제 개별 쿼리를 넘어 엔진 전체의 지표를 실시간으로 조망하는 **Performance Schema와 pg_stat_statements 활용 전략**을 분석합니다.
