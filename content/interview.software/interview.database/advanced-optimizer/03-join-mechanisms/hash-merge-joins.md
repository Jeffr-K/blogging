## 비정규 데이터 결합: Hash Join & Merge Join

모든 조인 연산에 유효한 인덱스가 존재할 수는 없습니다. 또한 조인 대상 데이터 집합이 너무 방대하여 인덱스 탐색(Index Seek) 비용이 풀 스캔 비용보다 커지는 임계점이 존재합니다. 

이러한 대용량 데이터 결합 환경에서 데이터베이스 엔진은 **해시 조인(Hash Join)**이나 **머지 조인(Merge Join)** 알고리즘을 선택합니다. 특히 MySQL 8.0.18+ 버전부터 도입된 해시 조인은 비동등 조인 환경에서 비약적인 성능 향상을 가져왔습니다.

---

## 1. Hash Join의 물리적 단계: Build & Probe

해시 조인은 인덱스 없이도 대량의 데이터 집합을 메모리 내에서 매칭시키는 효율적인 알고리즘입니다.

1.  **Build Phase (빌드 단계)**: 조인 대상 테이블 중 데이터 집합이 더 작은 테이블(Build Table)을 읽어 메모리 내에 **해시 테이블(Hash Table)**을 구축합니다. 조인 키 값은 해시 함수를 통해 해시 버킷으로 변환됩니다.
2.  **Probe Phase (프로브 단계)**: 나머지 큰 테이블(Probe Table)을 순차 스캔하면서 각 행의 조인 키를 해시하여 메모리 내 해시 테이블에 해당 데이터가 존재하는지 즉시 검증합니다.

### 1.1 성능 임계점: Join Buffer Size

해시 조인의 성능은 빌드 테이블이 메모리(`join_buffer_size`)에 모두 상주할 수 있느냐에 달려 있습니다. 메모리가 부족할 경우 데이터를 디스크에 분할하여 저장한 뒤 다시 읽어 들이는 **청크(Chunk) 방식**으로 전환되며, 이 과정에서 심각한 I/O 오버헤드가 발생합니다.

---

## 2. 정렬 기반 결합: Merge Join (Sort-Merge-Join)

머지 조인은 두 집합을 조인 키 순서대로 **사전 정렬**한 뒤, 두 포인터를 순차적으로 이동시키며 매칭시키는 지퍼형 결합 방식입니다.

- **장점**: 두 집합이 이미 인덱스에 의해 정렬되어 있는 경우, 추가적인 정렬 오버헤드 없이 순차 스캔(Sequential Scan)만으로 조인을 완료할 수 있어 매우 효율적입니다.
- **단점**: 데이터가 정렬되어 있지 않다면 강제로 소트(Sort) 연산을 수행해야 하므로 CPU와 임시 디스크 공간 비용이 발생합니다.

---

## 3. 알고리즘 선택 기준 (Optimizer Strategy)

- **Nested Loop Join**: 한쪽 집합이 충분히 작고 유효한 인덱스가 확보된 OLTP 환경의 기본 선택.
- **Hash Join**: 양쪽 집합이 크고 인덱스가 없거나, 동등 조인이 아닌 대용량 데이터 결합 환경 (MySQL 8.0+ / PostgreSQL).
- **Merge Join**: 대량의 데이터를 결합하면서 결과물에 대한 정렬 순서 보장이 필요할 때 강력한 성능을 발휘 (PostgreSQL, Oracle).

---

## 4. 실전 최적화 가이드: 메모리 튜닝

조인 방식은 보통 옵티마이저가 통계 정보를 바탕으로 자동 결정합니다. 가장 효과적인 최적화 수단은 엔진 매개변수 조율입니다.

- **메모리 확보**: `join_buffer_size`(MySQL) 또는 `work_mem`(PostgreSQL) 설정을 적정 수준으로 유지하여 해시 조인이 디스크로 넘어가 파티셔닝되는 현상을 방지해야 합니다.
- **힌트 활용**: `/*+ HASH_JOIN(t1, t2) */` 등의 힌트를 통해 특정 알고리즘 사용을 강제할 수 있으나, 이는 데이터 분포 변화에 따른 위험 부담이 따릅니다.

---

## 5. 결론

Hash Join과 Merge Join은 **"인덱스의 제약을 메모리 연산 성능으로 극복하는 기술"**입니다.

1. 해시 조인의 성능을 위해 빌드 테이블 선정과 메모리 가용량을 면밀히 관리하십시오.
2. 머지 조인의 효율을 위해 인덱스에 의한 정렬 상태를 최대한 활용하십시오.
