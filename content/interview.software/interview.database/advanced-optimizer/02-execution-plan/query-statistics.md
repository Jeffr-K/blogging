## 통계 정보: 옵티마이저의 실행 계획 수립 근거

현대 데이터베이스 옵티마이저는 **비용 기반(Cost-based)**으로 작동합니다. 쿼리 실행 전 각 경로의 물리적 비용을 계산하며, 이 계산의 '미리 보기'를 제공하는 기초 데이터가 바로 **통계 정보(Statistics)**입니다. 인덱스 유무와 별개로 옵티마이저가 특정 경로를 선택하는 논리적 근거를 분석합니다.

---

## 1. 카디널리티(Cardinality)와 데이터 분포의 수치화

카디널리티는 인덱스 컬럼 내에 존재하는 고유한 값(Distinct Values)의 총개수를 의미합니다.

- **비용 산출의 핵심**: 카디널리티가 높을수록(중복도가 낮을수록) 인덱스 스캔을 통해 필터링되는 데이터의 양이 기하급수적으로 많아집니다. 옵티마이저는 이 수치가 높을 때 해당 인덱스를 사용하는 것이 전체 비용(I/O, CPU) 면에서 유리하다고 판단합니다.
- **Full Scan의 임계점**: 카디널리티가 낮아(중복도가 높아) 인덱스 스캔 범위가 전체 데이터의 일정 수준(보통 20~30%)을 초과할 것으로 예측되면, 옵티마이저는 차라리 인덱스 리프 노드를 거치지 않고 데이터 페이지를 직접 읽는 풀 테이블 스캔(Full Scan)이 유리하다고 판단할 수 있습니다.

---

## 2. 통계 정보 관리: ANALYZE TABLE

통계 정보는 실시간으로 정합성이 완벽하게 보장되지 않습니다 (시스템 부하 방지 목적).

- **낡은 통계의 위험성**: 데이터가 대량으로 삽입되거나 삭제되었음에도 통계 정보가 갱신되지 않았다면, 옵티마이저는 실제와 동떨어진 비용 계산을 수행하여 비효율적인 실행 계획을 수립하게 됩니다.
- **해결책**: `ANALYZE TABLE [tablename]` 또는 `VACUUM ANALYZE`(PostgreSQL) 명령을 수행하여 통계 정보를 수동으로 최산화해야 합니다. 특히 대규모 배치 작업 직후에는 필수적인 가속 단계입니다.

---

## 3. 히스토그램 (Histogram): 인덱스 없는 컬럼의 예측 정밀도

인덱스가 생성되지 않은 컬럼은 기본적인 통계 정보가 부족합니다. 이를 보완하기 위해 도입된 기능이 **히스토그램(Histogram)**입니다.

- **데이터 분포 분석**: 특정 컬럼의 값이 어떤 범위에 얼마나 조밀하게 몰려 있는지(Bucket) 정보를 미리 수집하여 저장합니다.
- **최적화 기여**: 인덱스가 없는 컬럼이 `WHERE` 조건에 사용될 때, 옵티마이저는 히스토그램을 참조하여 결과 집합의 크기를 더욱 정밀하게 예측할 수 있습니다. 이는 특히 다중 조인 시 드라이빙 테이블을 결정하는 데 결정적인 역할을 합니다.

---

## 4. PostgreSQL의 통계 수집 시스템

PostgreSQL은 통계 정보의 정밀도 관리에 매우 고도화된 메커니즘을 제공합니다.

- **AUTOVACUUM ANALYZE**: 백그라운드 프로세스가 정기적으로 데이터 변경량을 감지하여 통계를 자동 갱신합니다.
- **pg_stats**: 실제 테이블의 샘플링 데이터를 기반으로 컬럼별 데이터 분포, Null 비율, 평균 빈도수 등을 제공하는 정교한 시스템 뷰를 통해 실행 계획의 근거를 추적할 수 있습니다.

---

## 5. 결론

통계 정보는 옵티마이저가 최적의 실행 경로를 선택하도록 돕는 물리적 지표입니다.

1. 실행 계획(`EXPLAIN`) 결과가 실제 데이터 분포와 상이하다면 통계 정보의 신선도를 가장 먼저 의심하십시오.
2. 대규모 DML 작업 이후에는 반드시 통계 정보를 수동으로 갱신하여 옵티마이저의 판단력을 유지하십시오.
3. 인덱스를 추가하기 어려운 컬럼은 히스토그램을 활용하여 옵티마이저의 예측 성능을 보강하십시오.

지금까지 인덱스와 실행 계획이라는 최적화의 물리적 토대를 분석했습니다. 다음 테마는 실제 여러 테이블이 결합될 때 발생하는 엔진 내부의 메커니즘, **물리적 조인 알고리즘(Join Internals)**입니다.
