## 샤딩: 단일 서버의 물리적 임계점 돌파

단일 서버 노드에 수십억 건의 데이터가 적재되고 초당 수만 건 이상의 트래픽이 집중될 경우, CPU, 메모리, I/O 대역폭 등 물리적 리소스는 한계에 도달합니다. 인덱스 튜닝이나 파티셔닝만으로 해결 불가능한 성능 저하를 방지하기 위해 데이터를 여러 대의 독립된 데이터베이스 서버에 물리적으로 분산 저장하는 기술이 **샤딩(Sharding)**입니다. 

본 아티클에서는 샤딩 아키텍처 설계의 핵심인 샤드 키(Shard Key) 선정 기준과 분산 환경에서의 기술적 제약 사항을 분석합니다.

---

## 1. 샤드 키(Shard Key) 선정의 물리적 규칙

샤딩의 효율은 데이터를 각 노드에 분배하는 기준인 **샤드 키** 설계에 의해 결정됩니다.

- **카디널리티(Cardinality)**: 샤드 키는 충분히 많은 고유값(Unique Values)을 보유해야 합니다. 예를 들어 `gender`처럼 값의 종류가 적은 컬럼을 샤드 키로 선정하면 데이터를 다수의 서버 노드로 분산시키는 것이 물리적으로 불가능합니다.
- **균등 분포(Uniform Distribution)**: 데이터가 특정 샤드 노드에 편중되지 않고 모든 서버에 골고루 분산되어야 합니다. 특정 키 값에 트래픽과 데이터가 집중되어 해당 노드만 부하가 치솟는 현상을 **핫스팟(Hotspot)**이라 하며, 이를 방지하기 위한 키 선정이 필수적입니다.

---

## 2. 데이터 분산 방식의 기술적 선택

1.  **Hash Sharding (해시 샤딩)**: 샤드 키 값을 해시 함수에 통과시켜 서버 노드 개수로 나누는 방식입니다. 데이터 분산이 균등하다는 장점이 있으나, 서버 증설 시 기존 데이터를 재배치하는 리샤딩(Resharding) 비용이 매우 높습니다.
2.  **Range Sharding (범위 샤딩)**: 값의 범위(예: ID 1~100만 번은 1번 서버)를 기준으로 나눕니다. 서버 확장이 용이하지만 특정 범위에 데이터가 몰리는 부하 불균형이 발생할 수 있습니다.
3.  **Directory Sharding (디렉토리 샤딩)**: 별도의 조회용 테이블(Look-up Table)을 두어 각 데이터가 위치한 샤드 정보를 관리합니다. 유연한 이동이 가능하지만 매핑 정보 조회 자체가 추가적인 네트워크 오버헤드가 될 수 있습니다.

---

## 3. 샤딩 도입에 따른 아키텍처적 제약

샤딩은 성능 확장을 제공하는 대신 다음과 같은 물리적 제약 조건을 수반합니다.

- **교차 샤드 조인(Cross-shard Join)의 제약**: 서로 다른 서버 노드에 저장된 테이블 간의 조인(Join) 연산은 네트워크 레이턴시로 인해 극도로 비효율적이거나 수행이 불가능합니다. 어플리케이션 계층에서 데이터를 병합하거나 공통 메타데이터를 모든 샤드 노드에 복제(Replication)하는 설계가 필요합니다.
- **분산 트랜잭션의 원자성 확보**: 두 대 이상의 서버 노드에 걸친 데이터를 원자적으로 수정하기 위해서는 2PC(Two-Phase Commit) 등 복잡한 합의 프로토콜이 필요하며, 이는 전체 시스템의 가용성과 응답 속도를 저하시키는 요인이 됩니다.

---

## 4. 실전 가이드: 도입 시점과 모니터링

- **최후의 수단으로서의 샤딩**: 샤딩 도입 전 수직적 확장(Scale-up), 인덱스 최적화, 파티셔닝, 캐싱, 읽기 복제본(Read Replica) 운영을 통해 성능을 최대한 확보해야 합니다. 샤딩은 운영 복잡도가 가장 높은 기술입니다.
- **부하 불균형 추적**: 샤딩 이후 각 노드별 CPU 사용량, 디스크 점유율, 네트워크 유량을 상시 계측하여 부하 편중 여부를 감지하고 리샤딩(Resharding) 계획을 선제적으로 수립하십시오.

---

## 5. 결론

샤딩은 **"단일 시스템이 감당할 수 없는 방대한 트래픽과 데이터를 다중 노드로 분산하여 처리하는 기술"**입니다.

1. 샤드 키 설계는 전체 분산 시스템의 확장성과 정합성을 결정하는 가장 중요한 요소입니다.
2. 균등 분산을 통해 특정 노드에 부하가 집중되는 핫스팟 현상을 철저히 방지하십시오.
3. 샤딩 도입 시 발생하는 조인 및 트랜잭션의 제약 사항을 어플리케이션 아키텍처 내에서 수용할 준비를 하십시오.

거시적 물리 분산 설계를 이해했다면, 이제 가장 하위 레벨에서 디스크 I/O를 결정짓는 **데이터 타입 선정과 페이지 분할 최적화** 기술을 분석하며 본 테마를 마무리합니다.
