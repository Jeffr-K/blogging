## 메모리 캐시: 데이터베이스 I/O 성능의 물리적 임계점

데이터베이스의 실제 처리 성능은 디스크 접근을 최소화하고 얼마나 많은 데이터를 메모리 내에서 처리하느냐에 달려 있습니다. 디스크 I/O는 메모리 접근에 비해 물리적으로 수만 배 이상 느리기 때문입니다. 이러한 메모리 캐싱을 전담하는 핵심 컴포넌트가 MySQL의 **Buffer Pool**과 PostgreSQL의 **Shared Buffers**입니다.

두 엔진은 메모리를 관리하는 기술적 접근 방식에서 뚜렷한 차이를 보입니다. 본 아티클에서는 각 엔진의 메모리 매니지먼트 전략과 물리적 튜닝 포인트를 분석합니다.

---

## 1. MySQL InnoDB: Buffer Pool (독점적 메모리 관리)

MySQL의 InnoDB 스토리지 엔진은 운영체제(OS)의 가상 파일 시스템 캐시에 의존하지 않고, 직접 할당받은 거대한 메모리 영역인 **Buffer Pool**을 주도적으로 관리합니다.

- **페이지 캐시 전략**: 최근에 읽힌 인덱스 및 데이터 페이지를 **LRU(Least Recently Used)** 알고리즘 기반으로 메모리에 유지하여 재사용성을 극대화합니다.
- **더티 페이지(Dirty Page)와 배치 쓰기**: 데이터 수정 시 디스크에 즉시 반영하지 않고 Buffer Pool 내의 데이터를 먼저 갱신(Dirty 상태)합니다. 이후 체크포인트 시점에 변경된 페이지들을 모아서 한꺼번에 디스크에 기록(Flushing)함으로써 쓰기 I/O 부하를 획기적으로 경감시킵니다.
- **권장 설정**: 일반적으로 데이터베이스 전용 서버 환경에서는 시스템 전체 RAM의 약 **70~80%**를 `innodb_buffer_pool_size`에 할당합니다.

---

## 2. PostgreSQL: Shared Buffers (OS 캐시와의 협업 구조)

PostgreSQL은 운영체제의 파일 시스템 캐시(Page Cache)를 적극적으로 활용하는 계층적 캐싱 구조를 취합니다.

- **이중 캐싱(Double Caching) 메커니즘**: 데이터는 엔진 레벨의 **Shared Buffers**에도 존재할 수 있으며, 그 하위 계층인 **OS Page Cache**에도 중복되어 상주할 수 있습니다.
- **아키텍처 특성**: Shared Buffers를 상대적으로 작게 설정하되, OS가 남은 메모리를 캐시로 활용하도록 유도합니다. Shared Buffers에서 데이터를 찾지 못할 경우 즉시 디스크로 접근하는 대신 OS 캐시를 먼저 탐색하여 물리적 I/O 발생을 억제합니다.
- **권장 설정**: 시스템 전체 RAM의 약 **25~40%**를 `shared_buffers`에 할당하고 나머지는 OS 캐시 가용량으로 남겨두는 것이 최적의 성능을 냅니다.

---

## 3. 캐시 히트율(Hit Ratio) 분석과 성능 지표

모든 데이터베이스 엔진은 사용 빈도가 낮은 페이지를 폐기하고 새로운 데이터를 적재하기 위해 LRU 알고리즘을 수행합니다.

- **Hit Ratio의 물리적 의미**: 요청된 데이터 페이지가 디스크 상상 읽기(Physical Read) 없이 메모리 캐시 내에 존재할 확률을 나타냅니다.
- **성능 측정 및 진단**: `SHOW ENGINE INNODB STATUS`(MySQL) 또는 `pg_statio_user_tables`(PostgreSQL)를 통해 히트율을 상시 모니터링해야 합니다. 히트율이 95% 미만으로 저하된다면 물리적 메모리가 부족하거나, 인덱스를 활용하지 못하는 대규모 풀 테이블 스캔(Full Table Scan) 쿼리가 빈번하게 발생하고 있다는 기술적 증거입니다.

---

## 4. 결론

메모리 튜닝은 **물리적 I/O 발생 빈도를 최소화하여 레이턴시를 억제하는 핵심 기술**입니다.

1. MySQL은 독점적인 `Buffer Pool` 관리를 통해 일관된 성능을 추구하며, 대규모 메모리 할당이 필수적입니다.
2. PostgreSQL은 OS 캐시와 리소스를 공유하며 유연하게 대응하지만, 이중 캐싱에 따른 메모리 낭비 요소를 고려해야 합니다.
3. 튜닝의 핵심은 히트율을 임계치 이상으로 유지하여 대부분의 쿼리 결과가 나노초 단위의 메모리 연산 내에서 종결되도록 유도하는 것입니다.

하드웨어와 소프트웨어의 접점인 메모리 최적화 설계를 이해했다면, 이제 데이터 규모가 물리적 단일 테이블의 한계를 초월할 때 적용하는 **테이블 파티셔닝(Partitioning)** 기술을 분석할 수 있습니다.
