# Section 01. 모델링의 3단계: 설계의 여정 (Three Levels of Modeling)

데이터베이스 설계는 추상적인 비즈니스 요구사항을 구체적인 데이터 저장소로 변환하는 점진적인 과정입니다. 이 섹션에서는 개념적, 논리적, 물리적 모델링의 각 단계에서 수행해야 할 핵심 작업과 그 결정이 시스템에 미치는 영향을 파헤칩니다.

## ✨ 왜(Why) 이 단계를 나누어 생각해야 하나요?

- **비즈니스와 기술의 분리**: 물리적인 제약(Storage engine, Memory 등)에 얽매이지 않고 비즈니스 논리(엔티티 관계)를 먼저 확정하기 위함입니다.
- **의사소통의 도구**: 기획자, 개발자, DBA가 각 단계에서 서로 다른 수준의 도표(Conceptual vs Physical)를 보고 명확하게 소통하기 위함입니다.
- **성능과 무결성의 조화**: 논리적 무결성을 먼저 확보한 뒤, 물리적 단계에서 성능 최적화(Index, Partitioning)를 적용하는 질서 있는 설계를 위해서입니다.

## 🔍 무엇을(What) 핵심적으로 보나요?

- **개념적 모델링**: 엔티티(Entity) 식별과 핵심 관계(Core Relationship)의 ERD화.
- **논리적 모델링**: 정규화(Normalization)의 수행과 속성(Attribute)의 상세 정의, 매핑 테이블 설계.
- **물리적 모델링**: 데이터 타입 선정, 인덱스 전략, 스토리지 엔진(InnoDB 등) 최적화 및 샤딩 계획.

## 🛠 어떻게(How) 탐구하나요?

- 각 단계별 ERD 변천사 비교 분석.
- 논리 모델에서 물리 모델로 넘어갈 때 발생하는 성능상 이슈(Join overhead vs Index scan) 추론.
- 실제 서비스(e.g. 주문/결제 시스템)의 요구사항을 바탕으로 3단계 모델링 실습.
