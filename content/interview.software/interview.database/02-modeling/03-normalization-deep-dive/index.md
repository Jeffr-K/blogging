# Section 03. 정규화의 심연 (Normalization Deep Dive)

정규화는 데이터베이스 설계에서 "무엇을 어디에 담을 것인가"를 규정하는 우아한 수학적 규칙입니다. 하지만 과도한 정규화는 시스템의 응답 속도를 늦추고 조인의 지옥(Join Hell)으로 우리를 안내합니다. 이 섹션에서는 정규화라는 면도날로 데이터를 정교하게 깎아내고, 다시 비즈니스의 속도를 위해 살을 붙이는(Denormalization) 설계의 변증법을 다룹니다.

## ✨ 왜(Why) 정규화를 깊이 알아야 하나요?

- **이상 현상(Anomaly) 방지**: 데이터를 넣고 빼고 고칠 때 엉뚱한 값들이 바뀌거나 사라지는 논리적 오류를 막기 위함입니다.
- **데이터 일관성 유지**: 같은 정보가 여러 곳에 흩어져 있으면, 하나를 고칠 때 나머지를 깜빡하는 순간 데이터는 오염됩니다.
- **최적의 반정규화 판단**: 정규화된 원칙을 알아야만 "어디를 무너뜨려야 가장 큰 성능 이득을 볼지" 결정할 수 있습니다.

## 🔍 무엇을(What) 핵심적으로 보나요?

- **Normalization (1NF ~ BCNF)**: 도메인의 종속성(Dependency)을 분석하고 테이블을 분해하는 정석적 절차.
- **Anomalies**: 삽입, 삭제, 수정 시 발생하는 비상식적인 현상들의 사례.
- **Advanced Normalization (4NF, 5NF)**: 다치 종속(Multi-valued)과 조인 종속이라는 난해한 주제의 실무적 해석.
- **Denormalization Strategy**: 조회 성능을 극대화하기 위해 일부 정규화를 포기하는 기술적 결단.

## 🛠 어떻게(How) 탐구하나요?

- 한 엔티티에 모든 정보가 담긴 거대한 '비정규형' 테이블에서 출발하여 정규형별로 쪼개나가는 과정 도해.
- 정규화된 테이블을 조인했을 때와 반정규화된 테이블을 단일 조회했을 때의 쿼리 응답 시간 벤치마킹.
- 실제 커머스 주문 테이블의 통계성 데이터(예: 총 주문 금액)를 중복 저장하는 반정규화 패턴 분석.
