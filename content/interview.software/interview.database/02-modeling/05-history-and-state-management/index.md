# Section 05. 이력 및 상태 데이터 관리 (History & State Management)

데이터베이스는 현재의 상태만을 담는 그릇이 아닙니다. 과거에 어떤 경로를 거쳐 현재에 이르렀는지, 즉 **데이터의 시간성(Temporality)**을 관리하는 것이 엔터프라이즈급 모델링의 핵심입니다. 이 섹션에서는 이력 데이터와 상태 전이(State Transition)의 무결성을 동시에 잡는 모델링 기법을 다룹니다.

## ✨ 왜(Why) 이력과 상태 관리가 중요한가요?

- **사후 분석 및 감사(Audit)**: "지난주 화요일에 상품 가격이 얼마였지?" 혹은 "이 유저는 언제 배송지를 바꿨지?"라는 질문에 답하기 위함입니다.
- **상태의 일관성**: 결제 대기 상태에서 배송 완료로 바로 넘어갈 수 없듯이, 비즈니스 규칙에 맞는 정교한 상태 전이를 보장하기 위함입니다.
- **성능과 보존의 균형**: 매번 조인하여 과거를 찾는 대신, 스냅샷(Snapshot)을 통해 현재 조회를 가속화하고 이력은 별도로 보관하기 위함입니다.

## 🔍 무엇을(What) 핵심적으로 보나요?

- **Snapshot vs History**: 현재 정보를 담은 마스터 테이블과 변동 내역을 담은 이력 테이블의 분리 전략.
- **Valid Period (SCD Type 2)**: 유효 시작일과 종료일을 이용해 특정 시점의 데이터 상태를 즉시 복원하는 기술.
- **State Machine**: 상태 코드와 전이 규칙(Transition)을 테이블로 정의하여 코드의 복잡성을 줄이는 방식.
- **Audit Log**: 누가, 언제, 무엇을, 어떻게 바꿨는지 기록하는 범용 감사 로그 설계.

## 🛠 어떻게(How) 탐구하나요?

- 상품 가격 변동 이력(Price History)을 기간 기반으로 설계하고, 특정 날짜의 가격을 찾는 쿼리 최적화.
- 주문 시스템의 상태 머신(`ORDER_PLACED` -> `PAYMENT_COMPLETED` -> ...)을 상태 전이 테이블로 구현.
- 이력 테이블의 데이터 폭증을 방어하기 위한 파티셔닝(Partitioning)과의 연계 전략 수립.
