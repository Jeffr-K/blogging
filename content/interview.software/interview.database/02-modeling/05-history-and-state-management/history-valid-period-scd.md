## 데이터에 시간을 입히다: 유효 시작일과 종료일

"2024년 5월 15일, 이 상품의 가격은 얼마였는가?" "지난달 10일, 이 유저의 배송지는 어디였는가?"

이런 질문에 답하기 위해 매번 복잡한 로그 테이블을 뒤지는 것(Full Scan)은 비효율적이다. 이때 사용하는 정석적인 기법이 **유효 시작일(Start Date)**과 **유효 종료일(End Date)**을 이용한 **기간 기반 이력 관리**다. DW(Data Warehouse) 설계의 핵심인 SCD(Slowly Changing Dimension) Type 2가 바로 이 방식이다. 이번 아티클에서는 특정 시점의 데이터 상태를 즉각 복원하는 이 고도의 모델링 기술을 딥다이브해 본다.

---

## 1. 딥다이브: 시작일과 종료일의 설계 (Closed/Open Interval)

각 이력 행에 해당 정보가 유효했던 기간을 칼럼으로 추가한다.

- **구조**: `effective_start_dt`, `effective_end_dt`.
- **현재 데이터**: 현재 진행 중인 최신 데이터의 `effective_end_dt`는 보통 `9999-12-31` 또는 `NULL`로 설정하여 영원히 유효함을 표시한다.
- **조회의 마법 (Time-point Query)**: `WHERE '2024-05-15' BETWEEN effective_start_dt AND effective_end_dt` 이 단순한 쿼리 하나로 특정 시점의 상품 가격을 인덱스 스캔만으로 즉시 찾아낸다.

---

## 2. 갱신 시나리오: 데이터가 변할 때

현재 데이터를 수정하는 것은 단순히 칼럼을 바꾸는 것이 아니라, **'과거의 마감'**과 **'새로운 시작'**을 의미한다.

1. **기존 데이터 마감**: 현재 최신인 데이터의 `effective_end_dt`를 `현재시간`으로 업데이트한다.
2. **새 데이터 삽입**: 새 정보를 `effective_start_dt = 현재시간`, `effective_end_dt = 9999-12-31`로 삽입한다.
3. **원자성**: 이 두 작업은 반드시 하나의 트랜잭션 내에서 원자적으로 일어나야 한다. (그사이에 빈틈이 생기면 누구도 유효하지 않은 '데이터 소외 시간'이 발생한다.)

---

## 3. 이 방식의 압도적 장점 (VS 순수 로그 방식)

- **검색 효율**: 이전 값을 찾기 위해 `MAX()`나 `TOP 1` 서브쿼리를 쓸 필요가 없다. 단순한 `BETWEEN` 연산만으로 수천만 건의 이력 중에서 단 한 건을 골라낸다.
- **분해 성능**: 데이터의 기간이 겹치지 않으므로 정합성 검증이 매우 쉽다.

---

## 4. 실전 가이드: 인덱스 전략

- **복합 인덱스**: `(entity_id, effective_start_dt, effective_end_dt)` 순서로 인덱스를 구성하여, 특정 엔티티의 특정 시점 조회를 최적화하라.

---

## 요약

기간 기반 이력 관리는 **"데이터에 시공간적 좌표를 부여하는 설계"**다.

- 시작일과 종료일을 통해 특정 시점의 재현성(Reproducibility)을 확보하자.
- 최신 데이터에 마감일(`9999-12-31`)을 두어 현재 데이터 조회를 가속화하자.
- 복잡한 이력 관리 알고리즘을 단순한 SQL 범위 검색으로 치환하여 성능을 잡자.

과거의 시간을 여행하는 기술을 마쳤다면, 이제 데이터가 변화하는 '규칙'인 **상태 머신(State Machine) 모델링**을 딥다이브할 준비가 된 것이다!
