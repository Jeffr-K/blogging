# SQL AntiPatterns - Bill Karwin (요약 레퍼런스)

SQL 안티패턴 중 관계 설계 및 물리 모델링과 관련된 핵심 내용들을 요약한 참고 문서입니다.

## 1. 관계 설계 및 물리 구조 안티패턴

### 무단횡단 (Jaywalking)

- **현상**: 한 컬럼에 쉼표로 구분된 다중 값 속성을 사용 (1:N을 텍스트로 처리).
- **문제**: 인덱스 불가, 집계 함수 불가, 유효성 검증 마비.
- **해법**: 중간(교차) 테이블을 사용하여 정규화.

### 순진한 트리 (Naive Trees)

- **현상**: 단순히 `parent_id`만 사용하는 재귀적 관계.
- **해법**:
  - 경로 열거 (Path Enumeration)
  - 중첩 집합 (Nested Sets)
  - **클로저 테이블 (Closure Table)**: 조상-자손 관계를 별도 테이블로 관리 (추천).

### 아이디가 필요해 (ID Required)

- **현상**: 모든 PK를 무의미한 가상키(`id`)로 고집.
- **해법**: 자연키나 복합키(특히 교차 테이블에서)의 효용성을 인정하고 상황에 맞게 설계.

### 키가 없는 엔트리 (Keyless Entry)

- **현상**: 물리적 외래키(FK)를 생략하는 행위.
- **문제**: 참조 정합성 파괴. 어플리케이션 단에서만 검증하는 위험성.
- **해법**: 성능 트레이드오프를 고려하되 가급적 DB 레벨의 FK 사수.

### 다형성 연관 (Polymorphic Associations)

- **현상**: 하나의 테이블이 여러 테이블과 다대일 관계일 때 `parent_type` 컬럼 사용.
- **문제**: 물리적 FK 사용 불가.
- **해법**: 역참조(각 테이블별 교차 테이블) 또는 공통 슈퍼테이블 구축.

## 2. 데이터 타입 및 쿼리 안티패턴

### 엔터티-속성-값 (EAV)

- **현상**: 가변 속성을 행 단위(이름-값 쌍)로 저장.
- **해법**: 상속 모델링(STI, CTI) 또는 반구조적 데이터(JSON/BLOB) 활용.

### 메타데이터 트리블 (Metadata Tribbles)

- **현상**: 테이블명에 연도/월을 붙여 파티셔닝을 흉내 냄 (예: orders_2023).
- **해법**: 정식 파티셔닝(Partitioning) 기능 활용.

### 반올림 오류 (Rounding Errors)

- **현상**: 수치 정밀도가 중요한 곳에 `FLOAT` 사용.
- **해법**: `NUMERIC`, `DECIMAL` 타입 사용.

### 31가지 맛 (31 Flavors)

- **현상**: `ENUM`, `CHECK` 제약으로 값을 지나치게 제한.
- **해법**: 색인(Lookup) 테이블 구축.

### 인덱스 샷건 (Index Shotgun)

- **현상**: 인덱스를 너무 많이 혹은 잘못 생성.
- **해법**: **MENTOR** (Measure, Explain, Nominate, Test, Optimize, Rebuild) 전략 활용. 커버링 인덱스 적극 활용.

## 3. 기타 안티패턴 및 권장사항

- **임의 선택**: `ORDER BY RAND()`의 성능 문제 → PK 오프셋이나 COUNT 기반 랜덤 추출 활용.
- **가난한 자의 검색 엔진**: `LIKE %..%` 검색 성능 문제 → Full-text Index 활용.
- **암묵적 컬럼**: `SELECT *` 지양, 명시적 컬럼 선언.
- **마법의 콩**: 액티브 레코드 패턴의 모델-스키마 과결합 경계.
