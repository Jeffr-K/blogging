## 데이터 분산의 난제: 서버 증설과 재배치 비용

분산 시스템에서 데이터를 여러 노드에 나누어 저장할 때, 가장 단순한 방식은 `hash(key) % node_count`입니다. 하지만 이 방식은 서버 한 대를 추가하거나 제거할 때마다 모든 데이터의 위치가 바뀌어 대규모 데이터 이동(Resharding)이 발생하는 물리적 재앙을 초래합니다.

이를 해결하기 위해 고안된 **일관된 해싱(Consistent Hashing)**은 서버 노드의 증설과 삭제 상황에서도 데이터 재배치를 최소화하는 고도의 확장성 기술입니다.

---

## 1. Consistent Hashing의 물리적 구조: 해시 링(Hash Ring)

일관된 해싱은 0부터 $2^{32}-1$까지의 큰 숫자 범위를 하나의 **링(Ring)**으로 형상화합니다.

1.  **서버 노드 배치**: 각 서버 노드를 해시 함수에 통과시켜 링 위의 특정 지점에 배치합니다.
2.  **데이터 키 배치**: 저장할 데이터의 키(Key) 역시 동일한 해시 함수를 통해 링 위의 특정 지점에 배치합니다.
3.  **데이터 매핑**: 데이터 키가 배치된 지점에서 **시계 방향(Clockwise)**으로 가장 먼저 만나는 서버 노드가 해당 데이터를 저장할 주인(Owner)이 됩니다.

---

## 2. 서버 증설과 삭제 시의 물리적 이동 범위

일관된 해싱의 진가는 노드 구성이 변할 때 발휘됩니다.

- **노드 추가**: 새로운 노드가 링에 추가되면, 오직 인접한 시계 방향의 노드에 저장되어 있던 일부 데이터만 새로운 노드로 이동합니다. (전체 데이터의 $1/N$만 이동함)
- **노드 장애**: 특정 노드가 제거되면 해당 노드의 데이터만 시계 방향의 다음 노드로 이동하며 시스템이 유지됩니다.
- **비교**: 단순 Modulo 방식(`% N`)이 전체 데이터의 대부분을 재배치해야 하는 것과 대조되는 압도적인 효율성입니다.

---

## 3. 고질적 문제: 데이터 불균형과 가상 노드(vNode)

단순히 서버 대수만큼 링 위에 배치하면 서버 간의 간격이 일정하지 않아 특정 서버에 부하가 쏠리는 **핫스팟(Hotspot)** 현상이 발생할 수 있습니다.

- **가상 노드(vNode) 기법**: 하나의 물리 서버를 링 위의 수백 개 지점에 논리적으로 복제하여 배치합니다. (예: `Server1-v1`, `Server1-v2`...)
- **효과**: 서버 노드들이 링 전체에 조밀하고 균등하게 분포하게 되어 데이터가 물리적 노드들에 골고루 분산됩니다. 특정 서버가 고성능 장비라면 더 많은 가상 노드를 할당하여 가중치를 부여할 수도 있습니다.

---

## 4. 실전 가이드: 어디에 쓰이는가?

일관된 해싱은 고가용성과 수평적 확장이 필수적인 대규모 분산 인프라의 핵심입니다.

1.  **분산 캐시(Redis, Memcached)**: 캐시 서버 증설 시 기존 캐시가 대량 무효화(Cache Invalidation)되는 현상을 방지합니다.
2.  **분산 DB(Cassandra, Amazon DynamoDB)**: 수천 대의 노드에 걸쳐 데이터를 파티셔닝하고 가용성을 유지하는 기본 매커니즘입니다.
3.  **로드 밸런서**: 동일한 클라이언트 세션이 항상 동일한 업스트림 서버로 전달되도록 하는 세션 고정(Session Affinity) 기능을 정교하게 구현할 때 사용합니다.

---

## 5. 결론: 데이터 배치는 시스템의 회복 탄력성이다

Consistent Hashing은 **"물리적 환경의 변화에 가장 유연하게 대응하는 데이터 배치 기술"**입니다.

1. 서버 노드 추가/삭제 시 서비스 중단을 최소화하고 데이터 이동을 국소화하십시오.
2. 가상 노드(vNode) 설계를 통해 물리적 서버 부하의 균형을 사수하십시오.
3. 데이터의 위치(Location) 결정 논리를 단순화하여 분산 시스템의 응답 속도를 높이십시오.

분산 시스템의 거시적인 데이터 배치 전략을 이해했다면, 이제 단일 노드 내부에서 쓰기 성능의 물리적 한계를 극복하는 **HA 성능 고도화 기술**을 분석하며 모든 여정을 마무리합니다.
